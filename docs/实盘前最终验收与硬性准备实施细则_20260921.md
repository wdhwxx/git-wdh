## 二、验收测试 T1-T8 实施细则

> 分级说明：**A 类**=代码/SIM 层现在即可验收（无需券商环境）；**B 类**=必须真实 QMT 环境；
> C 类=必须真实资金/连续运行。通过判据为“必须全部通过”。

### T1 信号→风控→QMT 下单→委托编号双向映射（B 类，前置=P3+环境）

- **验收目标**：信号生成 → 风控通过 → QMT 模拟盘下单成功，QMT 返回真实委托编号，委托编号与本地 order_id 双向映射正确。
- **实施步骤**：
  1. `live_config.yaml` 设置 `broker.mode: LIVE`（或先用 SIM 模式跑通本地段）；
  2. 运行 `run_实盘入口.py --dry-run` 验证装配；
  3. 注入一个买入信号，确认 `_process_signal` 全链路（去重→风控→防未来→RiskManager 复查→提交）；
  4. QMT 端核对：委托簿出现该订单，委托编号非空；
  5. 校验 `_local_to_qmt[order_id] == qmt_order_id` 且 `_qmt_to_local[qmt_order_id] == order_id`；
  6. 用 QMT 委托编号反查本地订单状态一致。
- **通过判据**：QMT 返回真实委托编号；双向映射查无缺失；本地状态与 QMT 委托状态一致。
- **现状**：SIM 模式委托流程已过 23 项测试；真实委托编号需真实环境。

### T2 重复 signal_id 二次拦截（A 类，✅ 已就绪，复验即可）

- **验收目标**：同一 signal_id 第二次发送被引擎拦截，不生成新订单，`dedup_skipped` 计数 +1。
- **实施步骤**：`pytest tests/unit/test_signal_idempotency.py -q`（19 项，含同 bar 重发/重建实例重发/异 bar 不误杀/分钟线粒度）。
- **通过判据**：19 项全过；`engine._stats["dedup_skipped"] == 1`，`total_orders` 不重复递增。

### T3 QMT 断线 → 重连补单，仅补发未成交（B 类，前置=P3 代码待办）

- **验收目标**：QMT 端模拟断线 → 本地重连后补单**仅补发未成交订单，已成交订单不重发**，无重复报单。
- **前置（代码待办 P3）**：当前仅有 `auto_reconnect`（连接恢复），**无“重连后对账补单”机制**——需实现：
  1. 重连成功后调用 `broker.get_active_orders()`（QMT 在途单查询，已具备）；
  2. 与本地 `_orders` 订单簿比对：本地 SUBMITTED 且券商端仍为在途/未报 → 视为丢失需补发；
  3. 补发走 `submit_order`（按 order_id 幂等，第三项已保证不重复报单）；
  4. 本地已成交（FILLED）订单绝不补发；
  5. 对账结果写日志 + 统计（`resend_count`）。
- **实施步骤**：断线注入（QMT 端断网或杀进程）→ 观察重连 → 检查补单日志 → 核对券商端无重复委托。
- **通过判据**：仅未成交订单补发一次；已成交订单零重发；券商端委托去重无重复报单。
- **现状**：`get_active_orders` 已具备；补单编排逻辑缺失（P3）。

### T4 资金不足业务拒单，不触发 failover（A 类，✅ 已就绪，复验即可）

- **验收目标**：模拟资金不足触发业务拒单，BrokerManager 拒绝重试，直接返回错误。
- **实施步骤**：`pytest tests/unit/test_broker_manager_failover.py -q`（27 项，含“资金不足/可卖数量/持仓不足/T+1/风控/涨跌停/校验”业务拒单参数化 9 例不 failover）。
- **通过判据**：27 项全过；`failover_stats["business_skipped"] == 1`，备券商零调用，主券商不切换。

### T5 通道故障 failover → 原 order_id → 冷却后切回（A 类，✅ 已就绪，复验即可）

- **验收目标**：模拟 QMT 通道故障（非业务拒单）自动切换备用通道，使用原 order_id；主券商恢复后冷却时间后切回。
- **实施步骤**：`pytest tests/unit/test_broker_manager_failover.py -q`（通道故障参数化 6 例 + 冷却熔断/解除 + 健康恢复切回 + 手动切换清恢复记忆）。
- **通过判据**：27 项全过；副本保持原 `order_id`；`restore_primary_if_healthy` 冷却过后切回原主，`restore_count == 1`。

### T6 隔夜回报（跨日成交）不触发当日信号逻辑（A 类，✅ 已就绪，复验即可）

- **验收目标**：模拟隔夜回报被记录，但不触发当日信号逻辑，无未来函数告警。
- **实施步骤**：`pytest tests/unit/test_live_lookahead.py -q`（19 项，含同日跳过/早于信号日真违规/T+1 成交）。
- **通过判据**：19 项全过；跨日成交 `record_trade` 正常记录；`assert_pass` 无违规；不生成当日新信号。

### T7 QMT 端手动撤单 → 本地状态同步（B 类，前置=环境）

- **验收目标**：QMT 端手动撤单，本地 state_machine 同步为“已撤单”，资金/持仓正确释放。
- **实施步骤**：
  1. 引擎运行中提交一笔订单；
  2. 在 QMT 客户端手动撤单；
  3. 等待 QMT 撤单回报 → `_handle_order_callback` 映射（QMT 状态码 → 本地 `CANCELLED`）；
  4. 校验本地 `_orders[order_id].status == CANCELLED`，portfolio 资金/持仓恢复。
- **通过判据**：本地订单状态同步为已撤单；撤单后资金/持仓与撤单前一致（无重复占用）。
- **现状**：QMT 状态码映射表已实现（LIVE 分支 30+ 状态码）；真实撤单回报需真实环境验证。

### T8 全天运行（C 类，前置=阶段1 全部通过 + 资金到位）

- **验收目标**：全天运行信号、下单、回报、风控全链路，账户权益曲线平稳，无异常抖动，日志无 ERROR。
- **实施步骤**：
  1. 阶段1 全部通过后，`live_config.yaml` 配 `trade_mode: live` + 完整风控规则库；
  2. 连续运行 1 个完整交易日（可先 monitor-only 1 日 → paper 1 日 → live 1 日）；
  3. 收盘后检查：权益曲线（无阶梯式异常）、日志 grep `ERROR` 为零、`dedup_skipped`/`failover_stats` 统计合理；
  4. 状态快照（StateStore）与券商实际持仓核对一致。
- **通过判据**：24h 无 ERROR；权益曲线无异常抖动；快照与券商持仓一致；无未预期的 failover/撤单。
