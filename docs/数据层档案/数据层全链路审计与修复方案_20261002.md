## 2. 问题清单（分级）

### A 级 · BUG（必须修复）

**A1. CLI 下载直写 processed（数据下载.py）**
- 现象：processed 出现 **2,376 个 6 列英文 parquet**；其中 **2,025 只创业板仅 2 行（2026-09-29/09-30）**，北交所 920 段为各自全历史但 6 列无派生量；文件 mtime **2026-10-02 15:33**（当日批量覆盖/创建）。
- 证据：processed 全目录扫描 5,571 个（14 列 3,195 / 6 列 2,376 / 其他 0）；`300001.SZ` 实测 2 行、DataLoader 可读但派生量列缺失；`download_daily` 194-195 行 `fetcher.get_stock_list()` 全列表无规则过滤；136-149 行 `save_market_data_parquet` 原始直写。
- 根因：CLI 与 GUI 增量链路**行为分裂**——GUI 走清洗管线（#57/#69 已根治），CLI 未同步改造；且 CLI 无标的池过滤，池外（创业/科创/北交）标的也被下载并直写。
- 影响：池外标的 processed 处于非标准状态（创业板仅 2 天、北交所无派生量、列集与 14 列口径不一致）；**主板若用 CLI 增量，同样会被覆盖式直写污染**；口径不一致破坏"processed 只含清洗池"契约。
- ✅ **已修复（2026-10-02，蓝图 #86）**：`download_daily` 候选池经 `resolve_incremental_symbols`（14 条规则）过滤只下载主板清洗池；processed 写回改 `manager.save_cleaned_incremental_parquet`（与 GUI 同链路、复用 records）；存量 2,376 只已清理（见交接摘要）；验证：新增单测 3 项 + 全量 pytest 1755 passed / 2 skipped 零破坏。

**A2. 排除规则内置兜底漂移（10 vs 14 条）**
- 现象：`full_clean_service.DEFAULT_EXCLUDE_RULES`（L62）与 `financial_sync_service.FINANCIAL_EXCLUDE_RULES`（L71）均仅 **10 条**，缺 `68 / 90 / 20 / 99`；而 `config/data_clean_run.json` 与 `config/financial_exclude_rules.yaml` 均为 14 条。

- 根因：#83 config 化只更新 yaml/json，**代码内置兜底未同步**。
- 影响：当 config 文件缺失/损坏时，兜底会**把科创板 68 / B 股 90·20 / 老三板 99 段重新纳入**清洗与财务池——**B 股（刚永久剔除）可能被复活**；属口径漂移炸弹。
