## 待办 01｜P1-14：GUI「预筛选标的」按钮阻塞主线程最长 300 秒

- **位置**：`myquant/gui/backtest_config_dialog.py:1080`
- **现状**：`subprocess.run(cmd, ..., timeout=300)` 在主线程同步阻塞，`processEvents()` 仅调用前刷一次；窗口最长 300 秒假死。
- **影响**：用户误判崩溃；该按钮正是 P1-02「预筛选池恒空」的入口。
- **整改方向（推荐）**：改为 `QThread` + 信号回调；同文件 `:1260 / :1267 / :1512 / :1518 / :1786` 已有 `Popen` + reader 线程的成熟范式，直接参照。
- **验收**：点击按钮后窗口仍可拖动/取消；脚本结束通过信号回写结果标签。
- **前置条件**：需在桌面 GUI 环境实机验证。

## 待办 02｜P1-11：momentum / multi_factor 三引擎接口不等价

- **位置**：
  - `myquant/strategies/momentum_strategy.py:517-524,602`
  - `myquant/strategies/multi_factor_strategy.py:1197-1203,1293`
- **现状**：横截面 top_n 选股依赖全市场数据，mixed/vectorized 按标的逐 bar 调用无法复现，退化为单标的动量阈值；调仓日三引擎语义不一致（vectorized `i % rebalance_days` vs event `_should_rebalance`）。一致性仅在演示桩 `DemoThreeModeStrategy` 上验证过。
- **影响**：参数扫描（vectorized）结论 ≠ 生产（mixed/event）行为，"回测实盘同构"对 2/7 策略不成立。
- **整改方向（推荐）**：在参数扫描/引擎选择入口对 momentum、multi_factor **禁止选 vectorized 并明确标注**（低成本门禁）；中期再实现真横截面 target 数组。
- **验收**：选 vectorized 跑这两策略时给出显式拒绝/警告，不再静默退化。
- **范本**：`kunpeng_strategy`（三接口共用同一 `_evaluate_exit` 状态机）为达标参照。
