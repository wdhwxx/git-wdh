# P0-3 告警分级规范

**编号**：P0-3
**版本**：V1.0（定稿版）
**日期**：2026-10-05
**依据**：《量化系统监控模块施工总清单_V1.2.md》P0-3 项（对应报告 §5.2）
**事实来源**：本次落地。分级定义与响应时限取自施工清单 P0-3 原文；示例告警映射对齐 P0-1 链路盘点确认的缺口场景。
**定位**：监控施工前置规范第三项——告警分级表定稿，每级绑定响应时限与通道；A 包起所有告警按本表分级。

---

## 1. 告警分级表（定稿）

| 级别 | 定义（触发场景） | 响应时限 | 通知通道 | 处置要求 |
|------|------------------|----------|----------|----------|
| **P0** | 资金异常 / 风控击穿 / 交易中断 | **1 分钟** | 多渠道即时（日志+控制台+邮件+飞书/企微 Webhook，P0 至少 2 通道可达） | 立即处置，挂 Runbook，升级路径直达责任人 |
| **P1** | 核心策略异常 / 行情中断 / 大量拒单 | **5 分钟** | 多渠道即时 | 尽快处置，挂 Runbook |
| **P2** | 性能退化 / 数据延迟 | **15 分钟** | 常规通道 | 当日处置 |
| **P3** | 趋势 / 日报 | **次日** | 日报通道 | 次日处置，无需即时 |

> 响应时限 = 告警产生到开始处置的时限（MTTA 目标：P0 < 5 分钟，见 §9 KPI-2）。

## 3. 分级与升级机制衔接（A-10）

- 现有 `alerting.py` 的 `SeverityLevel` 扩展对齐本表 P0~P3 分级映射（施工项 A-10）。
- 未确认自动升级：WARNING 未确认超时自动升级为 ERROR（现有 check_escalations 已接入，施工项 A-10 完善 P0/P1 时限）。
- 每条 P0/P1 告警必须绑定 Runbook（P0-4 模板）与责任人。

---

## 4. 通道要求（对齐 A-9）

- P0 至少 2 通道可达；主通道故障 → 冗余通道或未投递落盘兜底（_write_undelivered + 元监控计数）。
- 告警内容按 P0-7 脱敏规则处理（敏感数据脱敏、防泄露）。
