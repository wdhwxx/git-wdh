# P0-5 指标命名与埋点规范

**编号**：P0-5
**版本**：V1.0（定稿版）
**日期**：2026-10-05
**依据**：《量化系统监控模块施工总清单_V1.2.md》P0-5 项
**事实来源**：本次落地。命名规范与标签治理原则取自施工清单 P0-5 原文。
**定位**：监控施工前置规范第五项——统一 `领域_对象_动作_单位` 命名，标签维度治理（高基数不进时序，走事件/日志）。A 包起所有新增指标按本规范命名。

---

## 1. 指标命名规范：`领域_对象_动作_单位`

```
<领域>_<对象>_<动作>_<单位>
```

| 段 | 说明 | 示例 |
|----|------|------|
| 领域 | 链路环节/系统域枚举（见 §2） | market / data / signal / risk / trade |
| 对象 | 指标作用对象 | quote / order / position / equity |
| 动作 | 测量动作 | delay / reject / usage / gap / heartbeat |
| 单位 | 计量单位（小写） | ms / s / pct / rate / count |

**示例**：
- `market_quote_delay_p99_ms`（行情报价延迟 P99，毫秒）——与 P0-2 `monitoring.slo.market.quote_delay_p99_ms` 字段同名对齐
- `data_freshness_gap_s`（数据新鲜度缺口秒）
- `trade_order_reject_rate_pct`（订单拒绝率百分比）
- `risk_position_limit_usage_pct`（限额使用率百分比）
- `reconcile_diff_amount_cny`（对账差异金额，元）
- `engine_heartbeat_miss_count`（心跳连续未响应次数）

> **规则**：指标名与 `monitoring.slo` 配置块字段一致（同一指标同一名字，禁止两处命名不一）；单位统一小写（ms/s/pct/rate/count/cny）。

## 3. 标签维度治理

- **低基数标签**（enum 类，基数 < 100）：可进时序（如 symbol 交易所/level 级别/status 状态）。
- **高基数标签**（如具体 symbol 数千只、订单 id 无限增长）：**禁止进时序**，走事件/日志（BASE-4 事件四元组 + 告警落库），按需聚合后再入时序（如按交易所/板块聚合）。
- **标签命名**：小写下划线；禁止含空格/中文/特殊字符。
- **唯一约束**：同一指标不得既带高基数标签又按明细统计（防基数爆炸）。

---

## 4. 埋点规范（对齐 BASE-4 事件链路）

- 事件字段：`signal_id / order_id / trade_id / event_ts` 四元组 + `event_id`（BASE-4 落地后强制）。
- 监控指标只消费**已发生**数据（防未来）；统计窗口、周期参数外置配置（P0-6 yaml），禁止代码硬编码。
- 采集位置：业务逻辑发布事件（引擎/broker/portfolio），`metrics_collector.py` 订阅落指标（A-3 架构）。
