## 1. ① 误报 / 准确率判定规则（ground-truth 定义）

### 1.1 判定规则

| 分类 | 判定条件（P0-8 ① 原文） |
|------|--------------------------|
| **真告警（TP）** | 告警产生后在 Runbook 中被确认（acked）为"需处置"，**或** resolved 时标记根因为真实系统/市场事件 |
| **误报（FP）** | 告警产生后被人工标记为"误报/噪声/已自愈无需动作"，**或**在无处置动作下自动 resolved 且元监控确认无对应真实事件 |
| **漏报（FN）** | 由 P0-8③ 故障注入用例集主动测量——注入的故障未被任何告警捕获即计为漏报 |
| **无法判定（UNCLASSIFIED）** | 无任何处置标记、非自动 resolved——显式标注，不强行归类（人工周复盘抽检校正 ≥20%） |

### 1.2 统计口径

```
准确率      = TP / (TP + FP)
误报率      = FP / (TP + FP)
检出率      = TP / (TP + FN)
```

- 数据源：告警表（BASE-1）的 `status` + 新增 `classification`（TP/FP/自动）字段。
- 统计方式：由 §7 周复盘任务**自动统计**（`scripts/监控可测量性统计.py`），人工仅在周复盘对自动分类结果抽检校正（抽检比例 ≥ 20%）。
- 目标（C-9）：告警准确率 > 95%、误报率 < 5%（按周统计至少 4 周判定）。

## 2. ② MTTx 计时起点 / 终点定义（一律系统时间戳，禁止人工估算）

| 指标 | 起点 | 终点 | 说明 |
|------|------|------|------|
| **MTTD**（检测） | 故障注入脚本写入的"故障发生时间戳"（**事件时间，非告警时间**） | 对应告警在 BASE-1 落库的 `created_at` | 检测耗时 |
| **MTTA**（确认） | 告警 `created_at` | 告警 `acked_at` | **以系统确认事件为准，不以"人看到"为起点** |
| **MTTR**（恢复） | 故障注入时间戳 | BASE-1"告警→恢复"成对记录中的 `resolved_at` | 健康恢复自动发 INFO 并置 resolved |

- 所有计时以系统时间戳计算，**禁止人工估算/人工计时**。
- 时间戳非法（负值、终点早于起点）一律判为计时无效并显式报错，不静默取数。

## 3. ③ 标准故障注入用例集 FI-01~07（与 D-6 共用同一用例库）

| 用例 ID | 注入故障 | 期望捕获项 | 触发模式 | 期望告警级别 | 对应 KPI | 计时起点 | 计时终点 |
|---------|----------|------------|----------|--------------|----------|----------|----------|
| FI-01 | 行情源断流（交易时段停喂 bar） | A-4 StalenessDetector | EVENT | P0 | MTTD<1min | 断流注入时间戳 | 告警 created_at |
| FI-02 | 引擎僵死（get_status 无响应） | A-5 引擎心跳 | POLL（窗口<60s） | P0 | MTTD<1min | 僵死注入时间戳 | 心跳告警 created_at |
| FI-03 | 券商连接断开 | A-6 _check_broker | EVENT | P0 | MTTD<1min | 断连注入时间戳 | 状态变更告警 created_at |
| FI-04 | 伪造拒单 | A-8 ORDER_REJECTED | EVENT | ERROR/P1 | MTTA<5min | 拒单注入时间戳 | 告警 created_at |
| FI-05 | 人为制造持仓差异 | A-7 reconcile 差异 | EVENT | CRITICAL | MTTR<30min | 差异注入时间戳 | 告警→恢复 resolved_at |
| FI-06 | 告警主通道故障 | A-9 冗余/落盘兜底 | 元监控 | 元监控 | KPI-8 | 通道故障注入时间戳 | 冗余通道/落盘兜底完成 |
| FI-07 | 主进程 kill | BASE-8 外部心跳超时 | 外部通道 | 外部通道 | KPI-8 | kill 注入时间戳 | 外部载体收到存活告警 |

> **用例库纪律**：
> - FI 用例集为 §9 KPI-2 计时与 KPI-3 检出率的**唯一权威来源**；每次演练逐用例跑、逐用例计时、结果入库。
> - D-6 混沌工程**直接复用**本用例库（不再另立用例）；先做最小可行版（FI-01 断流 / 备份恢复），逐步扩展。
> - FI-02 窗口硬约束：判定窗口 N×心跳间隔必须 <60s（A-5/R-02/R-04）。
> - FI-07 补充（R-08）：临界网络抖动下外部心跳不误判"主进程死"（连续多次超时判定，非单次）。
