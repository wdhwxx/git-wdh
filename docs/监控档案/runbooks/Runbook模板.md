## 2. 字段填写说明

| 字段 | 填写要求 |
|------|----------|
| 告警名称 | 与告警规则 `alert_rules.example.yaml` 的 rule 名称一致（P0-6 对齐） |
| 级别 | 按 P0-3 分级表：P0 资金异常/风控击穿/交易中断；P1 核心策略异常/行情中断/大量拒单；P2 性能退化/数据延迟；P3 趋势/日报 |
| 影响范围 | 影响的链路环节（对齐 P0-1 链路盘点：行情/数据/因子/信号/组合/风控/订单/成交/持仓/资金/PnL）+ 影响面描述 |
| 触发条件 | 告警规则触发条件原文（阈值从 P0-2 `monitoring.slo` 引用，禁止自定义） |
| 可能原因 | 至少列出 2 个最可能原因，按概率排序 |
| 排查步骤 | 具体可执行步骤（看板/日志/Trace 定位），编号 1/2/3... |
| 应急动作 | 止血动作（如暂停开仓/切行情源/撤单），标注是否属自动动作（D-1 三阶段：shadow/人工/自动） |
| 恢复步骤 | 恢复正常后的验证步骤 |
| 责任人 | 单人系统：本人 |
| 升级路径 | 未按时处置升级到哪（P0-3 时限：P0 1 分钟、P1 5 分钟） |
| 关联仪表盘 | P0-6 dashboard.example.yaml 的面板名称 |
| 关联 Trace / 日志 | 链路 id（BASE-4 四元组 signal_id/order_id/trade_id/event_ts）+ 日志文件路径 |
| 最近变更 | 关联最近代码/配置变更（版本贯穿原则 6） |
| **处置分类（TP/FP/自动）** | **处置后回填**：TP=需处置/根因真实；FP=误报/噪声/已自愈；自动=自动恢复未处置。**供 P0-8 周复盘自动统计的 classification 数据源** |

---

## 3. 与 P0-8 的衔接

- `classification`（TP/FP/自动）是 §9 KPI-3 准确率/误报率统计的**数据源字段**（BASE-1 alerts 表对应列，`scripts/监控可测量性统计.py` 读取判定）。
- 周复盘自动统计 + 人工抽检校正（≥20%）对自动分类结果复核。

## 4. 示例（A-4 行情断流告警）

```text
告警名称：行情源断流（交易时段停喂 bar）
级别：P0
影响范围：行情链路 → 数据/因子/信号（交易连续性）
触发条件：交易时段内超过 bar_timeout_seconds（P0-2 monitoring.slo）无新 bar
可能原因：
  1. 行情源（akshare/腾讯）连接断开
  2. 行情订阅失效（订阅状态被重置）
排查步骤：
  1. 看板：行情活性面板确认 staleness 时间
  2. 日志：data_feed 最近 N 条 bar 接收时间
  3. 探活：数据源连通性检查（health_check）
应急动作：切换备用行情源 / 暂停相关策略（自动动作需 D-1 三阶段确认）
恢复步骤：恢复行情源后确认 staleness 时钟刷新，告警自动置 resolved（INFO）
责任人：本人
升级路径：1 分钟未处置 → 升级（P0-3）
关联仪表盘：监控中心 v1（A-11）/ 行情活性面板
关联 Trace：event_ts 链路（BASE-4 建成后）
关联日志：logs/live_*.log
最近变更：—
处置分类（TP/FP/自动）：
```
