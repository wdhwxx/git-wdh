## 1. 密钥管理（硬约束）

- API 密钥 / 券商凭证 / 数据库口令 **集中加密存储**（`config/secrets/` 或系统密钥库），**禁止明文落盘**。
- **禁止**出现在：日志、告警内容、监控指标、Runbook、看板、回显（`_redact` 机制已引入，A-2 事件脱敏）。
- 现有 `myquant/utils/` 的凭证读取统一走密钥管理，不硬编码在配置/代码。

## 2. 最小权限

- 进程按需授权：数据读取、券商交易、数据库写权限分离。
- 监控/审计进程只读，不授予交易权限。
- 运维操作（重启/熔断复位/阈值修改）需通过 RBAC（§5）授权。

## 3. 敏感数据脱敏（看板 / 告警 / 日志）

| 敏感类型 | 脱敏规则 |
|----------|----------|
| 券商账号 | 仅显示后 4 位 |
| API 密钥/凭证 | 全部掩码 `****`，禁止出参 |
| 持仓明细（金额/数量） | 看板聚合展示（按策略/板块），明细需 RBAC 查看者以上 |
| 资金余额 | 聚合展示，明细需授权 |
| 告警内容 | 含敏感字段一律脱敏（A-2 `_redact`）后发送 |

## 4. 告警内容防泄露

- 告警消息按脱敏规则处理后才投递外部通道（邮件/Webhook）。
- 外部通道投递失败 → 落盘兜底（`_write_undelivered`），不裸发敏感信息。

## 5. 监控面 RBAC（A-16 对应，R-06）

| 角色 | 可执行动作 | 禁止动作 |
|------|------------|----------|
| **查看者（viewer）** | 查看看板/告警（脱敏视图） | 确认/解决告警、改阈值、复位熔断 |
| **告警处置者（operator）** | 查看 + 确认/解决告警、执行 Runbook 步骤 | 改阈值、复位熔断、改配置 |
| **配置管理者（admin）** | 查看/处置 + 改阈值（monitoring.slo）、改告警规则、复位熔断 | 改交易参数 |
| **只读审计（auditor）** | 查看审计日志（BASE-9） | 一切写操作 |

- 动作矩阵：确认/解决告警、修改阈值、复位熔断、修改配置四类动作逐角色映射。
- 单人系统降级：默认本人=admin+auditor；审计只读通道保留（防未来多人协作）。

## 6. 监控数据加密与访问审计（BASE-9 对应，R-06）

- **存储**：监控时序/告警/审计数据存 OS 加密卷（个人系统降级版：加密卷 + 权限收紧）。
- **关键字段加密**：告警内容中敏感字段、审计日志关键字段加密存储。
- **访问审计**：对看板/告警/配置的访问留痕（BASE-9 审计表：who/what/when），只追加、防篡改。
- **审计数据保护**：审计日志独立于被审计对象，防止"删库灭迹"。
