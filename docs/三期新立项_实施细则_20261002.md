## 7. 数据层防破坏管控（战略顾问铁律，全程适用）

> 背景：数据层近期连续大改，口径漂移风险高（P0 诊断出的"排除规则 vs 标的池不一致"即为先例）。
> 三条总原则：**① 先治口径，再动数据；② 每一刀都可逆；③ 改完必有验证。**

### 7.1 破坏性操作清单（执行前必须双确认）

以下操作命中即属"破坏性"，**先出方案 → 用户明确确认 → 才可执行**，任何一步不得跳过：

- DROP / TRUNCATE / 批量 DELETE / 覆盖写入 / 全表重写式 UPSERT
- 全量清洗、批量 UPDATE 派生量字段
- 修改排除规则 `config\data_clean_run.json`（影响全库口径，且 gitignore + 内置兜底需同步改）
- git revert 含同文件多逻辑的提交（**349ed21 教训**：tdx_source 同文件含 B-2 占位 / 批1④⑤，必须手工剥离，禁止整文件回退）

### 7.2 "每一刀都可逆"三选一

每次数据改动前，至少满足其一，否则不动手：

| 可逆保障 | 适用层 | 判据 |
|---|---|---|
| DB 备份 | 数据层（大操作强制） | 备份已落入 `backups\`（现有 4 份先例，含 5.7GB 级） |
| git 可回滚 | 代码 / 配置 / 文档层 | 当前改动未提交前不叠加新改动，`git revert` 路径清晰 |
| 脚本幂等可重跑 | 补数 / 清洗 | 重复执行结果稳定、不叠加；补丁脚本以 `read_bytes` + `utf-8-sig` + `\r\n→\n` + 写回还原保持可重入 |

### 7.3 操作前后状态指纹比对

每次改动记录权威指纹，改后比对，**任何一项偏离即停并回查**：

- 全库行数 **16,989,737** / 标的 **5,668** / hfq 标签 **0**
- 日期范围 1990-12-19 ~ 2026-09-30
- 派生量覆盖率：全库 `pct_chg IS NOT NULL` 行数占比（P0 完成后即为验收口径）
- 一致性校验四指标：raw 标签 0 / 孤岛 0 / 日期覆盖 / 北交所对齐（`scripts\一致性校验.py`）

### 7.4 小批量先行

任何全量动作先做 **100 只级小批量实测** → 验证效果与耗时 → 再全量。耗时与影响以实测为准，禁止用估算代替（参考：全市场 3,208 只约 3-4 分钟/万行级，必须实测校准）。

### 7.5 一次只改一件事

- 数据层与代码层解耦提交；同一笔提交必须在提交信息中用一句话说清范围 + 验证结论。
- 禁止"顺手改"：与本次任务无关的文件/配置不动。
- 多逻辑同文件时，改动前先确认各逻辑归属（349ed21 教训）。

### 7.6 验证不通过即回退

每步验证（派生量覆盖度 / 抽样比对 / 一致性校验 / 全量 pytest **1730 passed / 2 skipped**）不通过 → 回到最近关卡重新确认。**禁止带病前进、禁止"先提交后补验证"**。

### 7.7 口径治理优先

**D1 未拍板前，禁止任何排除规则 / 标的池 / 清洗范围的实质改动。** 口径一致后，数据改动才有依据；口径未定就动数据，等于在漂移的地基上盖楼（P0 诊断出的 9-28~9-30 约 2,500 行缺口即为漂移证据）。
