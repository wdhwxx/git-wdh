> 依据：《掘金量化仿真模拟盘实施方案报告（终极版）》第四章、`docs/掘金量化仿真模拟盘_任务实施细则摘要.md`

## 一、目的与原则

本制度规范鲲鹏量化系统仿真模拟盘的运行与实盘准入，确保「回测 → 仿真 → 实盘迁移」链路安全可控。

**四条铁律：**
1. 回测与实盘参数一致（策略、手续费、滑点、风控同源）；
2. 全程防未来函数（LookaheadGuard 强制开启，strict 模式）；
3. 仿真—实盘零误接入（统一运行模式切割接口 + 实盘安全门）；
4. 实盘迁移必须双人复核。

---

## 二、运行模式与切割接口

系统以 `myquant/live/run_mode.py` 为单一真相源，统一控制运行模式。

| 模式 | 说明 | 启动命令 |
|---|---|---|
| `monitor` | 仅监控：订阅行情/生成信号，不下单 | `python run_实盘入口.py --mode monitor` |
| `paper` | 本地模拟盘（零外部依赖，仿真默认） | `python run_实盘入口.py --mode paper` |
| `sim` | 券商同源仿真（QMT/Ptrade SIM 撮合，需对应客户端） | `python run_实盘入口.py --mode sim --broker qmt` |
| `live` | 真钱实盘（需确认+账户+时段） | `python run_实盘入口.py --mode live --confirm-live` |

**安全约束：**
- `paper` / `sim` 为仿真，绝不触发真实下单；
- `live` 必须同时满足：`--confirm-live` + 券商为 `qmt/ptrade` + 已配置账户 + A股交易时段（或 `--force`）；
- 配置一致性由 `create_live_engine` 装配前校验（`trade_mode` / `broker.type` / `broker.mode` 冲突即拒绝）。

**未来实盘切割路径：**
```
仿真（paper）→ 同源仿真（sim，QMT SIM）→ 实盘（live，QMT LIVE）
只需切换 --mode + 安装券商客户端 + 配置账户，无需改业务代码。
```

## 三、仿真运行规范

1. **启动前**：确认 `config/live_config.yaml` 为 `trade_mode: paper`、`broker.type: paper`；敏感信息走环境变量，不写入文件。
2. **运行留痕**：仿真运行结束追加 `--stats-json outputs/live/仿真绩效_<日期>.json` 导出引擎统计（供准入评估）。
3. **状态**：`state_store` 启用以持久化快照（崩溃可恢复）；`python run_实盘入口.py --status` 查看。
4. **日志**：运行日志统一落 `logs/`，保留交易与数据质量日志供审计。
5. **纪律**：仿真期禁止以任何方式连接真实资金账户（零误接入）。

## 四、绩效准入评估与实盘准入（T10）

**数据准备：**
- 仿真绩效指标（年化/回撤/夏普/滑点/漏单/风控违规/中断次数）由绩效分析产出，汇总为标准 metrics JSON；
- 回测基线（年化/回撤）用于「不显著劣于回测」比较。

**评估命令：**
```bash
python scripts/仿真准入评估.py \
  --metrics outputs/live/仿真绩效_<日期>.json \
  --backtest results/<回测基线>_metrics.json \
  --output outputs/仿真准入评估_<日期>.csv
```

**判定逻辑（对照表5，阈值可按策略类型调整，见 `acceptance.py` DEFAULT_THRESHOLDS）：**

| 指标 | 达标阈值（示例） |
|---|---|
| 仿真运行时长 | ≥30 天（1个月）且覆盖震荡/趋势 |
| 年化收益率 | ≥目标收益且不显著劣于回测（默认 ≥回测−5%） |
| 最大回撤 | ≤回测回撤×1.3 且 ≤15% |
| 夏普比率 | ≥1.0 |
| 成交一致性 | 平均滑点 ≤万5，无异常漏单 |
| 风控触发 | 零重大违规 |
| 系统稳定性 | 中断次数 ≤3 且均已闭环 |

**准入双控：** 仅当评估结论「通过」（全部 8 项均有结论且无未达标）后，方可进入「量化清单 + 审批」双控：策略研究员出具结论 → 风控合规审批 → 项目负责人批准 → 纳入实盘准入清单。任一未达标/数据不足均不得准入。

## 五、异常预案（T12，对应表8）

| 异常场景 | 处置动作 | 责任环节 |
|---|---|---|
| 行情中断/延迟 | 暂停策略、检查订阅与网络、恢复后核对持仓再续跑 | IT运维 |
| 终端/策略崩溃 | 按预案重启，校验账户连接与持仓一致性（state_store 恢复） | IT运维 |
| 策略异常下单 | 参数/资金风控自动拦截（RiskManager/RiskGuardian），人工复核后决定暂停或回退 | 交易运营/风控 |
| 仿真—实盘疑似串户 | 立即冻结相关账户，核查柜台类型与鉴权，上报处置 | 风控合规 |
| 绩效严重偏离 | 暂停放量，归因分析（滑点/行情/逻辑），出具复盘报告 | 策略研究 |
| 需紧急平仓 | 一键平仓：`python scripts/一键平仓.py --config config/live_config.yaml`（默认 dry-run 预览，真实执行加 `--confirm`） | 交易运营 |

## 六、券商量化权限确认清单（实盘前外部依赖）

> 仿真阶段（paper）**不依赖**本清单，可立即运行。实盘前须逐项确认（联系开户券商客户经理）。

| # | 确认项 | 说明 | 东财 / 国泰海通参考 |
|---|---|---|---|
| 1 | 券商是否提供 QMT / Ptrade 量化权限 | QMT/Ptrade 为券商开通权限，非独立软件 | 国泰海通支持 QMT/Ptrade；东财官方仅支持「东财掘金量化」 |
| 2 | 资金门槛 | 各券商标准不一（普通量化约 50 万，低门槛券商约 10 万） | 以营业部为准 |
| 3 | 佣金费率 | 确认量化权限是否提高佣金 | 多数不提高 |
| 4 | 适当性 | 风险测评 C4/C5、6 个月交易经验、签署程序化交易协议 | — |
| 5 | 程序化报备 | 按《证券市场程序化交易管理规定》报备账户策略软件 | — |
| 6 | QMT 客户端安装包 | 向券商获取对应版本（自定义盘位置安装），配置 `qmt_path` | — |
| 7 | 账户与资金白名单 | 实盘需真实资金账号与白名单 | — |

**结论：** 若未来实盘走 QMT/Ptrade，优先向**国泰海通（君弘）**申请量化权限实现同源切割；东财账户日常看盘，必要时加开支持 QMT 的券商（同一身份证可多家开户，无需销户）。

## 七、合规与报备

1. 程序化交易按监管要求报备（《证券市场程序化交易管理规定（试行）》证监会公告〔2024〕8号，2024-10-08 施行）；
2. 个人程序化须在券商封闭终端内进行，报备账户策略软件；
3. 仿真—实盘迁移、重大异常、风控事件均留痕（logs/ + outputs/ + 状态快照），留痕率目标 100%。

## 九、仿真→实盘迁移检查单

- [ ] 仿真绩效准入评估通过（`scripts/仿真准入评估.py` 结论「通过」）
- [ ] A 类验收（`pytest` 实盘相关子集）全过
- [ ] B 类验收：真实 QMT 环境 T1/T3/T7（需 QMT 客户端实连）
- [ ] C 类验收：T8 全天运行 + 小额真钱验证
- [ ] 券商量化权限、账户、资金白名单就绪（第六节清单）
- [ ] 程序化报备完成
- [ ] 双人复核并批准迁移
- [ ] 以 `--mode live --confirm-live` 启动，先小额放量
