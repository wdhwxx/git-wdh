## 三、偏差项清单（按严重度排序）

### ⚠️ 偏差① 数据质量日志：蓝图声明未落地（唯一"声明>实现"的实质缺口）

- **蓝图声明**（两处）：
  - 头部说明第 8 行：v1 落地范围含"脏数据日志+落盘"
  - `core/logger.py` 条目："v1增加独立 data_quality 日志 handler 输出告警"
  - `logs/` 条目："专门分出 data_quality 子目录存放清洗告警日志"
- **实际情况**：
  - `logger.py` 仅实现 控制台 + 全量文件 + 错误文件 + trade 四类 handler，**无 data_quality 独立 handler**
  - `logs/` 目录实际只有 主日志/错误/交易 三类文件，**无 data_quality 子目录**
- **缓解事实**：脏数据"落盘"本身已实现（`datasets/bad/*.json` + `outputs/quality_report_*.json`），缺的是独立日志通道。蓝图第 8 行的头部声明（"不做事件总线推送、风控联动"）与后文已实现的联动能力也存在措辞滞后——事件总线联动实际已在后续任务中实现，蓝图头部"v1范围"段未同步更新。
- **建议（供决策，不代改）**：要么在 logger 补 data_quality handler 对齐蓝图；要么修订蓝图，把脏数据留痕口径改为"bad 目录归档 + 质量报告 json"。
