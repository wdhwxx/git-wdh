## 五、费用层：唯一做对的一轴（但门禁在撒谎）

### 做对的（应保留，勿一起改掉）

- **`FeeCalculator` 真正统一**：回测三引擎 + `paper_broker` + `qmt_broker` + `sim_broker` 共用同一模型，无第三套实现

- **滑点无重复扣减**：两边均为"折进成交价"，只算一次
- **实盘 `paper_broker` 与 event 约定逐位一致**

### 两个"门禁在撒谎"

**1. realism manifest 恒报错误费率**

`models/backtest.py:160-180` 的 `to_dict()` **不含 `commission`**，而 `backtest/engine.py:189-193` 从 `cfg_dict.get("commission", {})` 取值 → 恒落默认值：**佣金万3、过户费万0.2**，真模型为万2、万0.1。门禁只校验 `> 0`，永远通过。

> **紧邻的滑点字段已改成读真实实例**（`engine.py:177-188` 有明确注释），**佣金五行没改**。修法照抄旁边即可。

**2. 三引擎对拍阈值缺乏依据**

`rel_tol = 5e-3` 的依据（"费用基数差致 0.9% 净值差"）**数量级上不可能**——实算约 3e-5%/往返，凑出 0.9% 需约 3 万次满仓往返，而窗口不足 680 根 bar。**这个宽松阈值可能正在掩盖一个未定位的真实差异。**

### [SUSPECTED｜外部数据] 印花税可能已过时

代码忠实实现文档写的千1（`models/backtest.py:47`）。但 A 股印花税据报自 **2023-08-28 起已减半至 0.05%**，而回测窗口为 **2024-01-01 起**，整段落在减半之后。全项目 57 处印花税表述无一提到减半。

- 量级：10 万卖出，千1 收 100 元 vs 千0.5 收 50 元 → **每卖腿高估 5bp**，约 1-2%/年
- 方向：**回测与实盘账本同时高估成本**
- ⚠️ **此为外部政策事实，本报告未联网核实来源。请以实际交割单为准再决定是否修改。**

### 实盘从不读取券商实际扣费

`qmt_broker.py:1951-1971` 成交回调只取 `order_id`/`traded_price`/`traded_volume`/`trade_id`，然后**本地估算**费用。全仓库 `actual_fee|broker_fee|traded_amount` 零命中。→ 所谓"费用一致"是**模型对模型**，从未与**结算**对账。

## 七、优先级建议

| 序 | 动作 | 理由 |
|---|---|---|
| **0** | 确认实盘是否真在收行情（`--dry-run`） | 若是死链路，其余讨论前提不成立 |
| **1** | 确认要跑哪个策略，让回测跑同一个 | 其余全部无意义 |
| **2** | 修 `on_init` 时序（warmup 后重跑/加 `on_warmup_complete`）；修 `_processed_signal_ids` 每次清空 | 否则 RSRS 实盘恒躺平且监控报"零偏差"；重启重复下单 |
| **3** | 复权口径单点收敛（`adjust_out` 接线 + `adjust` 对齐）；`capital_base` 引擎统一注入；`risk_control` 段对齐 | 每次下单股数都错；40 万下单在回测被拒 |
| **4** | 建真信号落盘 + C-10（带 bar 时间戳）；**撤销 T+1 自动豁免**；启动加空仓/持仓断言与恢复校验 | 唯一能自动发现"又漂了"的机制；且当前违背项目自己的红线 |
| **5** | 仓位收敛为单一契约；接通轻量守卫三检查；实盘注入 `lookahead_guard` 与因果切片 | 关闭"无结构证据"状态 |
| **6** | 修 manifest 佣金字段（约 5 行）；**以交割单核实印花税**；接通滑点监控字段 | 廉价高价值；印花税率属外部事实，勿据本报告直接改 |
