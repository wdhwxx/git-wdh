## Phase 2 — 致命 bug 修复（修完策略才能真正发信号）

### 任务 T2-1 🔴 修 `on_init` 时序颠倒（RSRS 实盘恒躺平的根因）

  4. 注意：`ma_strategy.py:205-207` 已有注释——初始股票池**不要**在 on_init 里用全量数据构建（那会引入未来函数），保持"首根可交易 bar 惰性初始化"的现状不动。

## Phase 3 — 数据/资金口径对齐（同一信号算出来的股数必须一样）

### 任务 T3-1 🟠 复权口径分层收敛（**最大的坑，不要硬合并**）

- **现状三套**（报告已列）：
  | 路径 | 现口径 | 位置 |
  |---|---|---|
  | 回测主入口 | hfq（后复权） | `backtest_config.yaml:3256` → `provider.py:934-936` |
  | 实盘实时 bar | raw（不复权） | `data_feed.py:827` 默认 |
  | 实盘预热兜底 | qfq（前复权） | `live/engine.py:1359,1373` |
- **改法（分层架构，不是三套合一）**：
  - **信号/指标层**：统一用 **hfq 连续序列**（除权日不跳变，EMA/MACD/RSRS 稳定）。
  - **撮合/下单层**：始终用**当日真实 raw 价**（券商认的就是这个价）。
  - 两层之间通过复权因子换算，禁止把实盘下单也改成 hfq 虚价，也禁止把回测指标改成 raw（会在除权日跳变）。
  - 具体接线：`live/engine.py:2779-2784` 实时 bar 显式传 `adjust_out="hfq"` 给指标序列；`data_feed.py:827` 的默认值改为显式参数，不允许静默落 raw。
- **验收**：同一标的、同一历史区间，回测指标序列与实盘预热指标序列逐值 diff 为空（容差 1e-6）。
- **回滚**：git 还原 data_feed 与 live/engine 相关行。

### 任务 T3-2 🟡 `capital_base` 2 倍注入缺陷

- **位置**：`live/engine.py:2791` 🔴已核实——`strategy_params.setdefault("capital_base", initial_capital)` 实盘注入 200 万；回测 `config_builder.py:203` 只透传 params、不含该键 → 落类默认 100 万。之前回测自身资金恰好也是 100 万，两个错误互相抵消没暴露。
- **改法**：回测装配侧显式透传 `capital_base`，与实盘同一个数（配合 T1-1，统一 100 万）。
- **验收**：回测与实盘日志里打印的 `capital_base` 相同。

### 任务 T3-3 🟡 风控参数对齐 + lot_size 死代码

- **问题 A**：回测 `max_order_amount` 走工厂默认 200,000；实盘配 `max_order_value: 500000` → **实盘 2M×20%=40 万的下单，回测会拒、实盘会放行**。
- **问题 B**：`SimBroker` 默认 `lot_size=0`（`sim_broker.py:75,381`），整手约束在生产事件引擎回测里是死代码；而 mixed/vectorized 传了、实盘也强制。
- **改法**：
  1. 回测 yaml 补 `risk_control` 段，与实盘逐行一致。
  2. `SimBroker` 装配处显式传 `lot_size=100`，不要用默认 0。
- **验收**：同一笔 40 万订单在回测与实盘都放行（或都拒）；回测出现零股订单时被拒。

## Phase 4 — 执行纪律与监控整改

### 任务 T4-1 🟠 撤销 T+1 自动豁免（**必须同时改 paper 撮合时机，否则信号永不成交**）

- **位置**：`live/engine.py:2420-2422` 🔴已核实——`skip_t1 = (trade_date==signal_date) or ...`。而 `lookahead_guard.py:368` 的违规分支正是 `trade_date <= signal_date`。项目自己的红线文档 `防泄漏门禁红线清单.md:23,35` 把 RL-08 列为"**不可豁免**"。
- **改法（两步，缺一不可）**：
  1. 删除 `skip_t1` 自动豁免逻辑，信号日（T 日）生成的订单**不允许当日成交**。
  2. **同步改 paper_broker 撮合时机**：T 日信号落盘记账，**T+1 根 bar 开盘价撮合**——这才与回测 event 引擎（`backtest/engine.py:771-773` 次 bar 开盘成交）真正同构。
- ⚠️ 只做第 1 步不改第 2 步的后果：paper 模式所有信号都不成交，净值永远是初始资金。
- **验收**：paper 回放同一历史窗口，成交日期全部 = 信号日期 + 1 个交易日；`lookahead_guard` 不再因 `trade_date==signal_date` 报违规（因为这种情况已不存在）。

### 任务 T4-2 🟡 启动即下单问题

- **位置**：`live/engine.py:1316-1317`——最后一根预热 bar 的信号直接走完风控→算量→下单，可能落在非交易时段。
- **改法**：预热回放阶段只记录信号、不提交订单；预热完成后的**第一根真实 bar** 才允许下单。
- **验收**：非交易时段启动引擎，不产生任何订单。

### 任务 T4-3 🟡 真信号落盘 + 修复 C-10 信号一致性监控

- **背景**：`myquant/monitoring/signal_consistency.py` 目前是桩——无生产调用者、回测侧无信号流、`signal_id` 回测恒为空字符串、`DEFAULT_TIME_TOLERANCE=0.0` 且时间戳是墙钟不是 bar 时间 → `mismatch_rate` 硬编码返回 0，告警永不触发。
- **改法**：
  1. 回测侧 `BacktestResult` 增加信号流（symbol/date/side/strength/signal_id）。
  2. `make_signal_id` 在回测与实盘两侧都生成（现在只在 `live/engine.py:1496` 调用）。
  3. `Signal.timestamp` 传 **bar 时间**，不传构造墙钟。
  4. `DEFAULT_TIME_TOLERANCE` 放宽到 1 个交易日。
- **验收**：人为制造一个回测/实盘信号差异，C-10 能在日志里打出非零 mismatch_rate 并告警。

### 任务 T4-4 🟡 策略状态落盘与恢复校验

- **背景**：`datasets/live_state/ma_cross_live_demo/` 已积累 61 个版本，快照只有账户/持仓/订单，无 strategy 块；恢复时 `load_latest()` 无时效校验、无策略/参数对比 → 重启后 kunpeng 的 `days_held` 归 1、`peak_close` 塌缩到当日收盘，移动止损失效。
- **改法**：
  1. 快照写入时增加 `strategy_state` 块（days_held / peak_close / entry_close / 已持仓标识）。
  2. 恢复时校验：快照里的 `config_version` / 策略名 / 参数哈希 与当前启动配置不一致 → 拒绝恢复，从零开始，不"伪造持仓历史"。
- **验收**：手动修改启动参数后重启，引擎拒绝加载旧快照并打印原因。
