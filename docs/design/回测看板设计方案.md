## 2. 数据契约（看板的地基）

### 2.1 现成可用的三类数据

**① 净值曲线 `EquityPoint`**（`models/backtest.py:377-402`）

```
timestamp · date · equity · cash · position_value · drawdown · benchmark_equity · extra
派生属性 total_value = cash + position_value
```
> `drawdown` 与 `benchmark_equity` **已由引擎逐点算好**，看板无需重算回撤 —— 这是现成的最大便利。

**② 逐笔交易 `TradeRecord`**（`models/backtest.py:317-363`）

```
trade_id · symbol · side · quantity · price · timestamp
commission · slippage · pnl · pnl_pct · holding_days
strategy_id · signal_source · entry_reason · exit_reason · extra
```
> `entry_reason` / `exit_reason` / `signal_source` 是**归因富矿**。实测 RSRS 策略写入的 reason 形如 `"RSRS=0.823 > 0.7"`、`"take_profit +20%"`（`ma_strategy.py:236, 274`），均值回归策略写入 `"stop_loss -8%"`（`mean_reversion_strategy.py:281`）。看板可直接聚合出"出场原因分布"，无需任何后端改造。

**③ 绩效指标 `PerformanceMetrics`**（`models/backtest.py:170-224`，`backtest/metrics.py:72-135`）

| 类别 | 字段 | 计算口径（实测） |
|---|---|---|
| 收益 | `total_return` | 末净值/初净值 − 1（`metrics.py:147`） |
| | `annualized_return` | (1+总收益)^(252/天数) − 1（`:151-153`） |
| | `benchmark_return` / `excess_return` | 基准净值变化率 / 策略−基准（`:314-315`） |
| 风险 | `annualized_volatility` | 日收益 std × √252（`:164`） |
| | `downside_volatility` | 负收益 std × √252（`:168-170`） |
| | `max_drawdown` / `max_drawdown_duration` | 峰谷最大跌幅 / 最长回撤天数（`:173-187`） |
| 风险调整 | `sharpe_ratio` | (日均超额/日收益std) × √252（`:203-206`） |
| | `sortino_ratio` | 日均超额/下行波动 × √252（`:210-213`） |
| | `calmar_ratio` | 年化收益/最大回撤（`:216-217`） |
| | `information_ratio` | 超额均值/跟踪误差 × √252（`:332-335`） |
| 交易 | `total_trades` | SELL 且 holding_days>0 的平仓笔数（`:233`） |
| | `win_rate` / `profit_loss_ratio` | 盈利笔数占比 / avg_win÷\|avg_loss\|（`:243-255`） |
| | `max_consecutive_wins` / `losses` | 最大连胜/连亏（`:258-272`） |
| 成本 | `total_commission` / `total_slippage` / `turnover` | 费用累加 / 成交额÷平均总资产（`:282-294`） |
| 基准 | `alpha` / `beta` / `tracking_error` | CAPM α / Cov÷Var / 超额std×√252（`:319-335`） |
| 分布 | `var_95` / `cvar_95` / `skewness` / `kurtosis` | 5%分位 / 尾部均值 / 三四阶矩（`:349-360`） |

**费率模型**（`models/backtest.py:35-68`，`fee_common.py:20-24`）：佣金万2（最低5元，双向）· 印花税千1（仅卖出）· 过户费万0.1（双向）· 滑点 2bps `fixed_bps`（支持 `volume_based`）。

### 2.2 缺口：不是数据缺失，而是聚合缺失

这是本方案最重要的判断。以下看板必需指标 `MetricsCalculator` **未计算**，但 `equity_curve` 原始逐日数据完全够派生：

| 缺失指标 | 可否派生 | 派生自 | 备注 |
|---|---|---|---|
| 月度收益分解 | ✅ 可 | `equity_curve[].date` + `equity` | `metrics.py` 无月度逻辑 |
| 年度收益分解 | ✅ 可 | 同上 | |
| 滚动夏普 / 滚动回撤序列 | ✅ 可 | 同上（滑窗重算） | |
| 收益率分布直方图 | ✅ 可 | `equity` 一阶差分 | 现仅有 `skewness/kurtosis/var_95/cvar_95` 四个标量 |
| 个股贡献排行 | ✅ 可 | `trades[].symbol` 聚合 `pnl` | |
| 出场原因分布 | ✅ 可 | `trades[].exit_reason` 归类 | |
| 换手率按标的拆分 | ⚠️ 部分 | `trades` 可聚合，但无标的级资产权重 | |
| `incremental_update()` | ❌ 占位 | — | `metrics.py:434-450` 直接返回原对象，**不可依赖** |

> **设计含义**：看板需要新增一个**派生聚合层**（§4.3），而不是去改 `MetricsCalculator`。好处是回测内核零侵入，聚合逻辑可独立测试与演进。

## 3. 技术选型

### 3.1 三方案对比

| 维度 | **方案 A**<br>单文件深色 HTML 看板 | **方案 B**<br>Streamlit 回测页填充 | **方案 C**<br>FastAPI + SPA |
|---|---|---|---|
| 图表库 | ECharts（深色主题原生支持强） | Plotly（Streamlit 原生） | ECharts / D3 |
| 科技感上限 | **高**（完全可控 CSS/SVG/动效） | 中（受 Streamlit 主题约束） | 高 |
| 部署成本 | **零**（双击打开 / 静态托管） | 低（已有骨架） | 高（需前后端分离） |
| 交互能力 | 快照级（筛选、缩放、联动） | **可触发回测** | 全实时 |
| 离线分享 | **✅ 单文件即可发** | ❌ 需启服务 | ❌ |
| 与现有代码关系 | 新增 `backtest/dashboard_renderer.py` | 填充 `dashboard.py:336-375` | 与 `myquant/api` 骨架**重复建设** |
| 数据新鲜度 | 每次回测产出一份快照 | 实时 | 实时 |
| 实现工作量 | 中 | 低—中 | 高 |

### 3.2 推荐：A 为主，B 为辅，放弃 C

**推荐理由**

1. **A 与 B 不是竞品，是分工**。A 是"**报告级看板**"——每次回测固化一份可存档、可对比、可外发的快照；B 是"**操作级看板**"——在系统内触发回测、切换参数、横向比较。两者共用同一份 §2.3 JSON Schema，一次设计两处复用。
2. **C 应放弃**。`myquant/api/` 已有 `schemas.py` 与 `dependencies/get_services.py` 骨架，另起 SPA 会与 Streamlit、tkinter GUI 形成**第三套重复建设**，而项目已有两套未完成。
3. **A 的视觉可与结构图统一**。配套的 [量化模型结构图.html](量化模型结构图.html) 已确立深色科技风设计语言（§5 design token 直接沿用），两份交付物观感一致。
4. **A 复用 `downsample_equity_curve`** 可解决单文件体积问题，这是 `report.py` 已验证过的路径。

**关于 tkinter GUI**：建议明确定位为"**本地配置与调试工具**"，不承载看板职能，避免三套展示层继续并行膨胀。其 `gui/widgets/kline_item.py` 的 K 线绘制逻辑可作为 A 方案 K 线图的算法参考。

### 4.3 派生聚合层设计

新增模块建议：`myquant/backtest/dashboard_derive.py`

```
输入：BacktestResult
输出：derived dict（§2.3 的 "derived" 块）

函数划分：
  derive_daily_returns(equity_curve)      -> List[float]
  derive_monthly_returns(equity_curve)    -> List[{month, return, benchmark_return}]
  derive_rolling(equity_curve, window)    -> {rolling_sharpe, rolling_drawdown, rolling_win_rate}
  derive_exit_reasons(trades)             -> List[{reason_class, count, pnl_sum}]
  derive_symbol_contribution(trades)      -> List[{symbol, pnl, trades, win_rate}]
  derive_cost_breakdown(trades, config)   -> {commission, slippage, stamp_tax, transfer_fee}
```

**设计约束**
- **纯函数、无副作用**，不触碰回测内核，可独立单测。
- `exit_reason` 归类需容错：实测 reason 为自由文本（`"RSRS=-0.812 < -0.7"`、`"take_profit +20%"`、`"stop_loss -8%"`），应按前缀关键词归类，未匹配的归入 `other` 并保留原文，**不可静默丢弃**。
- 滚动窗口默认 60 交易日，与 RSRS `norm_window=60` 对齐，便于解释。

## 8. ⚠ 前置阻塞：三处口径冲突（需决策）

调研中发现文档与代码存在实质冲突。**这些不是文档瑕疵，而是会直接导致看板展示错误策略语义**，必须在第一期任务 1 解决。

### 冲突 1：波动率因子取高还是取低？（影响最大）

| 来源 | 表述 |
|---|---|
| `README.md:7` | 三因子交集股票池（**高波动** ∩ 高价 ∩ 高动量） |
| `docs/strategy_specs.md:65` | 波动率因子 → 取前 1/3 **高波动率** |
| `strategies/base.py:625`（**代码实测**） | `factor_df.nsmallest(top_n, 'volatility')` → 取**低波动** |
| `strategies/base.py:631`（日志实测） | `"三因子交集: 总{n} → 低波动{...} ∩ 高价{...} ∩ 高动量{...}"` |

**代码与自身日志一致（低波动），与两份文档冲突（高波动）。**

**影响**：看板 Z6 个股贡献、股票池构成展示若标注"高波动"，将与实际选股逻辑相反。`strategy_specs.md:88-96` 的对比表亦标注"高波动率单因子 234 只 +63.65%"，该历史回测结论的因子方向同样存疑。

**建议**：以代码为准，修正两份文档为"低波动"，并复核 §1.5 绩效数据是在哪个方向下跑出的。

### 冲突 2：核心策略是否实现止损？

| 来源 | 表述 |
|---|---|
| `docs/strategy_specs.md:44` | `stop_loss_pct` = 0.15，止损 −15%（0=不启用） |
| `docs/strategy_specs.md:125` | 卖出规则含"持仓收益 ≤ −15%（止损，如启用）" |
| `ma_strategy.py:78-106`（**代码实测**） | `RSRSStrategy.__init__` 参数仅 `buy_threshold` / `sell_threshold` / `take_profit_pct` / `max_position_pct` / `max_positions` / `pool_rebalance_days`，**无 `stop_loss_pct`** |
| 全文件检索 | `RSRSStrategy` 内**无任何** `check_stop_loss` 调用 |

**对比**：`MeanReversionStrategy` 确实实现了止损（`mean_reversion_strategy.py:103, 272`，默认 0.08）；`MultiFactorStrategy` 亦有（`multi_factor_strategy.py:138`，默认 0.10）。**唯独核心 RSRS 策略没有。**

**风控层不能替代**：`StopLossRule(max_loss_pct=0.10)` 与 `TakeProfitRule(max_profit_pct=0.50)` 仅**禁止加仓**，不自动平仓（`risk_manager.py:19` 明确"v1 不自动平仓"；`guardian.py:474-514` 强制平仓只记录不执行）。

**影响**：**这解释了 `strategy_specs.md:54` 记录的 −49.29% 最大回撤**（远超 :190 设定的 <30% 合格线）。核心策略实际只有 +20% 止盈和 RSRS<−0.7 择时退出两条出场路径，缺乏硬止损。看板 Z3 回撤视图与 Z6 出场原因分布会直接暴露此问题。

**建议**：属策略缺陷而非文档瑕疵，需决策是补实现止损，还是修正文档承认无止损设计。

### 冲突 3：撮合层是否处理涨跌停与停牌？

| 来源 | 表述 |
|---|---|
| `docs/strategy_specs.md:177-178` | 回测校验清单要求"涨停日不能买入，跌停日不能卖出""停牌日跳过" |
| `gui/backtest_config_dialog.py:291` | 配置项 `enforce_limit_up_down: True` 存在 |
| `risk/rules.py:354-369` | `PriceLimitRule` 实现了"涨停不能买，跌停不能卖"（±10%） |
| `order_matcher.py:334-397`（**代码实测**） | `_match_price` **不检查** `is_suspended`，**不校验**涨跌幅限制 |
| 实盘侧对比 | `live/brokers/paper_broker.py:751-769` 与 `qmt_broker.py:805-820` **均已实现**涨跌停校验 |

**结论**：约束存在但**位置在风控前置拦截层，不在撮合层**；且 `enforce_limit_up_down` 配置项在 `order_matcher` 中无对应消费逻辑。数据库 `is_suspended` 字段存在（`schema.py:65`），`data_access/manager.py:687` 按 `volume==0` 写入停牌标记，但撮合未读取。

**影响**：若 `PriceLimitRule` 未被启用（其不在默认库的强制路径上），回测可能在涨停日成交，导致**收益虚高**。看板需明确展示"风控规则启用状态"（Z10），否则使用者无法判断结果可信度。

**建议**：看板 Z10 必须呈现 10 条风控规则的**实际启用状态与阈值**，而非仅列出规则名。同时建议核实撮合层是否应补停牌校验。

## 9. 风险与约束

| 风险 | 说明 | 缓解 |
|---|---|---|
| 单文件体积失控 | 多年日线 + 全市场逐笔交易，JSON 可能达数十 MB | 复用 `downsample_equity_curve`；`trades` 分页/截断（`report.py:245` 已有"最近50笔"先例）；进阶 Tab 懒加载 |
| 派生指标口径分歧 | 前端派生的夏普与 `metrics.py:203-206` 可能因年化因子、rf 取值不同而不一致 | 派生层严格复用 `metrics.py` 公式；Z7 滚动夏普标注窗口与公式；验收任务 6 做一致性核对 |
| 三处口径冲突未决 | 看板会忠实呈现错误语义 | §8 列为第一期任务 1 前置阻塞 |
| `incremental_update()` 占位 | `metrics.py:434-450` 返回原对象 | **禁止依赖**，派生层自行实现滑窗 |
| Streamlit 重跑开销 | 每次交互全脚本重跑，大结果集卡顿 | 第三期用 `st.cache_data` 缓存 JSON；重计算放派生层 |
| 展示层继续膨胀 | 已有 Streamlit + tkinter 两套未完成 | §7 明确边界；放弃方案 C；GUI 定位收窄 |

## 10. 验收标准

第一期完成的判定条件：

1. 输入一份真实 `BacktestResult`，产出**单个 HTML 文件**，双击可离线打开，无外部服务依赖。
2. Z1 的 10 个 KPI 数值与 `metrics.py` 计算结果**逐项一致**（误差 < 1e-6）。
3. Z3 回撤曲线与 `equity_curve[].drawdown` **逐点一致**（不重算）。
4. Z6 出场原因分布覆盖 `trades` **全部记录**，`other` 类占比 < 5%（否则说明归类规则需补强）。
5. Z8 月度热力图各月收益**连乘**约等于 `metrics.total_return`（校验派生逻辑自洽）。
6. 夏普（Z1）与滚动夏普（Z7）在窗口=全期时**收敛于同一值**。
7. 三项达标判定（夏普、最大回撤）按 `strategy_specs.md:186-193` 标准正确标红。
8. 风控规则区（Z10）呈现 10 条规则的**实际启用状态与阈值**，非仅规则名。
9. 单文件体积在 10 年日线 + 500 笔交易场景下 **< 5 MB**。
