## 二、逐项任务卡

### F-13 因子缓存失效解析修复 ✅

- **模块**：myquant/indicators/factor_cache.py
- **根因**：L2 扁平文件名 `{factor}_{symbol}_{params}_{fp}.parquet` 在 invalidate() 用 `split("_",3)` 反向切分，因子名含下划线（bollinger_bands）时解析错位 → invalidate 永远匹配不上，L2 缓存删不掉；data_fingerprint=None 时 fp_short 固定 "nofp"，7 天 TTL 内永久命中脏缓存。
- **整改内容**：
  1. L2 改目录分层存储 `{safe_factor}/{safe_symbol}/{params_hash}_{fp}.parquet`，invalidate 按 shutil.rmtree 删目录
  2. nofp 场景强制 NOFP_FINGERPRINT_TTL=3600s（即使 l2_ttl=0 也不豁免）+ WARNING 告警去重
- **实施结果**：新增 tests/unit/test_factor_cache_nofp.py（16 项）；全量 2001 passed / 2 skipped（基线 1985 + 16，零回归）；提交 ccee46c

### F-14 增量特征加速与推理缓存 ✅

- **模块**：myquant/ml/features.py、myquant/ml/inference_service.py
- **根因**：compute_incremental 每次对全量历史 compute_features 重算取末行，单 bar 耗时 O(N) 随历史线性增长；同 bar 多模块重复调用无短 TTL 复用。
- **整改内容**：
  1. 新增 `IncrementalFeatureSession`：首次 update(df) warmup 逐行喂指标流式 update() 建状态，之后 push 新 bar O(1)/O(窗口)；价格衍生特征用 deque 环形缓冲；任一指标无 update() 自动降级全量重算兜底
  2. inference_service 加 `result_cache_ttl_ms`（默认 0=关闭零变化）短 TTL 结果缓存
- **实施结果**：新增 tests/unit/test_incremental_session.py（9 项）；增量 vs 全量末行容差一致、单 bar 耗时 len=200 vs 2000 不超 5 倍；全量 2010 passed / 2 skipped（基线 2001 + 9，零回归）；提交 c4cf44d

### F-15 基本面因子接入（公告日时点化）✅

- **模块**：myquant/database/schema.py、myquant/data_access/financial_service.py
- **根因**：`_build_fundamental_rows` 旧版用 `report_date <= trade_date` 做时点过滤——report_date 是报告期（Q2 截止 6/30），实际披露常在 8 月底，7/15 信号日会错误引用尚未公开的中报，构成未来函数；financial_data 表无 ann_date 公告日字段。
- **整改内容**：
  1. financial_data 表新增 `ann_date TEXT` 公告日列 + `idx_fin_ann_date` 索引；新增幂等迁移 `_migrate_financial_data_columns()`（PRAGMA 判断后 ALTER TABLE）；create_all_tables 顺序修正为「建表→迁移→建索引」
  2. `_map_csv_row` 解析 CSV 可选 ann_date 列（缺失置 NULL）；`_build_fundamental_rows` 重写为按「有效披露日 = COALESCE(ann_date, report_date) ≤ trade_date」选最新可见财报
- **验收**：负向测试——Q2 报告期 6/30、公告日 8/28 在 7/15 信号日不可见（正确回退看 4/15 披露的年报）；ann_date=NULL 存量行回退 report_date 向后兼容；真实 quant.db 迁移成功
- **实施结果**：新增 tests/unit/test_f15_ann_date_pointin.py（7 项）；全量 2017 passed / 2 skipped（基线 2010 + 7，零回归）；提交 59e3d62

### 附-A data_versioner 数据集口径版本登记 ✅

- **模块**：myquant/utils/data_versioner.py（新）、myquant/utils/__init__.py（导出）
- **背景**：F-07 时用户确认 data_versioner 拆出，与 F-15 公告日时点化排期关联；报告风险表点名「ann_date 切换会改变历史数据分布，须登记每个数据集指纹，历史结论标注口径版本，不做跨口径直接比较」。
- **整改内容**：
  1. `DATASET_SCHEMA_REVISIONS`：market_data=2（派生列加入）、financial_data=2（F-15 ann_date 时点语义变更）、factor_data=1；破坏性结构变更手动 bump
  2. `DatasetVersion` 值对象 + `get_dataset_version(conn, dataset)`：现算 schema_revision + row_count + 日期范围 + 列结构 sha256
  3. `write_result_version_sidecar`：结果文件旁写 `.version.json` 标注数据集版本 + git 短哈希；`load_result_version_sidecar` 读取
  4. `assert_versions_compatible`：schema_revision 不一致抛 DataVersionMismatchError，阻止跨口径 IC/绩效直比
- **实施结果**：新增 tests/unit/test_data_versioner.py（9 项）；全量回归待跑
- **合规要点**：本模块不做时间序列计算（无未来函数风险）；零变化纪律（纯新增模块，不改动既有调用链）；sidecar 写入是 opt-in（调用方显式调用才生成）
