基于 2026-10-02 风险审查结论，将「6 项高风险 + 12 项中风险 + 2 项低风险」转化为 15 项可执行整改任务，按 P0 / P1 / P2 三级优先级在三个阶段内落地，并给出仿真、模拟盘、实盘试运行三级验收门。

6 / 12 / 2高风险 / 中风险 / 低风险
15项整改任务（P0×6 / P1×6 / P2×3）
3 阶段止血 → 加固 → 增强（约 6 周）

01

执行摘要

上一轮审查确认：技术因子层面防未来函数与工程护栏（缓存指纹、时序切分、版本链、checksum）明显优于一般个人量化项目，但系统在因子有效性验证、因子处理标准化、训练-推理一致性、模型生命周期治理四个支柱上存在结构性缺失，叠加回测幸存者偏差，整体判定为高风险、不可直接实盘。

核心结论

本报告将 20 项风险收敛为三大根因，据此设计 15 项整改任务。P0 六项（特征一致性、因子有效性、去极值与中性化、幸存者偏差、失效监控、端到端测试）是上线阻塞项，须在阶段一内完成；完成全部 P0 后系统可达「仿真准入」水平，再经模拟盘 3 个月与 Gate 验收后方可评估实盘试运行。

三大根因

根因 R1

因子有效性缺失

无 IC/ICIR 校验、无去极值与中性化、无经济学约束，因子权重手工设定——信号质量不可知。

根因 R2

回测可信度不足

幸存者偏差、训练目标不含成本、面板切分缓冲失真——历史绩效不可信、不可复现。

根因 R3

工程治理断链

训练-推理特征一致性断裂、无模型失效监控、元数据缺数据快照与签名——线上不可靠、不可回退。

优化目标（递进四层）

因子可度量IC / ICIR / 衰减 / 门槛全部可计算、可审计
回测可复现数据快照 + 版本链 + 成本口径统一
模型可治理全生命周期元数据 + 失效自动降级
线上可回退训练-推理一致 + 模型热回滚 + 因子开关

03

优化目标架构

在不推翻现有分层的前提下，于既有链路上插入五个新组件，形成「计算 → 预处理 → 校验 → 训练 → 推理 → 治理」完整闭环。虚线框为新增/改造组件，实线框为既有组件。

新增/改造组件职责消除的风险点对应整改
data_versioner为每次训练登记数据指纹/快照引用，财务表补公告日字段，实现「报告期 ≠ 可得时点」的时点化未来函数（潜伏）、版本溯源F-07 / F-15
factor_preprocessor统一预处理管线：MAD/分位去极值 → 行业/市值中性化 → 回归归残与残差检验，输出带暴露审计的干净因子去极值、中性化、波动率稳健化F-03 / F-10
factor_validator内置 IC/ICIR/因子衰减计算与有效性门槛，因子生命周期状态机（候选→活跃→观察→淘汰）基础有效性校验缺失F-02
feature_contract统一列名契约与特征签名，训练/推理双向一致性校验，指标失败显式报错并记录训练-推理特征一致性F-01
model_monitor滚动窗口监控 IC/绩效/漂移，触发阈值自动标记失效并降级到上一活跃版本，输出告警失效预警缺失F-05
推理缓存与增量特征特征 O(1) 增量更新 + 推理结果短 TTL 缓存 + 延迟基准压测延迟退化、无缓存复用F-14
04

分模块实施计划（15 项整改任务）

按「上线阻塞 → 关键增强 → 进阶优化」三级划分。每项含目标、具体改动、涉及文件与验收标准；验收标准为硬性门禁，未通过不得进入下一阶段。

P0上线阻塞项（阶段一，第 1–2 周）6 项 · 全部完成方可进入仿真验收
F-01修复训练-推理特征一致性断裂高
模块 4 · inference_service模块 3 · features.py
  • 统一列名契约：指标层与特征层全部收敛到同一套 OHLC 列名（中文列），bars_to_df 产出对齐；删除 `_validate_data` 与 `bars_to_df` 的隐式语言差异
  • 指标计算失败从「warning + 跳过」改为显式抛错/写入失败登记，禁止静默降级
  • 新增 feature_contract：训练注册特征签名，推理前双向比对（列名、顺序、dtype），不一致即拒预测
验收：train → register → inference 全链路端到端测试通过；特征列不一致在推理侧 100% 被拦截；无任何静默跳过的指标
F-02因子有效性校验（IC/ICIR）高
模块 1 · factor_engine新增 factor_validator
  • 内置 IC/ICIR/因子收益率/衰减曲线计算器（RankIC + PearsonIC 双口径，按截面-时间双维度）
  • 为每个因子登记：样本区间、IC 均值、ICIR、胜率、换手、经济逻辑说明；低于门槛自动进入「观察/淘汰」
  • multi_factor_strategy 权重改为「IC 加权 + 下限约束」，废除纯手工权重
验收：全部活跃因子均有可审计的 IC 档案；权重来源可追溯到因子验证结果；无经济学说明的因子默认不进入组合
F-03去极值 + 中性化 + 残差检验高
模块 2 · 选层/归残/波动率新增 factor_preprocessor
  • 去极值：按因子分布特性自适应——对称分布用 MAD 截断，偏态分布用分位数（如 1%/99%）截断；禁止对波动率类因子用固定 MAD 一刀切
  • 中性化：行业（申万一级）哑变量 + 对数市值回归，取残差作为中性化因子
  • 残差检验：行业/市值暴露显著性检验（t 值）、残差正态性与异方差检查，残留暴露超阈值即告警
验收：预处理后因子对行业/市值回归 t 值全部不显著；异常值对截面均值影响 < 阈值；检验报告入档
F-04消除幸存者偏差高
模块 2 · 选层逻辑数据层 · 清洗流水线
  • 回测引入已退市/长期停牌标的的历史行情（akshare 退市股接口或本地归档），股票池按「当时时点是否存续」逐期构建
  • 无法完整补齐时，明确量化偏差：计算「存续池回测 vs 全样本池回测」的收益差，输出偏差折价系数并在报告中披露
验收：回测报告声明口径（是否含退市股）；含偏差折价或完整退市数据，二者必居其一
F-05模型失效监控与自动降级高
模块 5 · model_registry新增 model_monitor
  • 内置失效判定规则：滚动窗口 IC 连续 3 个月低于阈值（初始建议 |IC|<0.02，按市场校准）或绩效回撤超限 → 自动标记失效
  • 失效模型：从 active 自动切换至上一活跃版本，并触发告警；禁止失效版本被调用
  • 新版本注册必须「跑赢当前 active」方可激活，否则保留为候选
验收：模拟失效场景（注入低 IC 序列），失效检出并降级时间 < 1 个监控周期；失效版本 0 次被调用
F-06ML 端到端测试与延迟基准高
模块 3/4 · 训练与推理tests/
  • 补齐 tests/test_ml_*：特征一致性、时序切分、标签无泄露、registry 读写、推理兜底等单元与集成测试
  • 新增推理延迟基准：分钟级策略 P99 < 500ms（初始目标 P99 < 200ms），随历史长度增长压测
  • 训练数据注入「未来函数样本」应被守卫拒绝（负向测试）
验收：pytest 全绿；延迟基准报告入档；未来函数负向用例通过
P1关键增强（阶段二，第 3–4 周）6 项 · 提升回测可信度与治理完备度
F-07模型元数据补全与签名中
模块 5 · model_registry
  • 元数据补全：训练数据快照 ID/指纹、python 与关键库版本、模型参数量、常驻绩效（IC/最大回撤）
  • 签名校验：registry 元数据加入 HMAC/密钥签名，加载时校验签名后再校验 checksum，杜绝「连带重算」式篡改
验收：每个 active 模型均可追溯到数据快照与环境版本；签名被篡改时加载被拒
F-08面板数据切分缓冲日历化中
模块 3 · training_pipeline
  • time_series_split 的缓冲从「行数」改为「日历时间」：验证集起点 = 训练集最后时间戳 + horizon 交易日数，适配多标的面板数据
  • 增加跨标的同时间戳分组的确定性归属规则
验收：面板数据下，训练集末尾样本的未来 horizon 收益 0% 落入验证集；负向测试覆盖
F-09训练目标纳入交易成本中
模块 3 · 训练流水线
  • 标签生成支持成本化：forward return 减去双边滑点+佣金（复用 fee_table 参数）
  • 模型选型阶段改用「扣费后指标」（净 IC、扣费后收益、换手惩罚）
验收：训练标签口径与回测撮合层成本参数一致；选型报告同时给出毛/净指标
F-10波动率稳健化与自适应中
模块 2 · 波动率处理
  • 低波因子改用 EWMA 波动率（λ 自适应）或 稳健估计，叠加极端行情区制标记（如滚动收益绝对分位超阈值）
  • 波动率因子输出前经去极值管线，避免极端行情残留污染
验收：股灾/熔断区间内波动率估计相对真实波动偏差收敛；与固定 20 日 std 对比报告入档
F-11因子层可交易性过滤中
模块 1 · 因子引擎
  • 因子计算/选层前统一过滤：当日停牌、成交额低于阈值（初始建议：近 20 日均额 > 500 万元，按样本校准）、一字涨跌停
  • 过滤逻辑入因子管线而非仅靠撮合层兜底，与 ML 特征层共享同一过滤函数
验收：选层结果中 0 个不可交易标的；过滤前后换手率与收益对比报告入档
F-12滚动/扩展窗口交叉验证 + walk-forward中
模块 3 · 训练流水线
  • 接入扩展窗口（或滚动窗口）时序 CV，输出各折 IC 均值/波动，超参选择基于 CV 而非单次留出
  • 加入 walk-forward 逐期重训评估，输出策略在时序上的稳定性曲线
验收：CV 折间 IC 波动报告入档；任何超参调整都须附 CV 证据，禁止单次留出定参
P2进阶优化（阶段三，第 5–6 周+）3 项 · 性能与因子库扩展
F-13因子缓存失效解析修复中
模块 1 · factor_cache
  • L2 文件名解析改为结构化解码（固定分隔或注册表查询），修复因子名含下划线（bollinger_bands 等）导致失效匹配失败的问题
  • 无指纹输入禁止使用「nofp」永久占位，强制要求指纹或缩短 TTL 并显式告警
验收：含下划线因子名在数据更新后 L2 缓存 100% 失效；nofp 场景日志告警可见
F-14增量特征加速与推理缓存中
模块 4 · inference_service
  • compute_incremental 接入指标流式 update 接口，实现 O(1)/O(窗口) 增量而非每 bar 全量重算
  • 推理结果短 TTL 缓存（跨模块重复调用复用），并接入延迟基准回归
验收：相同历史下增量 vs 全量特征结果一致（容差内）；单 bar 推理耗时不随历史长度增长
F-15基本面因子接入（含公告日时点）中
模块 1 · 因子引擎数据层 · financial_data
  • financial_data 表新增公告日（ann_date）字段与数据回填，查询改为「公告日 ≤ 信号日」的严格时点过滤
  • 基本面因子（PE/PB/ROE/市值）在时点化数据上实现并纳入 factor_validator 门槛
验收：任何财报值在公告日之前不可见（负向测试）；因子 IC 档案齐全后方可入组合
05

实施路线图与里程碑

三个阶段串行推进，每阶段结束设验收门（Gate）；Gate 未通过不进入下一阶段。整体建议节奏约 6 周（可按人力并行压缩）。

第 1–2 周

阶段一 · 止血（P0 六项）

F-01 特征一致性修复、F-02 IC/ICIR 校验、F-03 去极值与中性化、F-04 幸存者偏差、F-05 失效监控、F-06 端到端测试。目标：系统从「不可信」变为「可信可测」。

Gate 1（仿真准入）：P0 六项验收全通过 → 允许进入仿真回测与因子档案评审
第 3–4 周

阶段二 · 加固（P1 六项）

F-07 元数据与签名、F-08 面板切分日历化、F-09 成本化标签、F-10 波动率稳健化、F-11 可交易性过滤、F-12 滚动 CV 与 walk-forward。目标：回测结论可信、模型选择有据。

Gate 2（模拟盘准入）：P1 六项验收通过 + 仿真期无重大缺陷 → 开启 3 个月模拟盘（paper）运行
第 5–6 周+

阶段三 · 增强（P2 三项 + 观察）

F-13 缓存失效解析、F-14 增量特征与推理缓存、F-15 基本面因子（公告日时点化）。模拟盘并行运行 3 个月，监控因子 IC 与模型绩效。

Gate 3（实盘试运行准入）：模拟盘 ≥ 3 个月、扣费后绩效达标、失效监控 0 漏报 → 小额实盘试运行（建议 ≤ 10% 计划资金）

实施风险与回退策略
