## 2. v2.0 增量评审：12 项新发现（本版修正依据）

> 外部评审对 v2.0 提出 5 项缺口（**全部成立**，见 §3）。本轮在补齐过程中**又发现 10 项 v2.0 未覆盖的问题**，其中 3 项为阻断级。

### 发现 #1 🔴 `ruleset` 字段**完全空转**（装饰性声明）

**实测证据**：
- `contract.py:176-177`：对 `ruleset` **只校验非空字符串**，不解析、不路由；
- `config/strategy_registry.yaml:200-206` 定义了 `rulesets.daily_close_decision` 的 5 个开关（`static_scan: true` / `cross_sectional` / `require_pit_asof` / `consumption_gate` / **`sanity: false`**）；
- 全仓库 grep `ruleset`：**仅出现在策略类属性声明 + registry 必填字段列表 + contract.py 非空校验**，**没有任何解析/消费代码**；
- `leakage_gate/gate.py:169-199` `_collect_violations()` 遍历 `_GATE_CHECKS.items()`，**逐一无条件执行**，无任何 ruleset 过滤；
- `leakage_gate/__init__.py:24-29` 五道门禁（consumption/contract/static_scan/cross_sectional/sanity）**导入即注册**，`sanity.py:559` 亦然。

**结论**：`rulesets` 映射是**死配置**；`sanity: false` **不生效**，sanity 门禁照常运行。

**对方案的影响**：v2.0 §6.2/§9.2 拟新增 `ruleset: "formula_daily_close_decision"` —— 这会**制造"门禁可分级"的错觉**。**修正**：公式策略**复用既有 `daily_close_decision`**，不新增 ruleset；并在报告中明示 ruleset 当前为声明性字段。

### 发现 #2 🔴 vectorized 路径的运行时防未来断言**自证式、无牙**

**实测证据**：
- `vectorized_engine.py:599-611`：记录信号时 **`data_end=dates[sig_i]` 与 `signal_date=dates[sig_i]` 硬编码相等**；
- `lookahead_guard.py:266-275`：`record_signal` 的校验条件是 `data_end > signal_date` 才违规 —— 二者恒等 ⇒ **恒不违规**；
- `vectorized_engine.py` 全文**无任何 `record_indicator_guard` / `record_indicator` 调用**（该能力仅存在于 `base.py:592`，且全仓库只有 `ma_strategy.py:283/705` 两处调用）；
- `_guard_from_context`（`base.py:555-559`）依赖 `context.extra["lookahead_guard"]`，而 `generate_signals_vectorized(data)` **签名里根本没有 context**；
- `_run_light_guard_check`（`:768-793`）只做**时间戳单调性**校验（`lg.on_bar_close(ts)`），与数据使用无关。

**结论**：vectorized 模式下，运行时守卫**只能验证"T+1 因果平移"这一结构性事实，无法发现策略在指标计算中读取了未来数据**。真正的防线只有静态审计。

**加强证据（子代理复核 + 本轮实测）**：
- **守卫根本未注入策略上下文**：`vectorized_engine.py:267-271` 构造 `StrategyContext(..., extra={"engine_mode": "vectorized"})`，**不含 `lookahead_guard`**；而事件引擎 `engine.py:327-334` 会注入 `extra={"lookahead_guard": self._lookahead_guard}`。⇒ `base.py:555-559` `_guard_from_context()` 返回 `None`，**`record_indicator_guard` / `record_data_access_guard` / `get_signal_data_end` 全部退化为 no-op**（`base.py:607-608`、`:627-628`、`:641-642`）。`mixed_engine.py:275-280` 同一缺陷。（📌 顺带发现：`vectorized_engine.py:196-198` 的私有守卫仅在调用方显式传入时才是全局单例；`engine.py:1074-1081` 会传入，直接构造则不会。）
- **`on_init` 暴露未过滤数据**：`:267-271` 传入的是 `data=self.data`（**未过滤**），而按日期过滤发生在 `:444-448`（逐标的、后置）。⇒ 策略可在 `on_init` 暂存全量数据后在 `generate_signals_vectorized` 内使用；即便 `data=` 注入的帧未经 provider 过滤（`provider.py:472-486` 只覆盖 provider 装载路径）。
- **`get_signal_data_end` 这一"诚实钩子"被绕过**：`base.py:648-654` 明确"禁止自证式常量"，事件引擎 `engine.py:573-592` 会消费它；vectorized 引擎**硬编码** `data_end=dates[sig_i]`（`:609`）。
- **仅对已成交 bar 记录信号**：`:601` `if float(fill_qty[i]) > 0:` ⇒ 策略发出大量未成交信号时，**守卫记录为零**。

**对方案的影响**：v2.0 §8.3/§12 称"静态扫描 + LookaheadGuard 双保险"在 vectorized 主路径上是**过度承诺**。**修正**：§7.2 明确边界，防线重心落到**审计表示层**。

### 发现 #3 🔴 多进程 pickle 约束：**排除运行期 `type()` 动态类 + 排除非原始类型参数**

**实测证据**：
- `parallel.py:279-281`：`ProcessPoolExecutor(max_workers=...)`，**未指定 `mp_context`** ⇒ Windows 走 **spawn**；
- `batch_backtest.py:23`、`param_optimizer.py:20-21` 文档明确假设 **Windows spawn**；
- `BatchTrial`（`batch_backtest.py:101-135`）/`ParamTrial`/`SymbolTrial` 载荷**只携带策略名字符串**，子进程重新 import 模块后从**各自的** `STRATEGY_REGISTRY` 解析类；
- ⇒ **父进程运行期注册的类在子进程不可见**（spawn 下不传播），且 `type()` 生成的 `<locals>` 类无法被 pickle 按 `__module__`+`__qualname__` 还原；
- `check_pickle=True`（`param_optimizer.py:851`、`batch_backtest.py:682`、`incremental_backtest.py:411`）会做**真实 `pickle.dumps/loads` 往返**；若策略 **params 内含 AST/lambda/编译对象**，抛 `PickleCheckError` ⇒ **整轮失败**（非单 trial 失败）。

**结论**：v2.0 §6.3"按公式动态生成子类（`type()`）"**不可用于批量/调参**。

**修正**：改为 **"启动时按注册表物化为真实类文件"**（§9.2）；公式参数**只允许原始类型**（str/int/float/bool/list/dict）。

### 发现 #9 🟡 指标守卫（铁律1）与"收盘决策"存在**口径冲突**，且现有用法自证

**实测证据**：
- `lookahead_guard.py:219-230`：指标校验要求 **`data_end < calc_date`（严格小于）**；
- `ma_strategy.py:704-707`：传入 `calc_date = T`，**不传 `data_end`** ⇒ 走 `base.py:615` 默认 `_causal_data_end()` = **T-1**；
- 而该策略实际使用**截至 T 的收盘价**（`ma_strategy.py:700-712` 用 `close.iloc[-1]`，`df` 已切到 `<= bar_dt`）；
- ⇒ 上报的 `data_end` **比实际使用的数据更早** ⇒ 校验**恒通过**；`base.py:546-548` 自述"读取了未来数据的桩策略必须传实际截止日" —— 即**自证式常量**风险。

**结论**：公式策略若照抄此模式，会**继承一个无牙的守卫**；若诚实上报 `data_end = T`，则被拦截。

**修正**：§10.5 明确 **FormulaBridge 不接入 `record_indicator_guard`**（与 7 个策略中 5 个一致），并**如实记录该语义冲突**为已知限制，不伪装成已受保护。

### 发现 #12 🟠 vectorized 引擎的静默失败面（公式策略高发区）

**实测证据**（部分经子代理独立复核）：

| 现象 | 锚点 | 后果 |
|---|---|---|
| **返回 0/1 标志不报错** | `:484`、`:496`、`:499-505` | 被当作 1 股 ⇒ 一手取整归零 ⇒ **零成交 + 仅 warning** |
| 仅校验 `.size`，不校验 `ndim` | `:472`、`:510`、`:367-369` | `(n,1)` 数组过 `:472` 后在 `:510` 抛错，被 per-symbol `except` **静默吞掉**，该标的被移出组合 |
| NaN 无校验 | `:471-496`、`:536-537` | NaN 静默污染 `position` 与净值 |
| 纯位置对齐 | `:471`、`:510-511` | Series 索引错乱不会被发现，只认长度 |
| **买单被拦不重试、卖单仍全额** | `:515-527`、`:537`、`:561-585` | 涨跌停/停牌拦下买单后，后续目标下调仍发全额卖单 ⇒ `cumsum` 可把 `position` 推成**负值（隐性做空）**；仅买单受 `:561-585` 收缩保护 |
| 轻量守卫返回值被丢弃 | `:753-754` + `models/backtest.py:444-450` | 守卫失败 ⇒ `mark_complete` 抛 `RuntimeError`，`run()` **异常逃逸**而非返回 failed |

**对方案的影响**：FormulaStrategy 的输出必须经过**严格自校验**（`ndim==1`、`len==n`、`np.isfinite().all()`、非负、且**明确是股数而非标志位**），并在适配器层加**持仓下限断言**。这些**不是可选的健壮性优化，而是避免静默失败的必要防线**。⇒ §9.3 增补输出自校验契约，§10.4 增补契约表。

### 4.2 封口 A′：审计表示层（**本方案的技术核心**）

#### 4.2.1 问题

`static_scan.py` 的三道门禁消费的是**策略 Python 源码的 AST**，而公式策略的核心逻辑**不在 Python 里**：

- `static_scan.py:514-536` `analyze_source()` 首行 `ast.parse(source)`，`SyntaxError` ⇒ `ScanResult(hits=[], referenced_columns=set())` —— **fail-open**；
- `static_scan.py:156-160` `extract_referenced_columns()` 同样 `ast.parse`，失败 ⇒ `return set()`；
- `static_scan.py:242-284` `_detect_shift` 只认 `ast.Call` 且 `func.attr == "shift"` 且实参为负常量 ⇒ **只匹配 Python 的 `.shift(-1)`，`REF(C,-1)` 永远不可能命中**；
- `static_scan.py:649-668` `_file_defines_name()` 要求文件内存在 `ClassDef` 且类体有 `name = "<id>"` **字面量赋值**。

⇒ **把公式文本当"伪源码"喂给门禁，会因 `SyntaxError` 变成零命中 + 空列集 = 静默放行**——表面闭合、实际 fail-open。这是最危险的修法。

#### 4.2.2 解决方案：公式 AST → **Python 语义投影**

由 FormulaBridge 把公式 AST 翻译为**语法合法的 Python 审计表示**（`audit_source`），使现有规则**原样复用**：

| 公式元素 | 生成的 Python 投影 | 命中的既有能力 |
|---|---|---|
| `REF(C,-1)` | `df["收盘价"].shift(-1)` | **R01a 阻断**（`_detect_shift`）✅ |
| `REF(C,1)` | `df["收盘价"].shift(1)` | 合法，不命中 ✅ |
| `C` / `收盘价` | `df["收盘价"]` | **R11 列引用提取** ✅ |
| `V` / `成交量` | `df["成交量"]` | R11 ✅ |
| `MA(C,250)` | `df["收盘价"].rolling(250).mean()` | R02/R10 可扩展窗口校验 |
| `#DYNAINFO(...)` 等禁用函数 | 生成保留名调用 `__forbidden_dynainfo__(...)` | 新增一条轻量规则即可 |
| `CROSS(A,B)` | `(A > B) & (A.shift(1) <= B.shift(1))` | 语义透明，可审计 ✅ |

**关键收益**：复用 R01a/R02/R09/R10/R11/R03/R07 **全部现有规则**，而非新写一套"公式专用门禁"——后者会造成两套标准，与"同权受检"目标相悖。

6. **不新增入口脚本**（R-23）；**不安装发行包**（避免环境级变更）。
7. **多进程可复现**：公式策略类必须**可由子进程 import 重建**；公式参数**只允许原始类型**。
8. **不虚假防护**：不得把"自证式守卫"宣传为"运行时防护"（§7.2 边界表）。

## 9. 策略适配器与物化设计

### 9.1 内容寻址身份（解决评审 #3）

```
name = "formula_" + sha256(normalize(formula_text))[:8]
```

- `normalize()`：去注释、统一空白、统一大小写关键字、**保留变量名与顺序**；
- **`name` 即指针**：门禁由 `formula_registry.yaml` 的 `formula` 字段重算哈希即可验证一致性 —— **无需任何 name→source 映射表**，双源漂移**结构性消失**；
- 哈希不匹配 ⇒ 条目与公式文本不一致 ⇒ **直接阻断**（防篡改）。

### 9.2 物化：真实类文件，**不用运行期 `type()`**（解决发现 #3）

**为什么必须物化**：
1. **多进程 spawn**：子进程按 `strategy_name` 字符串重新 import 后从注册表解析类（`batch_backtest.py:162-167`、`param_optimizer.py:190-195`）⇒ **父进程运行期注册不传播**；
2. **pickle 契约**：`type()` 生成的 `<locals>` 类无法按 `__module__`+`__qualname__` 还原；
3. **哈希契约**（§9.1）：类名须与公式内容可验证对应；
4. **门禁可见性**：`_file_defines_name`（`static_scan.py:649-668`）要求源码内**类级字面量 `name = "<id>"`**。

```python
def _validate_target(arr, n: int, symbol: str) -> np.ndarray:
    a = np.asarray(arr, dtype=np.float64)
    if a.ndim != 1:                    raise FormulaOutputError(f"ndim={a.ndim} 必须为 1（{symbol}）")
    if a.size != n:                    raise FormulaOutputError(f"长度 {a.size} != {n}（{symbol}）")
    if not np.isfinite(a).all():       raise FormulaOutputError(f"含 NaN/Inf（{symbol}）")
    if (a < 0).any():                  raise FormulaOutputError(f"含负目标（{symbol}）——引擎存在隐性做空风险")
    if np.all((a == 0) | (a == 1)):    raise FormulaOutputError(f"疑似返回 0/1 标志位，须换算为股数（{symbol}）")
    return a
```

> 为什么必须做：引擎对 **0/1 标志位、NaN、`.ndim`、索引错乱** 均**不报错**，且 per-symbol 异常会被吞（`:367-369`）⇒ 错误会以"零成交 / 净值异常 / 标的神秘消失"的形式**静默**表现。适配器层自校验是**唯一能把这些错误变成显式失败**的位置。

### 9.4 参数约束（解决发现 #3）

| 约束 | 原因 |
|---|---|
| 参数**只允许原始类型**（str/int/float/bool/list/dict/None） | `check_pickle=True` 做真实往返（`param_optimizer.py:851` 等）；AST/lambda/编译对象 ⇒ `PickleCheckError` ⇒ **整轮失败** |
| **不传 AST 对象**，只传公式文本 | 同上；文本可在子进程重新解析 |
| 公式参数化用 **`$param$` 占位符** 文本替换，不用闭包 | 保持参数为原始类型 + 可复现 |

### 10.3 静态预检（三层）

1. **禁用函数黑名单**（`DYNAINFO` 等动态行情、交易指令、绘图类）；
2. **`REF` 负偏移**（`REF(X,-N)`）；
3. **窗口越界**：`MA(C,250)` 在序列头部不足窗口时**必须约定为 NaN / 不产生信号，禁止回填**——这是向量化模式的**头号泄漏源**；
4. **横截面语义拒绝**（新增，依据 §7.3 注 3）：vectorized 引擎逐标的独立调用、无截面数据结构 ⇒ 凡出现跨标的排名/选股/对冲语义的公式，**在 V1 明确拒绝**并提示改用 mixed 引擎（V2 能力），**不得静默按单标的语义执行**。

### 10.4 向量化与时序对齐契约

| 项 | 契约 | 证据 |
|---|---|---|
| 调用粒度 | **每标的调用一次**；**不传 symbol 入参**（策略只能从 `df` 内容判断标的） | `vectorized_engine.py:356-361`、`base.py:326-341` |
| 返回长度 | **必须 == `len(df)`**，否则 `ValueError` | `:472-476` |
| **形状校验** | 仅校验 `.size`，**不校验 `ndim`** ⇒ `(n,1)` 数组可通过 `:472`，随后在 `:510` 抛错并被 `:367-369` 的 per-symbol `except` **静默吞掉**（该标的被移出组合，仅留 ERROR 日志） | `:472`、`:510`、`:367-369` |
| 返回语义 | **目标持仓股数**（非 0/1 信号） | `:460-496` |
| **⚠️ 0/1 陷阱** | 若返回 0/1 标志 ⇒ 被当作"1 股"目标 ⇒ `:496` 一手取整后**全部归零** ⇒ **零成交 + 仅一条 warning**（`:499-505`），**不报错**。公式策略必须自行换算为股数 | `:484`、`:496`、`:499-505` |
| **NaN 校验** | **无**。NaN 会穿过 `floor`/`max` 静默污染 `signed_fill`/`position`/净值 | `:471-496`、`:536-537` |
| **索引对齐** | **纯位置对齐**：`np.asarray` 丢弃 Series 索引；索引错乱/重排**不会被发现**，只有长度有效 | `:471`、`:510-511` |
| 时序 | `position[T] = target[T-1]`，T 日开盘成交 | `:13-14`、`:510-511` |
| 撮合价 | **执行 bar 的开盘价**（`fill_price[is_market] = open_px`），非信号 bar 收盘 ⇒ 无价格泄漏 | `order_matcher.py:549-552` |
| 资金 | 子账户 `initial_capital / n`；超预算按比例收缩（仅收缩买单） | `:350-351`、`:483-492`、`:561-585` |
| **预算不可见** | `sub_initial` **从不传给策略** ⇒ 策略只能用自己的 `capital_base` 自估股数，再由引擎 `:483-492` 收缩 | `:349-351`、`:470` |
| 一手取整 | 引擎 `np.floor(x/lot)*lot` | `:496` |
| 资金模式 | `SUPPORTED_CAPITAL_MODES = ("per_symbol",)`，其他模式抛错 | `:76`、`:163-166` |
| **无截面能力** | 逐标的独立循环 + 日期键累加聚合 ⇒ **策略无法排序/选股/对冲**；`MA(C,5) > REF(MA(C,5),1)` 这类**时序**公式可用，**横截面排名类公式不可用** | `:356-369`、`:799-841` |
| 停牌/涨跌停 | `match_vectorized` 拦截，未成交价置 NaN ⇒ 不产生幽灵持仓 | `:516-527`、`:536-539` |

> **⚠️ 已知引擎缺陷（非本方案引入，但公式策略易触发）**：下单量由**目标差额**驱动而非实际持仓。若买单被涨跌停/停牌拦截，**该差额永不重试**；而后续目标下调仍会发出**全额卖单**（按目标序列计算），经 `:537` 的 `cumsum` 可把 `position` 推成**负值（隐性做空）**。公式策略的信号频繁翻转时风险更高。施工阶段须加**持仓下限断言**作为防御（📌 引擎侧修复不在本方案范围内）。
>
> **⚠️ 另一已知引擎缺陷**：`_run_light_guard_check()` 的返回值被**丢弃**（`：753-754` 调用后无条件 `return True`）。若轻量守卫失败，它会 `mark_failed`，随后 `run()` 在 `:394-395` 调用 `mark_complete()` —— 而 `models/backtest.py:444-450` 规定 failed 为终态、`mark_complete` 抛 `RuntimeError`。⇒ **轻量守卫触雷时 `run()` 以 RuntimeError 逃逸，而非返回 failed 结果**。此外该检查只回放**最后一个标的**的时间戳（`:595` 逐标的覆盖 `self._bar_timestamps`），且只检测严格时钟倒退。
