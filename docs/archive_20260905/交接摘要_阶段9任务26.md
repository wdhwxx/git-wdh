### 4.2 A. BrokerManager 核心能力（manager.py）

- **注册/角色**：`register_broker(broker, alias, role)` 支持 primary/secondary 角色，alias 自动生成，非法角色/重复别名/非BaseBroker 均拦截
- **订单路由**：默认路由主券商，`submit_order(order, broker_id=...)` 指定券商，Order.extra 写入 `broker_id` 路由标记
- **主备 Failover 双路径**：
  - ① 连接断开 → `failover()` 自动切健康备券商
  - ② 主券商拒单 → `_failover_submit` 逐备券商重试 + 成功后自动切主
- **合并视图**：`get_account(merged=True)` 跨券商累加5项资金字段；`get_positions(merged=True)` 按 symbol 聚合数量 + 加权均价，extra 记录 broker_ids 溯源
- **状态持久化**：`get_state / restore_state` 衔接 StateStore；回调透传（order/trade/account 自动注册到全部券商）
- 异常类：BrokerManagerError / BrokerNotFoundError / NoBrokerAvailableError

### 4.3 B. QmtBroker 核心能力（qmt_broker.py）

- **双模式**：`mode="SIM"` 本地完整模拟撮合引擎；`mode="LIVE"` 真实 xtquant SDK 通道统一占位（`_call_qmt_sdk` 明确抛 NotImplementedError，不静默降级）
- **行情驱动撮合**：`update_market_price(symbol, price)` 与 PaperBroker 完全同接口 —— data_feed 收到行情推送统一调用，未来 QMT 真实 `on_tick` 回调同样走此入口
- **成交回报统一入口** `_execute_fill`：与真实 QMT `on_trade` 回报同构 —— 模拟与实盘逻辑一致，接入 SDK 后上层零修改
- **A股规则**：T+1 当日买入冻结、整手100股、涨跌停10%校验、佣金万2.5+最低5元+印花税千1+过户费
- **配置化**：`load_config` 支持 `qmt:` 段（路径/账户/模式/费率/T+1）；`account_id` 多账户预留
- 模块头部完整「真实QMT SDK对接说明」（XtQuantTrader 挂载点 + 接入步骤）

### 4.4 C. PtradeBroker 核心能力（ptrade_broker.py）

- **模拟引擎继承 QmtBroker**（同构共享，避免20KB重复代码，引擎已84项验证）
- **LIVE 分支零重复**：覆写 `_call_qmt_sdk` → 委托 `_call_ptrade_api` 占位
- **Ptrade 策略语义接口**（内部统一收敛到 `submit_order(Order)`）：
  - `order_shares(symbol, amount)` 按股数委托
  - `order_value(symbol, value)` 按金额委托（金额→整手股数换算，向下取整）
  - `order_target_percent(symbol, percent)` 按目标仓位比例委托
- `load_config` 支持 `ptrade:` 段；health_check 独立语义（ptrade_api_ready/ptrade_path）
- 模块头部完整「真实Ptrade API对接说明」（order_shares/order_value/get_position/get_total_assets/subscribe_quote 挂载点）

### 4.5 双券商并行用法示例

```python
from myquant.live.brokers import BrokerManager, QmtBroker, PtradeBroker
from myquant.models.trade import Order, OrderSide, OrderType

mgr = BrokerManager()
mgr.register_broker(QmtBroker(account_id="Q1", mode="SIM", initial_capital=1000000),
                    alias="qmt", role="primary")        # 主券商
mgr.register_broker(PtradeBroker(account_id="P1", mode="SIM", initial_capital=1000000),
                    alias="ptrade", role="secondary")   # 备券商
mgr.connect_all()

# 下单默认路由主券商；指定券商用 broker_id=
mgr.submit_order(Order(symbol="600519.SH", side=OrderSide.BUY,
                       order_type=OrderType.LIMIT, quantity=100, price=1500.0))

# 主券商故障自动切换（连接断开 → failover；拒单 → 逐备重试+切主）
# 合并视图
mgr.get_account(merged=True)      # 跨券商资金累加
mgr.get_positions(merged=True)    # 同 symbol 聚合 + 加权均价

# 状态持久化（衔接 StateStore）
mgr.get_state() / mgr.restore_state(state)
```

### 4.6 防未来函数（铁律4）

- 成交只依据【已发生】行情（`update_market_price` 传入当前价），不预测价格/不假设成交价
- T+1 冻结只累计当日【已成交】买入量，可卖数量 = 持仓 - 当日买入
- 主备切换只依据已发生健康检查 / 已发生拒单结果
- 三个文件均无预测方法、无 `shift(-` 未来引用、无硬编码未来日期

### 4.7 修复的真实缺陷

1. **BrokerManager 拒单 failover bug**：原实现误用连接健康判断（`failover()` 只检查连接状态），主券商拒单但连接健康时不会切换 → 改为 `_failover_submit` 逐备券商重试 + 成功后自动切主
2. **订单状态转换防御**：复用已 REJECTED 订单对象再次 submit 时 `order.submit()` 状态转换失败但无提示 → 增加防御（转换失败则 reject + 明确报错）

### 4.8 为实盘无缝对接预留

- data_feed 行情推送 → `broker.update_market_price(symbol, price)` 统一接口（Paper/Qmt/Ptrade 同构）
- 真实 QMT/Ptrade 回调（on_trade/on_tick）→ `_execute_fill` / `update_market_price` 同构入口
- BrokerManager 主备 Failover 与 StateStore 状态持久化衔接（get_state/restore_state）
- `simnow_broker.py` / `xtp_broker.py` 标记 TODO 后续迭代

## 六、关键设计决策

1. **多券商管理器独立于引擎**：BrokerManager 只依赖 ExecutionInterface，切换券商/主备配置零修改引擎
2. **模拟引擎同构共享**：QmtBroker 提供模拟撮合引擎，PtradeBroker 继承复用（避免重复代码）
3. **行情驱动撮合接口统一**：`update_market_price` 在 Paper/Qmt/Ptrade 三个券商完全同接口，data_feed 零差异对接
4. **成交回报统一入口**：`_execute_fill` 与真实券商 on_trade 回调同构，模拟/实盘逻辑一致
5. **LIVE 占位明确报错**：真实 SDK 未接入前抛 NotImplementedError，不静默降级
6. **防未来函数**：全部基于已发生数据，无预测/无未来引用
