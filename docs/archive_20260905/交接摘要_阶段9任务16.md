### 4.3 create_app 注入式设计（任务16新增）

```python
def create_app(
    title="...", version="...",
    enable_auth=False, enable_rate_limit=False,
    data_quality_explorer=None,   # 注入优先，否则懒加载 DataQualityExplorer()
    metrics_collector=None,       # 注入优先，否则 get_metrics_collector() 全局单例
    alert_manager=None,           # 注入优先，否则 get_alert_manager() 全局单例
) -> FastAPI
```

- **注入优先 + 懒加载全局单例**：测试/实盘环境可注入内存库探查器、独立采集器、隔离告警管理器；未注入自动 fallback
- 三个解析器 `_get_explorer()/_get_collector()/_get_alert_manager()` 闭包内缓存复用
- 端点全部 try/except 兜底：数据源不可用时返回友好 500 错误，不崩溃

### 4.4 关键实现细节

- **兼容端点 /api/data/quality**：v1 占位改为真实总览，保留 DataQualityResponse 结构（symbol/data_type/total_records/valid_records/bad_records/quality_rate/status/bad_types）；quality_grade 在 collector 中为数值（BuiltinMetrics.QUALITY_GRADE_MAP：excellent=0/good=1/fair=2/poor=3/critical=4），路由层做数字→名称映射
- **/api/metrics**：返回 `PlainTextResponse`（Content-Type: text/plain），`to_prometheus(include_timestamp=True)` 附带毫秒时间戳，空指标自动跳过
- **/api/alerts**：`scope` 三档（all→get_history / unacknowledged→get_unacknowledged / escalated→get_escalated）；`level` 字符串→SeverityLevel 枚举转换；返回 `Alert.to_dict()` 完整字段 + `AlertManager.stats`（property）统计

### 4.5 任务16 附带修复（DataQualityExplorer.get_metrics 带标签读取缺陷）

**缺陷**：`get_metrics()` 原用 `collector.get(name)` 无标签读取，而真实 pipeline 用 `collect_data_quality(symbol=..., data_type=...)` 写入**带 symbol/data_type 标签**的指标（实盘常态）→ 无标签读取恒为 None，导致总览/质量报告显示"无数据"。

**修复（web/dashboard.py，向后兼容）**：
```python
m = self._collector.get(name)
if m is None:
    # 无标签读不到时，回退读取该指标名下最新的带标签数据点
    points = self._collector.get_all(name)
    if points:
        m = points[-1]  # dict 保序，最后插入=最新
metrics[key] = m.value if m is not None else None
```
- 无标签指标场景（get() 直接命中）：原逻辑完全一致
- 空数据：仍返回 None（任务15"无数据指标→None"断言零破坏）
- 任务15 的 `_verify_web_data_quality.py`(65) 回归通过

### 4.6 防未来函数（铁律4）
