### 4.3 核心采集方法

**1. collect_from_data_quality_event(event) — 实时事件采集**
- 从DataQualityEvent提取：dirty_type/symbol/data_type/bad_count/total_count/severity
- 更新4个指标：
  - `data_quality_dirty_count`（标签：symbol/data_type/dirty_type）
  - `data_quality_dirty_type_count`（标签：dirty_type）
  - `data_quality_total_records`（标签：symbol/data_type）
  - `data_quality_dirty_ratio`（GAUGE，标签：symbol/data_type）
- **流式支持**：实盘逐条脏数据事件实时更新，无需批量处理
- bad_count=0时不采集dirty_count，只采集total_records

**2. collect_from_pipeline_event(event) — 流水线事件采集**
- 从PipelineCompleteEvent提取完整统计
- 更新：`data_quality_pipeline_runs`（按status标签）
- 失败时额外更新：`data_quality_pipeline_failures`（按error_type标签）
- 成功时调用collect_data_quality()更新全套数据质量指标

**3. collect_from_pipeline_result(pipeline_result) — 增强自动提取**
- 支持多种结果对象结构：
  - V1：stats字典 + cleaned/bad列表 + step_durations + dirty_type_counts + repair_counts
  - V2：stats字典 + step_results（含duration）+ quality_report（含dirty_type_counts）+ repair_results（含repaired）
- 自动提取：total/cleaned/bad/quality_grade/bad_ratio/step_durations/dirty_type_counts/repair_counts
- 失败状态自动采集pipeline_failures和pipeline_runs
- 成功状态调用collect_data_quality()更新全套指标

**4. collect_data_quality() — 增强**
- 新增`repair_counts`参数：修复策略计数（标签：symbol/data_type/repair_strategy）
- 步骤名规范化：`Validate`→`validate`，`Detect Anomalies`→`detect_anomalies`（去空格、小写、空格转下划线）
- 质量等级映射使用`BuiltinMetrics.QUALITY_GRADE_MAP`（excellent=0/good=1/fair=2/poor=3/critical=4）
- 空标签不添加（symbol/data_type为空时不创建标签）
- 更新：total_records/dirty_count/clean_count/dirty_ratio/quality_grade/step_duration/pipeline_duration/dirty_type_count/repair_count

**5. collect_from_alert_manager() — 增强**
- 按级别+分类统计（从告警历史聚合level_category_counts），而非仅按级别
- 采集升级告警数：`system_alerts_escalated`
- 采集未确认告警数：`system_alerts_unacknowledged`
- 回退机制：告警历史不可用时按级别统计

### 4.4 告警回调 + 事件总线自动订阅

**create_alert_callback() — 告警回调（与任务10 AlertManager联动）**
- 创建回调函数，注册到AlertManager.add_alert_callback()
- 告警发送时自动更新：
  - `system_alerts_total`（标签：level/category）
  - 升级告警额外更新：`system_alerts_escalated`
- **使用方式**：`alert_manager.add_alert_callback(metrics_collector.create_alert_callback())`

**subscribe_to_event_bus(bus) — 事件总线自动订阅**
- 订阅2个事件：
  - `DATA_QUALITY_DIRTY` → collect_from_data_quality_event()
  - `DATA_QUALITY_PIPELINE_COMPLETE` → collect_from_pipeline_event()
- 订阅后事件发布时自动采集指标，无需手动调用collect方法
- 支持unsubscribe_from_event_bus()取消订阅
- **为实盘无缝对接**：实盘数据流发布事件时自动更新指标

### 4.5 指标过期检测 + Prometheus导出增强

**get_stale_metrics(max_age_seconds) — 指标过期检测**
- 检测长时间未更新的指标（默认300秒）
- Metric新增属性：`age_seconds`（距上次更新时间）、`is_stale(max_age)`（是否过期）
- **用途**：实盘断连检测、数据源异常监控、指标健康度检查

**to_prometheus(include_timestamp=False) — 增强**
- 可选时间戳：`include_timestamp=True`时数据行末尾附加毫秒时间戳
- 标签值转义：双引号(`"`)、反斜杠(`\`)、换行符(`\n`)正确转义
- NaN/Inf处理：输出`NaN`/`+Inf`/`-Inf`（Prometheus规范）
- 空指标跳过：无数据点的指标不输出HELP/TYPE行
- 整数值不显示小数点（42而非42.000000）

### 4.6 完整自动采集链路

```
实盘数据流 / 清洗流水线
    ↓ 发布事件
EventBus (DataQualityEvent / PipelineCompleteEvent)
    ↓ 自动订阅
MetricsCollector.subscribe_to_event_bus()
    ├─ DataQualityEvent → collect_from_data_quality_event()
    │   ├─ data_quality_dirty_count (symbol/data_type/dirty_type)
    │   ├─ data_quality_dirty_type_count (dirty_type)
    │   ├─ data_quality_total_records (symbol/data_type)
    │   └─ data_quality_dirty_ratio (symbol/data_type)
    └─ PipelineCompleteEvent → collect_from_pipeline_event()
        ├─ data_quality_pipeline_runs (symbol/data_type/status)
        ├─ data_quality_pipeline_failures (失败时)
        └─ collect_data_quality() → 全套数据质量指标

AlertManager 发送告警
    ↓ 回调
MetricsCollector.create_alert_callback()
    ├─ system_alerts_total (level/category)
    └─ system_alerts_escalated (升级告警)

Prometheus / Grafana
    ↓ 抓取
GET /metrics → MetricsCollector.to_prometheus()
```

## 六、关键设计决策

### 1. 实时采集 vs 批量采集
- `collect_from_data_quality_event()` 用于实时流式场景（实盘逐条事件）
- `collect_from_pipeline_result()` 用于批量场景（流水线完成后一次性提取）
- `subscribe_to_event_bus()` 自动订阅，两种场景都覆盖
- 两种方式互补，不冲突

### 2. 指标类型选择
- 计数类（dirty_count/clean_count/total_records/pipeline_runs）→ COUNTER（只增不减）
- 状态类（dirty_ratio/quality_grade/health_status）→ GAUGE（可增可减）
- 耗时类（step_duration/pipeline_duration）→ HISTOGRAM（当前简化为最新值，后续可扩展分桶）

### 3. 标签维度设计
- 数据质量指标：symbol/data_type（标的+数据类型）为基础维度
- 脏数据指标额外加dirty_type标签
- 修复指标额外加repair_strategy标签
- 流水线指标额外加status/error_type标签
- 告警指标按level/category标签
- 标签组合数上限保护（max_metrics_per_name=1000），防止内存泄漏

### 4. 告警回调设计
- 使用`create_alert_callback()`工厂方法创建回调，闭包捕获collector引用
- 回调只更新指标，不阻塞告警发送流程
- 回调异常不影响主流程（try/except包裹）
- 与任务10 AlertManager.add_alert_callback()无缝对接

### 5. 防未来函数（铁律4）
- 所有指标值基于当前已采集的数据计算
- 不使用任何预测模型推断未来指标趋势
- collect_from_data_quality_event只处理已发布的事件，不预加载未来数据
- to_prometheus只导出当前快照，不包含预测值
- 指标时间戳为采集时刻的当前时间
- 源码中无predict/forecast/future关键词

### 6. 为实盘无缝对接预留
- 实时事件采集：实盘数据流发布DataQualityEvent时自动更新指标
- 事件总线自动订阅：subscribe_to_event_bus()一键开启自动采集
- 指标过期检测：get_stale_metrics()检测实盘断连/数据源异常
- Prometheus导出：to_prometheus()直接用于/metrics端点，Prometheus/Grafana监控
- 告警回调联动：AlertManager发送告警时自动更新指标
- 多维度标签：支持symbol/data_type/strategy等实盘维度
