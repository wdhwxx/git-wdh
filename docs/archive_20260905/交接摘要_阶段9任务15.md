## 六、关键设计决策

### 1. 数据逻辑与 UI 分离（可测试性）
- `DataQualityExplorer` 为纯 Python 数据层，不 import streamlit，可独立单元测试
- `_render_data_quality` 只负责渲染，数据全部来自 explorer
- 验证脚本用内存 SQLite + 注入指标采集器，无需启动 streamlit

### 2. 复用既有能力（零重复造轮子）
- 清洗运行/脏数据统计 → 任务13 CleanDataQueries（get_clean_runs/get_run_detail/get_dirty_stats/get_dirty_stats_summary）
- 质量等级/脏类型中文描述 → 任务6 QualityGrade/DirtyDataType + QUALITY_GRADE_DESC_MAP/DIRTY_TYPE_DESC_MAP
- 实时质量指标 → 任务11 MetricsCollector + BuiltinMetrics
- 数据库连接 → get_connection 全局单例

### 3. 注入式设计 + 自动 fallback
- 显式注入优先，未注入自动构建全局单例，缓存复用
- 实盘/测试环境可注入自定义数据库连接，页面零修改

### 4. 独立页面职责分离
- 「🧹 数据质量」专做质量探查（指标/运行/分布/脏数据/详情）
- 「💾 数据」保留数据源管理/数据操作，职责不混

### 5. 防未来函数（铁律4）
- 只展示已发生数据；end_time 严格过滤由任务13保证；无预测关键词

### 6. 为实盘无缝对接预留
- source 区分 offline/live、实时指标、get_latest_run 断点续跑监控、注入式设计
