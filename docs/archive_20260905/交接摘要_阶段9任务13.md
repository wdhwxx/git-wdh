### 2.2 clean_run_meta 清洗运行元信息表

与 PipelineResult / PipelineCompleteEvent 结构对应，存储每次清洗运行的完整元信息，供数据集版本管理与实盘追溯。

| 列 | 类型 | 说明 |
|----|------|------|
| `id` | INTEGER PK | 自增主键 |
| `run_id` | TEXT UNIQUE | 清洗运行ID（唯一） |
| `data_type` / `symbol` | TEXT | 数据类型 / 标的 |
| `status` | TEXT | 运行状态 running/completed/failed |
| `total` / `valid` / `bad` | INTEGER | 原始总数 / 有效数 / 脏数据数 |
| `valid_rate` | REAL | 合格率 |
| `quality_grade` | TEXT | 质量等级（QualityGrade） |
| `severity` | TEXT | 严重级别（SeverityLevel） |
| `steps_executed` | TEXT(JSON) | 已执行步骤 |
| `step_durations` | TEXT(JSON) | 步骤耗时 |
| `total_duration` | REAL | 总耗时（秒） |
| `bad_file` / `report_file` / `processed_file` | TEXT | 输出文件路径 |
| `source` | TEXT | 触发来源 offline/live |
| `started_at` / `finished_at` / `created_at` | TEXT | 起止/创建时间 |
| `error` | TEXT | 错误信息 |

状态常量：`STATUS_RUNNING="running"` / `STATUS_COMPLETED="completed"` / `STATUS_FAILED="failed"`
来源常量：`SOURCE_OFFLINE="offline"` / `SOURCE_LIVE="live"`

### 2.3 dirty_data_stats 脏数据统计表

与 DirtyDataType / DIRTY_TYPE_DESC_MAP 对应，按脏数据类型逐类统计，供质量分析/告警/风控追溯。

| 列 | 类型 | 说明 |
|----|------|------|
| `id` | INTEGER PK | 自增主键 |
| `run_id` | TEXT FK | 关联 clean_run_meta.run_id（外键） |
| `symbol` / `data_type` | TEXT | 标的 / 数据类型 |
| `dirty_type` | TEXT | 脏数据类型（DirtyDataType） |
| `severity` | TEXT | 严重级别（SeverityLevel） |
| `bad_count` | INTEGER | 该类型脏数据条数 |
| `repair_strategy` | TEXT | 修复策略（RepairStrategy） |
| `sample_data` | TEXT(JSON) | 样本数据 |
| `created_at` | TEXT | 创建时间 |

### 2.4 CleanDataQueries 完整 CRUD（queries.py）

**clean_run_meta 组**
| 方法 | 功能 |
|------|------|
| `insert_clean_run()` | 插入一条清洗运行元信息（返回 run_id，run_id 缺省自动生成） |
| `update_clean_run_status()` | 更新清洗运行状态（running→completed/failed，进入终态自动记结束时间） |
| `get_clean_run(run_id)` | 按 run_id 查询单条（steps/耗时自动反序列化） |
| `get_clean_runs()` | 条件查询（symbol/data_type/status/source/时间范围，**end_time 严格过滤防未来函数**，按 started_at 倒序） |
| `get_latest_clean_run()` | 获取最近一次清洗运行（用于增量清洗/实盘断点续跑） |
| `count_clean_runs()` | 统计清洗运行次数 |
| `delete_clean_run(run_id)` | 删除清洗运行记录（级联清理脏数据统计） |
| `insert_clean_run_from_pipeline_result()` | 从 PipelineResult 一键入库（清洗流水线自动关联） |
| `insert_clean_run_from_pipeline_event()` | 从 PipelineCompleteEvent 一键入库（事件总线自动关联） |

**dirty_data_stats 组**
| 方法 | 功能 |
|------|------|
| `insert_dirty_stats()` | 插入/覆盖一条脏数据统计（同 run_id+symbol+data_type+dirty_type 冲突覆盖） |
| `get_dirty_stats()` | 条件查询脏数据统计（run_id/symbol/dirty_type/severity，聚合可选） |
| `get_dirty_stats_summary()` | 脏数据统计汇总（按 dirty_type/severity 聚合，供质量看板/告警） |
| `delete_dirty_stats()` | 删除脏数据统计 |

### 2.5 建表工具（schema.py）

- `create_all_tables(connection)`：建表 + 建索引（含新两表，事务包裹）
- `drop_all_tables(connection)`：删表（**先删子表 dirty_data_stats 再删父表**，外键安全）
- `table_exists(connection, table_name)` / `get_table_count(connection, table_name)`：表检查/计数
- 外键关联：dirty_data_stats.run_id → clean_run_meta.run_id

### 2.6 防未来函数（铁律4）

- `get_clean_runs` 的 end_time 严格过滤：只返回 started_at <= end_time 的记录，绝不返回"未来"运行
- `get_latest_clean_run` 只返回已发生的最近运行
- 无 predict/forecast/future 关键词

### 2.7 为实盘无缝对接预留

- **source 区分 offline/live**：离线批量清洗写 "offline"，实盘会话写 "live"
- **processed_file 路径落库**：清洗产物 processed 文件路径入库，供任务14（数据集版本管理）直接从清洗运行建版本
- **PipelineResult / PipelineCompleteEvent 一键入库**：离线流水线（PipelineResult）与实盘事件流（PipelineCompleteEvent）都能自动写入 clean_run_meta，形成清洗→入库闭环
- **get_latest_clean_run**：增量清洗判断 / 实盘断点续跑

## 四、关键设计决策

1. **两表分离**：clean_run_meta（每次运行的完整元信息）+ dirty_data_stats（脏数据逐类统计），职责清晰，外键关联
2. **JSON 字段**：steps_executed / step_durations / sample_data 用 TEXT(JSON) 存储，读写自动序列化/反序列化
3. **结构对齐**：与 PipelineResult / PipelineCompleteEvent / DirtyDataType 枚举完全对齐，离线流水线与实盘事件流无缝入库
4. **一键入库**：insert_clean_run_from_pipeline_result / insert_clean_run_from_pipeline_event 封装了对象→SQL 转换，调用方零心智
5. **防未来函数**：get_clean_runs 的 end_time 严格过滤
6. **为实盘对接**：source 区分 offline/live；processed_file 落库衔接任务14 数据集版本管理
