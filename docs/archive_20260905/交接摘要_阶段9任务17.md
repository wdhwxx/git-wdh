### 4.3 零破坏保障（关键设计）

1. **泛型 ApiResponse[T]**：`data: Optional[T]`，`ApiResponse` 无参用法默认不约束（阶段8 全部 `response_model=ApiResponse` 向后兼容）
2. **`model_config={"extra": "allow"}`**：FastAPI 用 response_model 序列化时保留任务16 返回的全部额外字段（含表自增 id 列）
3. **字段全部 Optional 宽松类型**：空值/None 不校验失败；`quality_grade` 支持 `Union[int, float, str]` 双形态
4. **`response_model_exclude_none=True`**：排除 None 字段，避免 FastAPI 补默认 `details: null` 等字段破坏任务16 断言（关键：`dirty?include_detail=false` 不再返回 details）

## 六、关键设计决策

### 1. 泛型 ApiResponse[T]（向后兼容）
- `ApiResponse(BaseModel, Generic[T])`，`data: Optional[T]`
- 无参用法 `response_model=ApiResponse` 默认 T 不约束，阶段8 全部端点零破坏
- 详细端点用 `ApiResponse[QualityOverviewData]` 等参数化，OpenAPI 文档完整

### 2. extra="allow" + response_model_exclude_none（零破坏双保险）
- extra="allow" 保证额外字段（含表 id 列）不丢弃
- exclude_none 保证 None 字段不补默认值（关键：dirty include_detail=false 不返回 details）
- 两个机制配合，任务16 的 83 项硬门槛守住

### 3. 字段全部 Optional 宽松类型
- 空值/None 不校验失败，适配数据源空库场景
- quality_grade 双形态（collector 数值 1.0 / 字符串 good）兼容

### 4. 复用既有能力（零重复造轮子）
- 字段对齐任务13 clean_run_meta 表 / 任务10 Alert.to_dict / AlertManager.stats
- 复用 BuiltinMetrics.QUALITY_GRADE_MAP（quality_grade 数值→名称映射）
- 复用任务16 DataQualityExplorer 数据逻辑（模型只做类型化包装，不重复查询）

### 5. 防未来函数（铁律4）
- 只承载已发生事实；无预测方法/字段；无硬编码未来日期

### 6. 为实盘无缝对接预留
- source 区分 offline/live、告警 summary 承载实盘统计、泛型统一包装、OpenAPI 文档完整
