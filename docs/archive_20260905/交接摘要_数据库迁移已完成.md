## 三、各子项详情

### A项：Alembic 初始化框架

**文件清单：**
- `alembic.ini`（项目根目录）— 主配置，script_location=myquant/database/migrations
- `myquant/database/migrations/env.py` — 环境配置
- `myquant/database/migrations/script.py.mako` — 迁移脚本模板
- `myquant/database/migrations/versions/__init__.py` — 版本目录
- `pyproject.toml` — 添加 alembic>=1.13.0 依赖

**env.py 核心能力：**
- 自动探测项目根目录（向上查找 pyproject.toml）
- SQLite 相对路径转绝对路径，确保数据库文件位置正确
- 支持环境变量 QUANT_DB_URL 覆盖（实盘/测试切换数据库）
- offline 模式（生成SQL脚本不连接数据库）
- online 模式（连接数据库执行迁移，每个迁移独立事务）
- render_as_batch=True（SQLite 不支持部分 ALTER，用 batch 模式）

**注意：** alembic.ini 用英文注释。Alembic 用 locale 编码读取 ini 文件，中文注释在 Windows GBK 环境会 UnicodeDecodeError。Python 文件（env.py、迁移脚本）正常使用中文。

### C项：增量迁移 0002 + stamp 兼容

**0002 内容：** 新增 `idx_market_symbol_period_date(symbol, period, trade_date)` 复合索引。
- 背景：实盘多周期（daily/minute/tick）混合存储时，按「标的+周期+日期范围」查询是最常用模式
- 原有索引 idx_market_symbol_date(symbol, trade_date) 不包含 period
- 不删除原有索引，保持向后兼容

**stamp 兼容（已有数据库）：**
- 场景：数据库已通过旧 MigrationManager 或 create_all_tables() 建表
- 操作：`alembic stamp head` 标记当前为最新版本，不执行任何迁移
- 验证：旧方式建表8张 → stamp head → 版本0002 → 表数量不变（不重复建表）→ 再 upgrade head 无操作

**增量升级/回滚验证：**
- 0001 → upgrade 0002 → 复合索引出现，版本0002
- 0002 → downgrade 0001 → 复合索引删除，版本0001
- 反复切换无异常

### D项：中文入口 + 统一验证

**中文入口：scripts/数据库迁移.py**

| 子命令 | 功能 |
|--------|------|
| `upgrade [--revision]` | 升级到最新/指定版本 |
| `downgrade --revision` | 回滚到指定版本（-1=上一个，base=清空） |
| `current` | 查看当前版本 |
| `history` | 查看迁移历史链 |
| `stamp --revision` | 标记版本（不执行迁移，已有库用） |
| `check` | 检查数据库状态（表数量/记录数/索引/版本/是否最新） |
| `init` | 初始化新数据库（等价于 upgrade head） |

支持 `--db` 参数指定数据库路径，支持 `QUANT_DB_URL` 环境变量。

## 四、与现有系统的关系

**自研 MigrationManager（myquant/database/migrations/__init__.py）：**
- 保留不动，作为兼容层
- `scripts/数据库初始化.py` 和 `tests/_verify_database_schema.py` 继续使用它
- 未来新表结构变更统一走 Alembic，不再新增 MigrationManager 版本

**Alembic 为主迁移框架：**
- 新数据库初始化：`python scripts/数据库迁移.py init`
- 表结构变更：编写新版本迁移脚本 → `upgrade head`
- 生产环境升级前：`check` 检查状态 → `upgrade head`
- 回滚：`downgrade -1` 或指定版本

## 五、为实盘无缝对接的准备

1. **不停库升级**：Alembic 增量迁移在事务中执行，SQLite WAL 模式下支持并发读写
2. **多数据库支持**：`--db` 参数和 `QUANT_DB_URL` 环境变量，可分别管理回测库和实盘库
3. **版本可追溯**：alembic_version 表记录当前版本，`history` 命令查看完整迁移链
4. **回滚能力**：每个迁移都有 downgrade，出问题可快速回退
5. **已有库兼容**：stamp 机制让旧库无缝接入，无需重建
