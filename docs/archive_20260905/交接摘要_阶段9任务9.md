### 4.2 health_check.py 核心内容

**HealthStatus 枚举**：HEALTHY / DEGRADED / UNHEALTHY，支持比较运算和 is_healthy/is_critical 属性

**HealthCheckResult 数据类**：name/status/message/details/duration/timestamp/check_id，to_dict()/summary()

**内置检查项函数**：
- `check_disk_space()` — 磁盘空间使用率（Windows/Linux兼容，warning/critical阈值）
- `check_event_bus_status()` — 事件总线运行状态（事件数/处理器数/错误数）
- `check_process_uptime()` — 进程存活（PID/Python版本/运行时间，psutil可选）

**HealthChecker 管理器**：
- `register_default_checks()` — 注册3个内置检查项
- `add_check(name, func, timeout, critical, description)` — 动态注册自定义检查
- `run_check(name)` / `run_all()` — 执行检查
- `get_summary()` — 汇总状态（overall_status/healthy_count/degraded_count/unhealthy_count）
- 关键检查项（critical=True）失败直接导致总体状态 UNHEALTHY
- 状态历史记录（get_status_history）
- 全局单例 `get_health_checker()`

### 4.3 alerting.py 核心内容

**Alert 数据类**：level(SeverityLevel)/message/source/category/details/deduplication_key/timestamp/alert_id/acknowledged/resolved，is_critical属性，to_dict()/summary()

**AlertChannel 抽象基类**：
- `send(alert)` 抽象方法
- `can_send(alert)` — 按 min_level 和 enabled 过滤
- 通道统计：sent_count/error_count/last_error

**内置通道实现**：
- `ConsoleAlertChannel` — 控制台输出（带ANSI颜色，可关闭）
- `LogAlertChannel` — 日志记录（按级别调用info/warning/error/critical）

**预留通道骨架**（TODO，为实盘对接预留）：
- `EmailAlertChannel` — SMTP邮件（配置项已定义，send记录日志）
- `WebhookAlertChannel` — Webhook（飞书/钉钉/企业微信，配置项已定义）

**AlertManager 管理器**：
- `add_channel(channel)` / `remove_channel(name)` / `list_channels()`
- `send_alert(alert, dedup_enabled)` — 多通道分发 + 去重
- `alert(level, message, ...)` — 便捷创建并发送
- 告警去重（dedup_window_seconds，相同deduplication_key窗口内只发一次）
- 静默模式（silence/unsilence/is_silenced，维护模式）
- 告警历史（get_history按级别/分类过滤，get_unacknowledged）
- 告警确认/解决（acknowledge/resolve）
- **为任务10预留**：`subscribe_to_event_bus(bus)` 订阅数据质量事件，`handle_data_quality_event()` / `handle_quality_alert_event()` / `handle_pipeline_complete_event()` 事件处理方法（骨架已实现，任务10完善规则）
- 全局单例 `get_alert_manager()`（默认注册Console+Log通道）

### 4.4 metrics_collector.py 核心内容

**MetricType 枚举**：COUNTER（只增不减）/ GAUGE（可增可减）/ HISTOGRAM（直方图，当前简化），is_monotonic属性

**Metric 数据类**：name/type/value/labels/help/timestamp/metric_id，labels_key/full_name属性，to_dict()

**BuiltinMetrics 常量**：预定义指标名称
- 事件总线：event_bus_total_events / event_bus_sync_handlers / event_bus_async_handlers / event_bus_handler_errors / event_bus_handler_calls
- 数据质量（为任务11预留）：data_quality_dirty_count / data_quality_clean_count / data_quality_dirty_ratio / data_quality_quality_grade / data_quality_step_duration_seconds / data_quality_pipeline_duration_seconds / data_quality_dirty_type_count
- 系统：system_health_status / system_alerts_total / system_alerts_unacknowledged
- 实盘（为后续预留）：live_positions_count / live_orders_total / live_pnl_total

**MetricsCollector 采集器**：
- `register(name, type, help, label_names)` / `register_builtin_metrics()`
- `set_gauge(name, value, labels)` — 设置仪表盘值
- `inc_counter(name, amount, labels)` — 增加计数器（负值被忽略）
- `observe_histogram(name, value, labels)` — 观察直方图
- `get(name, labels)` / `get_value(name, labels, default)` / `get_all(name)`
- `to_prometheus()` — 导出Prometheus文本格式（HELP/TYPE/数据点行）
- `to_dict()` — 导出字典格式（JSON友好）
- `reset(name)` — 重置指标
- 自动注册（未注册的指标首次set时自动注册为GAUGE）
- 标签组合数上限保护（防止内存泄漏）

**采集方法**：
- `collect_from_event_bus(bus)` — 从事件总线采集（事件数/处理器数/错误数）
- `collect_data_quality(...)` — 采集数据质量指标（为任务11预留骨架，支持symbol/data_type/total/clean/bad/quality_grade/step_durations/dirty_type_counts）
- `collect_from_pipeline_result(pipeline_result)` — 从PipelineResult对象采集（便捷方法）
- `collect_from_health_checker(checker)` — 从健康检查器采集系统健康状态
- `collect_from_alert_manager(alert_manager)` — 从告警管理器采集告警统计
- 全局单例 `get_metrics_collector()`（默认注册内置指标）

## 六、关键设计决策

### 1. 兼容性策略
- monitoring 是新增独立模块，不修改任何已有文件
- 全局单例模式与项目其他模块一致（get_health_checker/get_alert_manager/get_metrics_collector）
- 预留通道（Email/Webhook）采用骨架模式，配置项已定义，send方法记录日志不实际发送

### 2. 防未来函数（铁律4）
- 健康检查只读取当前时刻的系统状态（磁盘/进程/事件总线）
- 告警只响应已经发生的事件，不使用任何预测模型
- 指标只记录当前和历史已发生的数据，时间戳为采集时刻
- 所有模块无predict/forecast/future方法

### 3. 为实盘无缝对接预留
- HealthChecker.add_check() 可动态注册数据源/券商/行情连接检查
- AlertManager 多通道架构（Console/Log/Email/Webhook），实盘可配置邮件+钉钉告警
- AlertManager.subscribe_to_event_bus() 已预留，实盘数据流发布的DataQualityEvent自动触发告警
- MetricsCollector.to_prometheus() 可直接用于/metrics端点，Prometheus/Grafana监控
- MetricsCollector.collect_data_quality() 支持流式逐条更新计数器

### 4. 入口脚本中文名
- `scripts/数据清洗.py`
- `scripts/run_回测入口.py`
- `scripts/运行API.py`
