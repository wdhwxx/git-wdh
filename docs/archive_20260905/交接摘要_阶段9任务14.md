### 4.2 版本元数据结构 DatasetVersion

| 字段 | 类型 | 说明 |
|------|------|------|
| `version` | int | 版本号（同一数据集单调递增） |
| `symbol` / `data_type` / `period` / `adjust` | str | 标的 / 数据类型(bar/tick) / 周期 / 复权 |
| `created_at` | str | 版本创建时间（UTC） |
| `source` | str | 数据来源 offline/live（实盘预留） |
| `record_count` | int | 快照数据条数 |
| `total` / `valid` / `bad` | int | 清洗统计（原始/有效/脏） |
| `valid_rate` / `quality_grade` | float/str | 合格率 / 质量等级 |
| `checksum` | str | 数据快照SHA256（完整性校验） |
| `data_range` | dict | 数据时间范围 {start_date, end_date} |
| `clean_run_id` | str\|None | 关联任务13 clean_run_meta.run_id |
| `parent_version` | int\|None | 派生链上一版本（实盘增量版本） |
| `description` / `metadata` | str/dict | 版本说明 / 扩展元数据 |

### 4.3 版本存储布局（与阶段2 processed 完全兼容）

```
datasets/processed/{symbol}/
    {data_type}_{period}{adjust}_{timestamp}.csv   # 阶段2原有时间戳文件（保持不动）
    versions/
        index.json      # 版本索引（全量版本元数据 + head 指针 + last_rollback）
        v1/ data.csv + metadata.json               # 版本快照 + 元数据
        v2/ data.csv + metadata.json
        ...
```

### 4.4 方法清单（12个）

| 方法 | 功能 |
|------|------|
| `create_dataset_version()` | 创建新版本（版本号自动取 max+1、写快照+元数据+索引、SHA256校验、线程锁+文件锁） |
| `create_dataset_version_from_clean_run()` | **衔接任务13**：从 clean_run_meta.run_id 读取清洗元信息创建版本（total/valid/bad/quality_grade/source 自动带入） |
| `list_dataset_versions()` | 列出版本（按版本号降序，可 data_type 过滤） |
| `get_dataset_version()` / `get_latest_dataset_version()` | 查询指定/最新版本元数据 |
| `load_dataset_version()` | 加载版本数据（**checksum 完整性校验 + end_date 严格过滤防未来函数** + 按日期升序） |
| `rollback_dataset_version()` | 回滚到指定版本（写回 processed 当前文件 + index 记录回滚事件，load_processed_data 自动读到回滚数据） |
| `delete_dataset_version()` | 删除版本（head 自动回退到前一个版本） |
| `verify_dataset_version()` | 版本数据完整性校验（checksum） |
| `get_dataset_versions_metadata()` | 版本汇总信息 |

### 4.5 异常体系

| 异常 | 触发场景 |
|------|----------|
| `DatasetVersionError` | 版本管理基础异常 |
| `DatasetVersionNotFoundError` | 版本不存在 / 版本数据文件缺失 / data_type 不匹配 |
| `DataVersionIntegrityError` | 数据完整性校验失败（checksum 不匹配，防篡改） |

### 4.6 为实盘无缝对接预留

- **source 区分 offline/live**：实盘实时增量创建版本时标记 source="live"，离线批量标记 "offline"
- **parent_version 派生链**：实盘增量版本基于上一版本（v_n → v_{n+1}），版本历史可追溯
- **并发安全**：版本创建用线程锁 + 跨进程文件锁（`file_utils.file_lock`），实盘多进程安全
- **回滚接口**：数据异常时一键回滚到健康版本，写回 processed 后下游（回测/实盘 data_feed）无缝衔接
- **clean_run_meta 闭环**：清洗运行（任务13）→ 版本快照（任务14）→ 数据质量事件/告警/风控（任务8-12），全链路可追溯

### 4.7 防未来函数（铁律4）

- 版本创建**只基于传入的已发生数据**（records），不引入未来数据
- `load_dataset_version` 的 **end_date 严格过滤**：end_date 之后的数据绝对不返回
- 回滚**只使用已保存的历史版本快照**
- 数据范围（data_range）从当前记录中提取 min/max，不预测未来
- 源码扫描：manager.py 无 predict/forecast/future 关键词（`from __future__` 语言特性除外）

## 六、关键设计决策

### 1. 版本号全局递增 + data_type 独立 head
- 同一 symbol 的版本号单调递增（删除版本不重用版本号，保证历史可追溯）
- 每个 data_type（bar/tick）独立维护 head 指针；删除 head 版本自动回退前一个版本

### 2. 快照 + 索引双写，checksum 防篡改
- 每版本写 `data.csv`（数据快照）+ `metadata.json`（完整元数据）+ 更新 `index.json`（索引）
- 数据文件 SHA256 写入 checksum，加载/校验时比对，防止数据被篡改或损坏

### 3. 与阶段2 processed 完全兼容
- 版本管理新增 `versions/` 子目录，**不改动**阶段2的时间戳文件与 `load_processed_data`
- 回滚写回 processed 当前目录（时间戳格式 + `_rollback_v{N}` 标记），`load_processed_data`（glob 取最新）自动读到回滚数据，下游零修改

### 4. 与任务13 clean_run_meta 闭环
- `create_dataset_version_from_clean_run()` 从 clean_run_meta 读取清洗统计（total/valid/bad/quality_grade/source）自动带入版本元数据
- 清洗运行（任务13）→ 版本快照（任务14）→ 数据质量事件/告警/风控（任务8-12），全链路可追溯

### 5. 防未来函数（铁律4）
- 版本创建只用传入的已发生数据
- load 按 end_date 严格过滤，未来数据绝对不返回
- 回滚只用已保存历史快照
- 无 predict/forecast/future 关键词

### 6. 为实盘无缝对接预留
- source 区分 offline/live、parent_version 派生链、文件锁并发安全、回滚接口供数据异常恢复
