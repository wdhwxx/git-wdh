### 4.1 文件清单

| `tests/_verify_event_bus.py` | 验证脚本（243项验证全通过） |

### 4.2 核心新增内容

**1. 数据质量事件类型（EventType 新增4个）**
- `DATA_QUALITY_DIRTY = "data_quality.dirty"` — 发现脏数据
- `DATA_QUALITY_PIPELINE_COMPLETE = "data_quality.pipeline_complete"` — 清洗流水线完成
- `DATA_QUALITY_ALERT = "data_quality.alert"` — 数据质量告警
- `DATA_QUALITY_CRITICAL = "data_quality.critical"` — 严重数据质量问题

**2. 三个强类型事件类（均继承 Event dataclass）**

| 事件类 | 用途 | 关键字段 |
|--------|------|----------|
| `DataQualityEvent` | 脏数据发现事件 | dirty_type, symbol, data_type, severity, errors, record, quality_grade, bad_count, total_count, repair_strategy, source_step |
| `PipelineCompleteEvent` | 流水线完成事件 | symbol, data_type, status, cleaned_count, bad_count, total_count, quality_grade, bad_ratio, duration, steps_executed, bad_file, report_file |
| `QualityAlertEvent` | 质量告警事件 | alert_level, message, symbol, data_type, quality_grade, bad_ratio, threshold, dirty_type, deduplication_key |

**3. EventFilter 事件过滤器**
- 按 symbol / data_type / min_severity / event_type 过滤（AND关系）
- 支持 DataQualityEvent 的 severity 和 QualityAlertEvent 的 alert_level
- 订阅时传入 `event_filter` 参数，只接收匹配事件

**4. HandlerStats 处理器统计**
- call_count / error_count / last_error / last_called / total_duration
- 派生属性：avg_duration / error_rate
- `bus.get_handler_stats(handler_id)` / `bus.reset_handler_stats()`

**5. 告警去重**
- `EventBus(dedup_window_seconds=60)` 配置去重时间窗口
- `publish_quality_alert(deduplication_key="...")` 相同 key 在窗口内只发布一次
- `clear_dedup_cache()` 清除缓存

**6. 类型化发布方法**
- `publish_data_quality(...)` — 发布脏数据事件
- `publish_pipeline_complete(...)` — 发布流水线完成事件（bad_ratio自动计算）
- `publish_quality_alert(...)` — 发布质量告警（支持去重）
- `publish_critical(...)` — 发布严重事件（priority=100，自动生成dedup_key）

**7. 便捷订阅方法**
- `subscribe_data_quality(handler, symbol=None, data_type=None, min_severity=None)`
- `subscribe_pipeline_complete(handler, symbol=None)`
- `subscribe_quality_alert(handler, min_level=None)`

**8. wait_for_event 阻塞等待**
- `bus.wait_for_event(event_type, timeout=30.0, event_filter=None)`
- 线程安全，超时返回 None

**9. DataQualityEventPublisher 便捷发布器**
- 封装 EventBus，提供面向清洗流水线的简洁 API
- `publish_dirty()` / `pipeline_complete()` / `alert()` / `critical()`
- 支持 enable/disable 开关
- 可注入到 CleanPipeline、DataFeed 等组件

### 4.3 向后兼容性
- 原有 EventBus API（subscribe/unsubscribe/publish/once/emit/history/stats）完全保留
- 原有 Event 类不变，新增的三个事件类继承 Event
- `get_event_bus()` 全局单例不变
- 新增 `reset_event_bus()` 用于测试
- 所有现有验证脚本（exceptions/pipeline/constants等）继续通过

### 4.4 为后续任务预留的接口
- **任务9-11（monitoring）**：`subscribe_quality_alert()` 接收告警事件，`get_handler_stats()` 采集指标
- **任务12（risk_manager）**：`subscribe_quality_alert(min_level="critical")` 接收严重事件，触发策略暂停
- **CleanPipeline 集成**：`DataQualityEventPublisher` 可直接注入流水线，在 `on_pipeline_complete` 钩子中发布事件
- **实盘数据流**：`publish_data_quality()` 支持逐条发布流式脏数据事件

## 六、关键设计决策

### 1. 兼容性策略
- 所有重构都保留旧函数（如 `clean_bar_records()` / `run_clean_pipeline()`）
- 新类与旧函数内部复用同一套校验逻辑，结果100%一致
- 配置格式不变，`config/data_clean.example.yaml` 无需修改
- event_bus.py 原有 API 完全保留，新增功能均为增量

### 2. 防未来函数（铁律4）
- 所有清洗/回测/实盘模块严格禁用未来函数
- 价格跳变只比较当前与前一条记录
- 信号在T日生成，T+1才能成交
- 枚举/异常/事件类是纯定义，不包含任何数据或预测逻辑
- event_bus 是纯基础设施，事件 timestamp 为发布时当前时间

### 3. 为实盘无缝对接预留
- 流式清洗：`BarCleaner.clean_single()` / `TickCleaner.clean_single()` 逐条处理
- 事件联动：DataQualityEvent → 监控告警 → 风控暂停（任务8已完成事件基础设施）
- 规则热更新：`CleanRuleLibrary.reload_rule_library()` 配置热重载
- 状态持久化：任务23将实现崩溃恢复
- DataQualityEventPublisher 可直接注入实盘 DataFeed

### 4. 入口脚本中文名
- `scripts/数据清洗.py`
- `scripts/run_回测入口.py`（需确认是否已改名）
- `scripts/运行API.py`
