## 一、背景与核查结论

### 1.1 一句话结论

**项目里不存在"回测真实性门禁"这个实体。** 存在的是 `leakage_gate`（策略**源码**防泄漏合规门禁）与 `live_safety_gate`（实盘运维安全验收）。真实性约束（涨跌停、停牌、流动性、T+1 持仓冻结、费用与滑点口径、复权、样本口径、数据质量）全部以**引擎内联行为 + 配置声明 + 文档承诺**三种形态存在，**没有任何一项**受"唯一出口断言 + 违规阻断 + 审计留痕 + 证据产物 + fail-closed"这套门禁范式的保护。

**三轮核查共同确认的独立命中项**（可信度最高，施工排序最前）：`leakage_report` 幽灵产物（生产零调用）、豁免流内存态无持久化、运行时 as-of 校验孤儿（R03/R07 仅警告）、`decision_time` 传运行当天、铁律1/2 依赖策略自觉上报、**`context.data` 全量暴露（v2.2 第三轮新增）**、**`severity` 语义失效（v2.2 第三轮新增）**。

### 1.2 四条支撑判断

1. **`leakage_gate` 装配链真实、主入口硬阻断，但检测能力已被掏空。**
   列级台账 14 列 `severity` 全部为"通过"，导致 `blocked=∅` → 消费侧 R11 主判据与特征白名单门禁**在结构上永远返回空**。这道门禁能因"配置缺失"变红，**不能因"存在泄漏"变红**。且 5 个注册检查**全部是对 `myquant/strategies/*.py` 的 AST 静态扫描**，回测运行期**零约束**。

2. **真实性约束呈三种失效形态。**
   - 默认路径生效但**不可控**：mixed 引擎的涨跌停/停牌由 `OrderMatcher()` 硬编码默认值生效，配置文件管不到；
   - 默认路径**不生效且配置写了也没用**：event 涨跌停/停牌、流动性占比、T+1 持仓冻结、`adjust_strict`、幸存者偏差折价；
   - **只存在于文档**：`leakage_report.json` 产物、数据快照 pin、回测期数据质量门禁。

3. **[v2.2 新增·最重要] 回测的因果性在结构上没有被保证，而是被"委托"给每个策略作者。**
   三个引擎都把**整个回测窗口**的 DataFrame 塞进 `context.data`（event engine.py:327-337 / mixed mixed_engine.py:275-281 / vectorized vectorized_engine.py:267-271），而 `StrategyContext.get_data()` 不做任何时间截断（base.py:178-179）。策略若忘记自行截断，即可读取未来 bar，**现有任何防线都无法发现**。这是"回测真实性"里对收益影响最大的一项，且**它无法靠"加门禁"解决，只能靠结构性切片解决**（P0-07）。

4. **配置→行为链断裂，且默认值一律偏向"更宽松/更便宜"。**
   任何配置疏忽、键名拼写错误、参数未透传，都朝"回测更好看"的方向漂移。这是本项目最危险的设计属性。

### 1.3 一句话战略判断

项目在"**数据如何被消费**"这一层（复权 as_of、财务 `eff_disclosure_date`、股本科 PIT、清洗期 OHLC 阻断、指纹缓存）做得扎实且可验证，工程质量明显高于一般个人量化项目。问题高度集中在"**回测样本是什么**""**约束是否真的在跑**""**策略是否真的只看过去**"这三层。**不需要重写**，需要把已有严谨性从"数据消费层"平移到"回测真实性层"——补上缺失的门禁对象（P0-01）+ 补上缺失的**因果切片**（P0-07），再把散落的真实性约束挂上去。

**[v2.1 补充·红队复盘定位]** 对 v2.0 做方案级红队复盘后确认：诊断结论全部成立，但作为"可直接施工的基线"存在分支未闭合、状态机不闭合、文件级资源冲突未排期、接口方案未经代码核实四类缺陷。

**[v2.2 补充·第三轮复核定位]** 对 v2.1 的**新增设计假设**逐条回到代码验证后确认：诊断部分（§一~§三、附录 A）全部成立；v2.1 新增的闭合工作（P0-00、§4.5、§4.6、§4.7、§5.4、§6.1）方向正确；但新增设计中 **4 项与代码事实冲突**（G1~G4），另有 17 项覆盖缺口。本版**方向不变、骨架不变**，为纯增量修正。

### 2.3 `leakage_gate` 被掏空的检测能力（决定性）

**缺陷 A｜台账无阻断列 → R11 / 特征白名单恒真**

`config/data_time_semantics.yaml` 全部 14 列 `severity` 均为"通过"（第 20/25/30/35/41/46/51/56/61/68/73/78/83/91 行），`severity: 阻断` **零匹配**。

判据在 myquant/leakage_gate/consumption.py:151：

```python
return sorted((set(declared) | actual) & blocked)   # blocked = 台账 severity=阻断 的列
```

`blocked = _blocked_columns(ledger)`（consumption.py:192-200）取到**空集** → 交集恒空 → `check_consumption` 永不产违规。同理 myquant/leakage_gate/sanity.py:345-347：`blocked` 为空即 `return []`。

**后果**：R11/RL-13「引用阻断档数据列即出口报红」这一被反复写入文档与验收项的能力，**当前处于完全空转**。门禁剩下的唯一变红路径是"台账/注册表/配置缺失"。

**[v2.0 修正·R11 空转可见性]** 即便"当前确无阻断列"是真实状态，"R11 恒空转"也必须**显式可见**（台账头部声明 + 可见提示），不得静默。**[v2.2 修正]** 提示的实现方式受缺陷 C 约束——**不得以 `Violation` 形式产出**，落点见 P0-02。

**缺陷 B｜5 个注册检查全是源码 AST 扫描，回测运行期零约束**

| 注册名 | 检查对象 | 运行时数据？ |
|---|---|---|
| `contract` | config/strategy_registry.yaml 声明完整性 | ❌ |
| `consumption` | myquant/strategies/*.py 源码文本 | ❌ |
| `static_scan` | 同上 | ❌ |
| `cross_sectional` | 同上（找 `panel.rank()` 类命名） | ❌ 且只产 `severity="警告"` |
| `feature_whitelist` | myquant/ml/features.py 的白名单字面量 | ❌ |

能真正做运行时 as-of 判定的 `validate_asof` / `validate_cross_sectional_panel`（myquant/leakage_gate/cross_sectional.py:44-163）是**孤儿**——生产调用点为零（仅 tests/leakage_gate/test_static_scan.py）。源码注释自认："本门禁不持有运行数据"（cross_sectional.py:229）。

**缺陷 C｜[v2.2 新增·致命] `severity` 在出口断言中从不被消费 —— "警告档不阻断"命题为假**

`assert_all_gates_pass` 全段**没有任何 severity 判断**（gate.py:277-289 逐行核实）：

```python
# myquant/leakage_gate/gate.py:277-289
violations = _collect_violations(strategy_id, decision_time)
if not violations:
    return
from myquant.leakage_gate.exemption import suppress_violations
violations = suppress_violations(violations)
if not violations:
    return
config = get_config()
if config.audit_violations:
    _append_audit(violations)
if config.enabled:
    raise LeakageGateError(violations)      # ← 任何非空 violations 都抛，不看 severity
```

两端行为对照：
- `static_scan` **自己预过滤**了阻断档：`blocking_hits = [h for h in hits if h.severity == "阻断"]`（static_scan.py:131-133）；
- `cross_sectional` **没有过滤**，直接把 `severity="警告"` 的 `Violation` 返回（cross_sectional.py:259-267）→ 进入出口断言 → **照样抛 `LeakageGateError`**。

**误读根源（务必记入施工交底）**：`gate.py` 的 docstring 用"警告档"指代 `GateConfig.enabled=False` 这个**全局审计开关**（"enabled=False 仅审计（警告档）不阻断"，gate.py:267-268；"门禁违规（disabled 档，仅审计不阻断）"，gate.py:290-291），**而不是** `Violation.severity == "警告"`。v2.1 把二者混为一谈，据此推出的三条结论全部不成立：

| v2.1 的结论 | 实际 |
|---|---|
| §1.3「该层存在'警告档不阻断'缺口」 | **反了**：警告档违规**会**硬阻断出口 |
| P0-02 方案 B「让 `check_consumption` 在 `blocked=∅` 时产出 `severity="警告"` 的可见提示」 | **会硬阻断每一次引擎创建**（因为提示也是 `Violation` → 出口抛错）→ 方案 B 按字面实施会让**所有回测无法启动** |
| P1-07 步骤②「R07 由警告升阻断」 | **前提不成立**：R07 已经在阻断。真正的问题是**检测方式**——`_is_full_sample_receiver` 只匹配接收者名称含 `panel/full/all_/entire/whole`（cross_sectional.py:211-217），是命名启发式而非语义检测 |

**修正方向**（写入 P0-02 / P1-07）：
1. `realism_gate` **不复制** `leakage_gate` 的 severity 模型——直接**取消 severity，只保留 `critical` 布尔**，从设计上消灭歧义（§4.5 已按此设计，v2.2 明确写出"与 leakage_gate 不同构"）；
2. `leakage_gate` 侧二选一：①在 `assert_all_gates_pass` 中**真正消费 severity** 并补测试；②彻底移除 severity 语义，只保留"有违规即阻断"。**不得**维持"字段存在但无人读取"的现状；
3. R07 的正确处理不是"升档"，而是**改写为语义检测**（是否对含未来行的切片做 rank/quantile）或明确降级为报告项。

### 2.10 [v2.2 新增] 运行期因果暴露与 guard 接线实测

> 本节是第三轮复核的核心产出，直接决定 P0-07 与 P1-07 的设计。

**G1｜`context.data` 向策略暴露全量历史（含未来）**

| 事实 | 证据 |
|---|---|
| `get_data()` **不做任何时间截断**，直接返回整个 DataFrame | myquant/strategies/base.py:178-179（`return self.data.get(symbol)`） |
| 三个引擎都把**全回测窗口**塞进 `context.data` | event engine.py:327-337；mixed mixed_engine.py:275-281；vectorized vectorized_engine.py:267-271（均为 `data=self.data`） |
| 策略作者**自己知道**这是全量历史，必须自行截断 | kunpeng_strategy.py:930「回测中 context.data 为**全量历史**，若不截断会读到当前 bar 之后的」；kunpeng_strategy.py:34、149；multi_factor_strategy.py:27-28、1009；momentum_strategy.py:422、449；mean_reversion_strategy.py:220、225；ma_strategy.py:195、417 |

**推论一（v2.1 的 P1-07 设计不可用）**：provider 只在初始化时按 `[start_date, end_date]` 取一次全窗口，故"本次回测实际访问到的最大数据日期"**恒等于 `end_date`** ≥ 任何 `signal_date`。按 v2.1 写明的判据「任何标的的 `accessed_max_date > signal_date` 即违规」，**每个回测都会被判违规**。

**推论二（真实风险远大于方案描述）**：既然 `context.data` 含未来，"只看过去"**全靠每个策略作者记得截断**。而 `get_signal_data_end` 的默认实现恰恰是从**同一个全量 df** 里取 `<= signal_date` 的最后一行（base.py:664-674）——它**按构造恒返回 ≤ signal_date**，无法发现策略已读过未来行。这就是"自证"的**结构性成因**。

**推论三（新增缺陷族）**：`ma_strategy.py:417` 的 `self.pool_builder.build(all_symbols, context.data, as_of=bar.timestamp)` 说明选股池构建器接收全量 df + `as_of`——即**因果性依赖 `as_of` 参数被正确使用**，而非结构保证。任何 `as_of` 传错/漏传即前视，且不可检测。

**G3｜mixed / vectorized 未向 `context.extra` 注入 `lookahead_guard`**

| 引擎 | context 构造 | 是否注入 guard |
|---|---|---|
| event | engine.py:332-336 `extra={"lookahead_guard": ...}` | ✅ |
| **mixed（默认路径）** | mixed_engine.py:280 `extra={"engine_mode": "mixed"}` | ❌ |

| 数据 | `quality.{nan_price_rows, ohlc_violation_rows, coverage_rate}` | int/int/float | ✅ | 数据层注入 |
| 数据 | `fingerprint_hash` / `snapshot_id` | str\|null | ✅（null 即 unverified） | 数据层注入 |

| 样本池 | `pool.requested_count` / `.admitted_count` / `.dropped_count` / `.drop_reasons` | int/int/int/dict | ✅ | **[v2.2·G21]** 支撑 §9.4 影响面扫描 |

**[v2.1 并入·清单完整性 fail-closed]** 注入方（L3/L4）未提供某 critical 字段时，`manifest.build()` 必须抛 `ManifestIncompleteError`（记 `severity="阻断"` 的 `realism-manifest-incomplete` 违规）——**不允许"字段缺失 = 空值通过"**。

### 4.3 出口断言语义

```
assert_realism_pass(manifest) ->
  清单不完整（critical 字段缺失）    -> fail-closed：ManifestIncompleteError + 阻断
  无违规                            -> 通过
  有 critical 且 enabled=True       -> 落 audit_log（kind=realism_gate, action=violation）
                                       + 落阻断产物（§4.3.1）
                                       + 抛 RealismGateError（阻断引擎创建/启动）
  有 critical 且 enabled=False      -> 仅落 audit_log（audit 档）+ 强制把清单写入产物
  检查函数自身异常                  -> fail-closed：记 severity="阻断" 的 realism-gate-error 违规
```

与 `leakage_gate` 保持**三处对称**：①唯一出口断言；②违规落 `AuditLogStore` 哈希链（BASE-7 append-only）；③检查自身异常 fail-closed。

**与 `leakage_gate` 的三处刻意不同（[v2.2] 第三处为新增）**：
- **配置缺失 = 阻断**（`leakage_gate` 段缺失时落模块默认 True，本门禁要求**显式启用**，缺失即红）；
- **必须落盘**（清单强制写入 `results.json` 与报告页，不允许只进审计链）；
- **[v2.2·G2] `severity` 语义必须真实生效**：本门禁**取消 `severity` 字段，只保留 `critical` 布尔**。理由：`leakage_gate` 的 `severity` 事实上无人读取（§2.3 缺陷 C），若本门禁沿用同名概念，施工者照抄既有模式会再次得到一个"档位装饰性"的门禁。`critical` 是唯一的阻断判据，无歧义。

#### 4.3.1 [v2.2·G11] 阻断路径产物落点

被门禁拦下时**没有 `result` 对象**，故"写入 results.json"在该路径不可满足。定义：

- 阻断产物路径：`outputs/realism_gate_blocked_<YYYYMMDD_HHMMSS>_<strategy_id>.json`；
- 内容：完整 `RealismManifest` + 违规明细 + `decision_time` + 引擎模式 + 配置指纹；
- 与 `results.json` 同保留策略（纳入 `cleanup_service`，见 §4.7）；
- 报告侧：阻断产物同时渲染为 `realism_gate_blocked_*.html`（便于人工核查）；
- 反红测试：注入 critical 违规 → 断言①抛 `RealismGateError`；②`blocked_*.json` 存在且含违规字段；③`audit_log` 有记录。

### 4.4 双保险落点（针对旁路）

出口断言的"唯一性"已被核查证伪（§2.4）。因此采用**构造器级 + 出口级双保险**，**[v2.2·G5] 并按两阶段握手消除时序悖论**：

```
时序（不可颠倒）：
  ① create_engine 构造目标引擎实例
  ② 引擎.collect_manifest()   ← 采集装配事实（OrderMatcher/broker/费用模型实例的真实生效值）
  ③ manifest.build()          ← 完整性校验（缺 critical → ManifestIncompleteError）
  ④ assert_realism_pass(manifest)  ← 出口断言；通过则 seal(manifest)
  ⑤ engine.run() / on_init()  ← 入口处断言 "is_sealed()" 为真，否则 raise
```

- **出口级**：`BacktestScheduler.create_engine` / `create_live_engine` 调用 `assert_realism_pass`；
- **构造器/运行级**：断言点放在 **`on_init()` / `run()` 之前**（**不是 `__init__`**——v2.1 把断言点写成 `__init__` 会与 manifest 采集形成鸡生蛋）；未封存时 `raise`（或按配置降级为审计 + 产物标记）。
- **例外清单**（走**轻量审计**路径并打标，不豁免构造器断言）：`engine_benchmark.py`（无真实决策语义）、`consistency_check` 三引擎对拍（本身即门禁对拍工具）、`live_safety_gate` 验收流程。其余旁路（scripts/生成回测报告.py、param_optimizer、incremental_backtest、3 处 LiveEngine 直构）**必须**收敛。例外在 P0-00 阶段固化为 `REALISM_EXEMPT_ENTRY` 白名单并接受架构门禁登记。

### 4.5 Manifest 状态机闭合：字段状态 × 阻断语义矩阵

| critical 字段 | status=ok | status=degraded | status=disabled | status=unverified |
|---|---|---|---|---|
| critical=True（如 `slippage.is_zero_cost`、`pool.exclusion_basis`、`t1_position_freeze.enabled`、`causality.context_sliced`） | ✅ 通过 | 🔴 **阻断**（enabled=True 时）；记录 degraded 原因 | ⚠️ **仅当字段本身声明"可显式关闭"时允许**（如 `suspension.basis=none` 显式声明"停牌不建模"）→ 通过但清单打 `disabled` 标记；**未显式声明即 disabled → 视为 unverified → 阻断** | 🔴 **阻断**（缺失/无法判定即拒绝，如 `snapshot_id=null`） |
| critical=False（警告级，如 `calendar_source`、`engine_consistency.overall_ok`） | ✅ | ⚠️ 进清单 + 报告页警示条，不阻断 | ⚠️ 同上，不阻断 | ⚠️ 进清单 + 警示，不阻断 |
| 清单完整性（字段本身缺失） | — | — | — | 🔴 **阻断**（ManifestIncompleteError，§4.2） |
| **本引擎不适用**（[v2.2·G20]） | — | — | — | ⚪ **不参与判定**，但**必须在字段元数据中显式声明 `applicable=false` + reason**；未声明即按"缺失"处理 → 阻断 |

**裁决规则**：
1. `snapshot_id=null` / `fingerprint_hash=null` → **unverified → 阻断**；
2. `disabled` 必须是**显式配置声明**（配置里写明 `X: disabled` 并附 reason），非显式声明一律按未判定处理；
3. 同一字段同时出现 degraded + unverified 时，取**更严**（unverified → 阻断）；
4. `engine_consistency.overall_ok=False` → **不阻断回测**，但**阻断"可信/可上线"宣传标记**（P2-05 双轨）；
5. 矩阵在 `manifest.py` 中以**数据驱动表**实现（不写死在 gate.py 的 if 链），每个字段可独立配置语义；
6. **[v2.2] 本门禁不使用 `severity`**（§4.3 第三处不同）——阻断判据只有 `critical` 布尔与 status 四态，避免复现 `leakage_gate` 的"档位装饰性"缺陷。

### 4.7 性能/IO 预算（防止参数优化拖垮）

| 场景 | 落盘策略 | 存储预算 |
|---|---|---|
| 单次回测 / 实盘准入 | 逐次落盘（1 份 results.json + 1 份 blocked 产物（仅阻断时）+ 1 份 realism manifest + audit_log 1~N 条） | 单份 ≤ 200 KB |
| 批量回测（BatchBacktest） | **按批次聚合**：1 份批次清单（含每标的摘要 + 违规明细仅在违规时展开） | 批次 ≤ 2 MB |
| 参数优化（鲲鹏，千次实验） | **按扫描批次聚合落盘**：每批 1 份 `realism_manifest_batch.json`（含参数组摘要 + 全量关键字段矩阵 + 违规明细按需展开）；**不逐参数组落盘** | 每批 ≤ 5 MB |
| audit_log 哈希链 | 违规才落链；通过项仅记批次级摘要（不含逐参数组哈希） | — |

**保留期**：`realism_manifest*.json`、`realism_gate_blocked_*.json` 与 `leakage_report_*.json` 纳入既有 `cleanup_service` 保留策略（与回测期产物同生命周期）；违规批次清单保留期**双倍**（审计需要）。性能验收：参数优化 1000 组场景下，清单相关 IO 总耗时 ≤ 总回测时长的 1%。

### 4.8 行为回归基线

反红三件套只证明"门禁能抓违规"，**不证明"引擎合法行为没被改造意外破坏"**。因此建立**基线净值档案**：

- **建立**：P0-00 阶段对"**策略 × 其支持的引擎 × 当前配置**"（[v2.2·G19] 原文"全部策略 × 三引擎"不可执行——多数策略不支持三引擎）跑一遍基线回测，输出 `outputs/realism_baseline/{strategy}_{engine}_{config_hash}.json`（净值曲线哈希 + 关键指标 + 成交明细指纹）；
- **对拍**：每张 M3/M6 任务卡完成后，重跑同配置回测，与基线对拍；差异超阈值（单标的净值序列 max abs diff > 0.5%，或成交笔数差 > 5%）→ 该卡**未通过验收**；
- **预期变化与回归事故的区分**：预期变化必须**在 §5.5 映射表中声明**对应的 manifest 字段 `degraded/disabled` 标记变化；无标记变化却出现净值差异 → 判为回归事故。

### 4.9 [v2.2·G8] 结果侧真实性不变量（Result Realism Invariants）

**动机**：§4.2 的 manifest 只在**引擎创建时**校验"配置/装配是否真实"，无法发现**结果层面的不可能事件**。而对"回测是否真实"最有力的证据恰恰在结果侧。以下不变量成本极低、几乎无法伪造，且**能直接抓住本项目已存在的缺陷**。

| ID | 不变量 | 判据 | 能抓住的既有缺陷 |
|---|---|---|---|
| RI-1 | 成交价在当日价格区间内 | 每笔成交价 ∈ `[当日 low, 当日 high]`（容忍滑点带宽：`±max(slippage_amount, 1 tick)`） | 滑点/撮合定价错误 |
| RI-2 | 成交量不超过当日可成交量 | 单笔成交量 ≤ `当日 volume × participation_cap`（cap 未声明时按 manifest 的"无限流动性"声明放行并在清单打标） | 流动性约束缺失（P1-09 的前置证据） |
| RI-3 | 权益恒等式 | `equity == cash + Σ(持仓量 × 当日收盘价)`，容差 1e-6×初始资金 | **vectorized `cash[i:]`/`position[i:]` 覆盖前值**（vectorized_engine.py:561-584） |
| RI-4 | 现金非负（未声明杠杆时） | 任一时点 `cash >= -tolerance` | **event 市价单资金校验 fail-open（透支）**（sim_broker.py:150-160） |
| RI-5 | T+1 一致性 | 同一标的同一交易日卖出量 ≤ 前一交易日末持仓量 | T+1 持仓冻结缺失（P1-08 的前置证据） |
| RI-6 | 持仓非负 | 任一时点持仓量 ≥ 0（未声明做空时） | 卖空穿透 |

**落点与语义**：
- 实现于 `myquant/realism_gate/invariants.py`（L0，只消费调用方注入的成交/净值序列，不 import L3/L4）；
- 在**回测结束时**（`on_stop` 前）逐笔/逐 bar 校验；
- 违规 → ①写入 manifest `invariants.*`；②`result.mark_failed`（复用既有终态保护，models/backtest.py:445-447）；③落 `audit_log`；④阻断"可信"标记；
- **不**阻断引擎创建（此时刻已过），但**必须**阻断结果被引用为决策依据（产物打 `realism_invariants_failed` 标记）；
- 反红测试：`tests/realism_gate/test_invariants_red.py` —— 逐条构造违规序列，断言 `mark_failed` + 产物标记 + 审计。

### 4.10 [v2.2·G7] manifest_signature 与跨运行可比性

**动机**：项目已有前车之鉴——`batch_backtest` 的指纹 payload 缺 `mode` 字段，导致不同引擎口径的结果被复用/混入同一排名（项目自身独立审核报告 P1 项）。`realism_gate` 在**新的层次**上引入了同一类风险：1000 组参数中若部分 `degraded`（复权降级 raw、涨跌停未生效），排序会把**不同真实性口径**的结果混在一起比较。

**设计**：
- `manifest_signature = sha256(canonical_json(manifest 字段))`，**剔除** `run_id` / 时间戳 / `start_date` / `end_date` / `engine_mode_*` / `pairs` 等运行特异字段，**保留**全部真实性相关字段；
- 签名写入：`results.json`、`realism_manifest_batch.json`、批量指纹（`fingerprints.json`）；
- **排序分组键**：`param_optimizer` / `batch_backtest` / `candidate_pool` 的聚合与排序必须以 `manifest_signature` 为**分组键**；跨签名**禁止**合并排行；
- **跨签名比较拦截**：`candidate_pool` / `batch_report` 在合并多标的结果时校验签名一致，不一致即拒绝合并并输出差异清单；
- 反红测试：构造两个仅真实性字段不同的 manifest → 断言排序不合并、`candidate_pool` 拒绝合并。

## 七、验收标准（反红三件套 + 行为回归，不可协商）

任何任务卡完成的判定必须是**四条同时成立**：

| # | 标准 | 判定方式 |
|---|---|---|
| 1 | **能变红** | 注入违例 → 门禁抛出 → 有测试证明（且测试**不 monkeypatch 掉被测对象**、**走真实生产出口**） |
| 2 | **看得见** | 进程退出码非零 / 产物含明确标记（含 `realism_gate_blocked_*.json`）/ 报告页有披露 |
| 3 | **可追溯** | `audit_log` 哈希链 或 `results.json` 有留痕（**[v2.2·G12] strict 模式抛错路径同样必须落链**） |
| 4 | **不误伤** | M3/M6 每张卡完成后，重跑基线档案同配置回测；净值序列 max abs diff ≤ 0.5% 且成交笔数差 ≤ 5%（§4.8）。预期差异必须**在 §5.5 映射表中登记的 manifest 字段**出现 `degraded/disabled` 变化，无登记字段却出现差异 → 回归事故，卡不通过 |

**明确排除项**（以下不构成完成证据）：
- 仅"测试全绿"；
- 仅"配置断言为 true"（如 ci.yml:443-458 现有做法）；
- 仅"调用点已被调用"（spy 替换被测函数的做法）；
- 仅 logger 输出（尤其 debug 级）；
- 仅"行数达标"而行为未对拍（重构必须双证：行数 + 基线对拍）；
- **[v2.2] 仅"字段存在"**而出口断言不消费它（`severity` 的教训，§2.3 缺陷 C）。

**本项目测试现状恰恰证明了上述排除项的必要性**：全测试会话关门禁 + 不复原的 `reset_gate_checks()` + spy 替换 + 合成台账 + 把"注入泄漏仍通过"写成断言 —— 这套组合下"全绿"与"门禁有效"之间没有因果关系。

## 附录 B：术语

| 术语 | 定义 |
|---|---|
| 真实性约束 | 使回测成交/费用/样本与真实市场一致的一类约束（涨跌停、停牌、T+1、流动性、滑点、费用、复权、样本口径、数据质量） |
| 死键 | 配置文件中存在、但全仓无任何代码读取点的键 |
| fail-open | 约束缺失/异常时**放行**（不阻断），使约束静默失效 |
| fail-closed | 约束缺失/异常时**阻断**，宁可拒绝启动也不放行 |
| 反红 | 注入已知违例，验证门禁**必然**变红（相对于"注入泄漏仍通过"的 self-proving 测试） |
| 反红三件套 | 能变红 + 看得见（退出码/产物标记）+ 可追溯（audit_log/results.json） |
| 自证式测试 | 测试把被测对象替换掉、或把"不报警"写成期望，因此"全绿"不携带检测有效性信息 |
| 真实性清单 | RealismManifest：一次回测运行的真实性事实快照（配置声明值 vs 实例生效值） |
| 审批两态 | 豁免的 `pending → approved → revoked` 状态机；仅 `approved` 且未过期豁免压制违规 |
| Manifest 状态机 | `ok/degraded/disabled/unverified` 四态 × critical 的阻断语义矩阵（§4.5） |
| 基线净值档案 | P0-00 建立的"策略×其支持的引擎×当前配置"基线回测产物，用于行为回归对拍（§4.8） |
| 行为回归 | 重构/改造后与基线对拍，验证引擎合法行为未被意外改变（第七章标准 4） |
| **[v2.2] 因果切片** | 让 `StrategyContext.get_data()` 只返回 `<= current_bar_ts` 的数据视图，使"策略看不到未来"成为**结构保证**而非约定（§4.1 / P0-07） |
| **[v2.2] 结果侧真实性不变量** | 在回测结果上校验的不可能事件断言（价界/量界/权益恒等式/现金非负/T+1 一致/持仓非负），§4.9 |
| **[v2.2] manifest_signature** | 剔除运行特异字段后的 manifest 哈希，用作跨运行可比性的分组键（§4.10） |
| **[v2.2] 标记背书** | 行为变化必须由 §5.5 映射表中的 manifest 字段 `degraded/disabled` 变化背书，否则判为回归事故 |
