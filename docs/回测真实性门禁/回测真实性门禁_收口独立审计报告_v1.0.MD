- 引擎出口真实调用点：
  - `myquant/backtest/engine.py:1657` → `assert_all_gates_pass(...)`
  - `myquant/live/engine.py:2796` → `assert_all_gates_pass(...)`
- `gate.py:162` `_GATE_CHECKS` 注册表；`gate.py:288` `assert_all_gates_pass` 出口断言。

**结论**：✅ 非空 dict 假绿。`from myquant.leakage_gate import assert_all_gates_pass` 一行即连带注册全部 7 个 check。

## 三、两个"疑似漏洞"专项排查

### 3.1 vectorized 引擎从不置位 current_bar_ts

**疑点**：`vectorized_engine.py:505` 注释"vectorized 从不置位 current_bar_ts（逃生口路径）→ 评估不判"。初看疑似 P0 漏洞——vectorized 回测是否读全量含未来？

**回代码**：
- `vectorized_engine.py:495-496`：vectorized 策略的信号函数签名是 `generate_signals_vectorized(df)`，df 作为**全量参数直接传入**——策略**不经 `context.get_data` 取数**。
- 逃生口由 `full_sample_declared=True` critical 字段**显式声明**（`manifest` 里诚实 `context_data_scoped: False`）。
- 因果性不来自逐 bar 切片，而来自 static_scan 静态门禁（R03 全样本拟合检测）覆盖信号函数内部。

**结论**：✅ **不是漏洞，是显式设计**。vectorized 是"全样本一次性计算"范式，与 event/mixed 的"逐 bar 切片"范式并列，各自有声明与门禁覆盖。

### 3.2 R-25 半完成尾巴

**疑点**：前置调研最后一项 R-25 `_slicing_enabled` 生命周期，此前标"半完成：运行时复用待验"。

**回代码**：`tests/unit/test_causality_slicing.py:127` `TestReusedContextNoLeftover`：
- 首次 run 末：`_slicing_enabled=True` + `current_bar_ts=末bar` + `accessed_max_dates` 记账。
- 二次 run：run 起点复位三态后 on_bar 重新置位。
- 复跑 1 passed。

**结论**：✅ 运行时复用复位点已被测试冻结，归档成立。
