## 一、背景与核查结论

### 1.1 一句话结论

**项目里不存在"回测真实性门禁"这个实体。** 存在的是 `leakage_gate`（策略**源码**防泄漏合规门禁）与 `live_safety_gate`（实盘运维安全验收）。真实性约束（涨跌停、停牌、流动性、T+1 持仓冻结、费用与滑点口径、复权、样本口径、数据质量）全部以**引擎内联行为 + 配置声明 + 文档承诺**三种形态存在，**没有任何一项**受"唯一出口断言 + 违规阻断 + 审计留痕 + 证据产物 + fail-closed"这套门禁范式的保护。

### 1.2 三条支撑判断

1. **`leakage_gate` 装配链真实、主入口硬阻断，但检测能力已被掏空。**
   列级台账 14 列 `severity` 全部为"通过"，导致 `blocked=∅` → 消费侧 R11 主判据与特征白名单门禁**在结构上永远返回空**。这道门禁能因"配置缺失"变红，**不能因"存在泄漏"变红**。且 5 个注册检查**全部是对 `myquant/strategies/*.py` 的 AST 静态扫描**，回测运行期**零约束**。

2. **真实性约束呈三种失效形态。**
   - 默认路径生效但**不可控**：mixed 引擎的涨跌停/停牌由 `OrderMatcher()` 硬编码默认值生效，配置文件管不到；
   - 默认路径**不生效且配置写了也没用**：event 涨跌停/停牌、流动性占比、T+1 持仓冻结、`adjust_strict`、幸存者偏差折价；
   - **只存在于文档**：`leakage_report.json` 产物、数据快照 pin、回测期数据质量门禁。

3. **配置→行为链断裂，且默认值一律偏向"更宽松/更便宜"。**
   任何配置疏忽、键名拼写错误、参数未透传，都朝"回测更好看"的方向漂移。这是本项目最危险的设计属性。

### 1.3 一句话战略判断

项目在"**数据如何被消费**"这一层（复权 as_of、财务 `eff_disclosure_date`、股本科 PIT、清洗期 OHLC 阻断、指纹缓存、防未来函数记录校验）做得扎实且可验证，工程质量明显高于一般个人量化项目。问题高度集中在"**回测样本是什么**"与"**约束是否真的在跑**"这两层。**不需要重写**，需要把已有严谨性从"数据消费层"平移到"回测真实性层"——即补上缺失的门禁对象（本方案 P0-01），再把散落的真实性约束挂上去。

### 2.3 `leakage_gate` 被掏空的检测能力（决定性）

**缺陷 A｜台账无阻断列 → R11 / 特征白名单恒真**

`config/data_time_semantics.yaml` 全部 14 列 `severity` 均为"通过"（第 20/25/30/35/41/46/51/56/61/68/73/78/83/91 行），`severity: 阻断` **零匹配**。

判据在 myquant/leakage_gate/consumption.py:151：

```python
return sorted((set(declared) | actual) & blocked)   # blocked = 台账 severity=阻断 的列
```

`blocked = _blocked_columns(ledger)`（consumption.py:192-200）取到**空集** → 交集恒空 → `check_consumption` 永不产违规。同理 myquant/leakage_gate/sanity.py:345-347：`blocked` 为空即 `return []`。

**后果**：R11/RL-13「引用阻断档数据列即出口报红」这一被反复写入文档与验收项的能力，**当前处于完全空转**。门禁剩下的唯一变红路径是"台账/注册表/配置缺失"。

**缺陷 B｜5 个注册检查全是源码 AST 扫描，回测运行期零约束**

| 注册名 | 检查对象 | 运行时数据？ |
|---|---|---|
| `contract` | config/strategy_registry.yaml 声明完整性 | ❌ |
| `consumption` | myquant/strategies/*.py 源码文本 | ❌ |
| `static_scan` | 同上 | ❌ |
| `cross_sectional` | 同上（找 `panel.rank()` 类命名） | ❌ 且只产「警告」 |
| `feature_whitelist` | myquant/ml/features.py 的白名单字面量 | ❌ |

能真正做运行时 as-of 判定的 `validate_asof` / `validate_cross_sectional_panel`（myquant/leakage_gate/cross_sectional.py:44-163）是**孤儿**——生产调用点为零（仅 tests/leakage_gate/test_static_scan.py）。源码注释自认："本门禁不持有运行数据"（cross_sectional.py:229）。

**补充澄清（避免误判）**：`assert_all_gates_pass` 的 `decision_time` 传的是 `time.strftime("%Y-%m-%d")`（今天，engine.py:1065），但 5 个注册检查**只把该值写进 `Violation` 字段、从不与数据比较**（contract.py:269→131、consumption.py:203→220、static_scan.py:734→753、cross_sectional.py:224→265、sanity.py:324→343）。因此它**不导致空转**，只造成（a）审计记录语义错误（把"回测决策日"记成"今天"）、（b）豁免有效期按今天而非决策日判定（exemption.py:45-47,75,80）。修复时应一并纠正，但不是空转根因。

### 4.3 出口断言语义

```
assert_realism_pass(manifest) ->
  无违规                            -> 通过
  有 critical 且 enabled=True       -> 落 audit_log（kind=realism_gate, action=violation）
                                       + 抛 RealismGateError（阻断引擎创建/启动）
  有 critical 且 enabled=False      -> 仅落 audit_log（警告档），并强制把清单写入产物
  检查函数自身异常                  -> fail-closed：记 severity="阻断" 的 realism-gate-error 违规
```

与 `leakage_gate` 保持**三处对称**，以复用既有治理经验：
1. 唯一出口断言（`create_engine` / `create_live_engine` 旁）；
2. 违规落 `AuditLogStore` 哈希链（BASE-7 append-only）；
3. 检查自身异常 fail-closed。

**与 `leakage_gate` 的两处刻意不同**（针对本次核查发现的失效模式）：
- **配置缺失 = 阻断**（`leakage_gate` 段缺失时落模块默认 True，本门禁要求**显式启用**，缺失即红）；
- **必须落盘**（清单强制写入 `results.json` 与报告页，不允许只进审计链）。

### 4.4 双保险落点（针对旁路）

出口断言的"唯一性"已被本次核查证伪（§2.4）。因此本门禁采用**构造器级 + 出口级双保险**：

- **出口级**：`BacktestScheduler.create_engine` / `create_live_engine` 调用 `assert_realism_pass`；
- **构造器级**：`BacktestEngine.__init__` / `MixedBacktestEngine.__init__` / `VectorizedBacktestEngine.__init__` / `LiveEngine.__init__` 增加"必须持有已通过门禁的 `realism_manifest` 句柄"断言（未持有时 `raise`，或按 `enforce` 配置降级为审计 + 产物标记）。

## 七、验收标准（反红三件套，不可协商）

任何任务卡完成的判定必须是**三条同时成立**：

| # | 标准 | 判定方式 |
|---|---|---|
| 1 | **能变红** | 注入违例 → 门禁抛出 → 有测试证明（且测试**不 monkeypatch 掉被测对象**、**走真实生产出口**） |
| 2 | **看得见** | 进程退出码非零 / 产物含明确标记 / 报告页有披露 |
| 3 | **可追溯** | `audit_log` 哈希链 或 `results.json` 有留痕 |

**明确排除项**（以下不构成完成证据）：
- 仅"测试全绿"；
- 仅"配置断言为 true"（如 ci.yml:443-458 现有做法）；
- 仅"调用点已被调用"（spy 替换被测函数的做法）；
- 仅 logger 输出（尤其 debug 级）。

**本项目测试现状恰恰证明了上述排除项的必要性**：全测试会话关门禁 + 不复原的 `reset_gate_checks()` + spy 替换 + 合成台账 + 把"注入泄漏仍通过"写成断言 —— 这套组合下"全绿"与"门禁有效"之间没有因果关系。

## 附录 B：术语

| 术语 | 定义 |
|---|---|
| 真实性约束 | 使回测成交/费用/样本与真实市场一致的一类约束（涨跌停、停牌、T+1、流动性、滑点、费用、复权、样本口径、数据质量） |
| 死键 | 配置文件中存在、但全仓无任何代码读取点的键 |
| fail-open | 约束缺失/异常时**放行**（不阻断），使约束静默失效 |
| fail-closed | 约束缺失/异常时**阻断**，宁可拒绝启动也不放行 |
| 反红 | 注入已知违例，验证门禁**必然**变红（相对于"注入泄漏仍通过"的 self-proving 测试） |
| 反红三件套 | 能变红 + 看得见（退出码/产物标记）+ 可追溯（audit_log/results.json） |
| 自证式测试 | 测试把被测对象替换掉、或把"不报警"写成期望，因此"全绿"不携带检测有效性信息 |
| 真实性清单 | RealismManifest：一次回测运行的真实性事实快照（配置声明值 vs 实例生效值） |
