## 四、P1-11 接口级接线方案（基于真实签名）

> 施工原则（遵守治理规则）：**改动全部落在 myquant 内已存在模块**（engine.py / live/engine.py / training_pipeline.py / param_optimizer.py），不新增蓝图外文件；如确需新增模块，先查蓝图 `docs/project_layout_gear2.md` 目录树、回写蓝图、配测试（R-19）。以下为设计，实施前须按 P0-00 行数预算评估落点。

### 4.1 回测出口（P1-11 步骤①）—— 唯一必做

**接线点**：`BacktestScheduler.run()`（engine.py:1099-1124），`engine.run()` 返回之后、`return result` 之前。

**设计**（伪代码，施工时按 py 规则全量类型注解 + docstring）：

```python
# engine.py BacktestScheduler.run() 内，result = engine.run() 之后
from myquant.leakage_gate.gate import collect_gate_stats
from myquant.leakage_gate.report import write_experiment_report

decision_time = config.end_date            # 或策略首个决策日（P2-11 语义，勿用 time.strftime 当天）
gate_stats = collect_gate_stats(
    strategy_id=getattr(strategy, "name", "") or "",
    decision_time=decision_time,
)
guard = get_lookahead_guard()              # engine.py 已 import（:1075 用）
write_experiment_report(
    experiment_id=f"backtest_{config.start_date}_{config.end_date}",
    experiment_type="backtest",
    strategy_id=getattr(strategy, "name", "") or "",
    decision_time=decision_time,
    gate_stats=gate_stats,
    lookahead_guard=guard.stats(),
    extra={"engine_mode": self.selected_mode},   # 复用 :1122 既有 extra 打标
)
```

**要点**：
- 用 `write_experiment_report` 便捷入口（真实存在，report.py:258）而非手写 build+write 两步——少一个出错面；
- `gate_stats` 数据源 = `collect_gate_stats`（真实存在，gate.py:235），参数与断言同形（strategy_id/decision_time）；
- `guard.stats()` 取全局单例统计；**接线前须确认 `engine.run()` 前已 `guard.reset()`**（P1-07 落实，本卡只读 stats）；
- 若 P2-11（decision_time 语义）未同步实施，此处先传 `config.end_date`（比"今天"更接近决策日，且是配置既有字段，无新依赖）。

### 4.2 实盘出口（P1-11 步骤②）

**接线点**：`create_live_engine`（live/engine.py:2687），`assert_all_gates_pass`（:2793-2798）通过之后、返回引擎之前。

**设计**：
```python
# live/engine.py create_live_engine 内，断言通过后
from myquant.leakage_gate.report import write_experiment_report
from myquant.leakage_gate.gate import collect_gate_stats

gate_stats = collect_gate_stats(strategy_id=strategy_name, decision_time=decision_time)
write_experiment_report(
    experiment_id=f"live_{strategy_name}_{_iso_now_ts()}",
    experiment_type="live",
    strategy_id=strategy_name,
    decision_time=decision_time,
    gate_stats=gate_stats,
    lookahead_guard=get_lookahead_guard().stats(),
)
```
- `experiment_type="live"`（v2.2 要求）；**实盘不 reset guard**（实盘持续运行，统计为进程累计，语义上标注即可）。

### 4.3 训练出口（P1-11 步骤③）

**接线点**：`TrainingPipeline.run()`（training_pipeline.py:1270）收尾段。

**设计**：
- 在 run() 内调用 `sanity.check_training_sanity(...)`（真实存在，sanity.py:416）并把返回的违规列表作为报告 `sanity` 段（报告结构本就预留）；
- `write_experiment_report(experiment_id=..., experiment_type="training", sanity=bad_list, ...)`；
- **治理约束**：sanity.py:6 注明"training_pipeline.py 行数 ≤ 1651，新增逻辑不落 ml 层"——接线代码应**薄**（仅 2-3 行调用），或经 myquant.ml.__init__ 现有导出路径调用，避免行数膨胀触发 R-14。

### 4.4 参数优化出口（P1-11 步骤③）

**接线点**：`ParamOptimizer.optimize()`（param_optimizer.py:815）收尾段。

**依赖声明**：本出口的**门禁断言本身缺失**（optimize 直构引擎旁路），严格说应先由 **P1-04（旁路收敛）** 让参数优化改走 `create_engine`，再在 optimize() 收尾接报告。若 P1-11 先于 P1-04 施工，则此处只能接"参数优化结果摘要"报告（不含门禁段），并在文档标注"门禁段待 P1-04 后补齐"。

**设计**（P1-04 之后）：
```python
# param_optimizer.py optimize() 收尾
write_experiment_report(
    experiment_id=f"param_opt_{config.start_date}_{config.end_date}",
    experiment_type="param_optimization",
    strategy_id=strategy.name,
    gate_stats=collect_gate_stats(strategy.name, config.end_date),
    lookahead_guard=get_lookahead_guard().stats(),
    extra={"n_groups": len(result.groups) if hasattr(result, "groups") else 0},
)
```

```python
def get_data(self, symbol: str) -> Optional[pd.DataFrame]:
    """返回截至当前 bar 的因果切片视图（防未来：本行使用的数据截至 current_bar_ts 时刻）。

    - current_bar_ts 已设置：返回 ``data[symbol].loc[:current_bar_ts]``（O(1) 视图，不复制）；
    - current_bar_ts 未设置且非 full_sample_declared：**fail-closed 返回空 DataFrame**
      （迫使调用方显式声明语义，杜绝"以为有全量"的隐性泄漏）；
    - full_sample_declared=True：返回全量（vectorized 逃生口，须 manifest 披露）。

    Args:
        symbol: 标的代码。

    Returns:
        因果切片 DataFrame；无数据或 fail-closed 时返回空 DataFrame。
    """
```

**切片实现要点**：
1. `df.loc[:cutoff]` 是 pandas 标签切片，对 DatetimeIndex **O(1) 视图不复制**（R-20 需微基准验证：`current_bar_ts` 为 Timestamp 时直接切片；为 epoch 秒 float 时先 `pd.Timestamp.fromtimestamp()` 归一化——参照 base.py:899 既有写法）；
2. **fail-closed 语义**：`current_bar_ts is None and not full_sample_declared` → 返回 `df.iloc[0:0]`（空视图，保留列结构，防调用方 `.columns` 访问炸裂）；
3. **引擎内部通道不受影响**：引擎持 `self.data` 原始引用（§2.4），不经过本方法。

## 四、vectorized 全量逃生口设计（§4.4 联动）

**问题**：vectorized 的 `generate_signals_vectorized(df)`（vectorized_engine.py:470）**直接收全量 df**（不经 context.get_data），其目标持仓生成天然需要全窗口（向量化一次性计算）。

**设计**：
1. `_run_symbol` 内 `self.context.full_sample_declared = True`（每标的进入时设置）；
2. `get_data` 在 `full_sample_declared=True` 时返回全量（逃生口，与 fail-closed 互斥）；
3. `generate_signals_vectorized` 的因果性由策略内部保证（策略注释声明，kunpeng 等已按 `_slice_upto` 自证）；
4. 结果侧：`causality.full_sample_declared=true`（critical）写入 manifest；报告页固定披露"**本回测以全样本生成目标持仓，因果性由策略 generate_signals_vectorized 内部保证**"；
5. **反红测试**：构造"探针 vectorized 策略读 `df.iloc[-1]`"→ 断言全量可用（逃生口不拦），且 manifest 出现 `full_sample_declared=true` 披露——证明"逃生口是显式声明而非静默泄漏"。

### 四、关键发现与边界

1. **确定性执行已天然成立**：无随机种子/无 provider 快照 pin（provider.py:309-311、420-433），重跑仍逐点一致 → 系统执行路径（数据加载→信号→撮合→记账）为确定性计算，无时间/随机依赖泄漏进业务结果。P0-00 子步骤 B 的基线档案可安全建立在"同配置重跑哈希一致"前提上。
2. **运行元数据是唯一不稳定字段**：result JSON 仅 started_at/finished_at/run_id 含墙钟时间（run_回测入口.py:435 文件名亦含 `int(time.time())`）。P0-00 子步骤 B 建哈希时必须**剔除这三字段**（或规范化后比较），否则每次提交必 diff。

4. **基准数据缺失**：000300.SH（benchmark）processed parquet 不存在 → 基准净值恒为 1.0、基准收益率 "-"；该缺口影响"超额收益"指标计算，但不影响可复现性结论。如需基准对拍，P0-00 子步骤 B 施工时应先补齐基准数据或显式声明跳过。
