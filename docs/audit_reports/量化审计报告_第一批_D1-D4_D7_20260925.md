- 证据：GUI `backtest_config_dialog.py` L333-336 与 `config/backtest_config.example.yaml` L139 均写 `strict_mode: true`；但回测引擎以 `LookaheadGuard()` 无参构造（engine.py L147 / vectorized_engine.py L198 / mixed_engine.py L195），strict 仅由环境变量 `LOOKAHEAD_GUARD_STRICT` 决定（默认 false）；`config_builder.py`、`run_回测入口.py` 均无 strict_mode 消费代码。实盘端正常：`live/engine.py` L2546 `LookaheadGuard(strict=bool(lookahead_cfg.get("strict_mode", True)))`，`tests/unit/test_live_lookahead.py` 有 4 项覆盖
- 影响：回测端违规为「跑完统一在 assert_pass() 抛错（返回码 3）」，而非配置声明的「立即中止」；安全兜底仍在，但声明与实现不一致
- 修复动作：在 `run_回测入口.py`（或 config_builder）读取 `lookahead_guard.enabled/strict_mode`，构造/注入 `LookaheadGuard(strict=...)`，与实盘端对齐
- 复验：新增单测断言回测 guard.strict == 配置值；`test_lookahead_wiring.py` 回归

**P2-D7-002 · 轻量防未来校验器未接入任何引擎，开关形同虚设（LOOKAHEAD_BYPASS）**
- 证据：`light_lookahead_guard.py` 头部声明「回测专用、由回测引擎逐 bar 推进」、`performance_config.py` L31/L269 注释「引擎逐 bar 校验」；但全仓检索 `on_bar_close / check_data_access / check_indicator_window / check_signal_execution` **无任何生产调用**（仅模块自测与文档字符串）；`apply_performance()` 仅切换单例 `enabled/strict` 并同步环境变量，**无消费方**
- 影响：蓝图「双校验器」防线的第二层（轻量逐 bar 实时拦截）零防护作用；性能配置中的 `light_lookahead_guard` 开关实际无效；`strict` 默认 false 且无人消费
- 修复动作（二选一）：(a) 将 light guard 接入事件/mixed 引擎关键检查点（`on_bar_close` + `check_*`），使性能配置真正生效；(b) 若判定记录型 guard 已足够，降级 light guard 声明为「独立可选模块」，修正 performance_config 注释，避免误导
- 复验：接入后构造一次未来数据访问观察拦截；或更新文档后跑 `test_lookahead_wiring.py` 回归

**P2-D7-003 · `record_indicator` / `record_stop_loss` 无生产调用，铁律 1/2 运行期无 guard 记录（LOOKAHEAD_BYPASS）**
- 证据：全仓检索仅 lookahead_guard.py 自身定义与 docstring 示例引用；引擎只调 `record_signal` / `record_trade`（engine.py L376/L443、vectorized L557-570、mixed L605/L829、live L1435）

- 影响：防御深度低于蓝图「四条铁律各有 guard 校验」表述
- 修复动作：在引擎指标计算/止损调用点补 `record_indicator` / `record_stop_loss`；或在蓝图明确「铁律 1/2 由结构+测试保障，guard 覆盖 3/4」
- 复验：新增一条断言测试验证违规被记录
