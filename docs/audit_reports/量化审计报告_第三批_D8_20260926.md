## 4. 资金口径（1 项 P3）

### 4.1 实测同源链路（健康）

- **实盘侧**：`live_config.example.yaml` L22 `initial_capital: 1000000` → `myquant/live/engine.py::create_live_engine` L2490 `initial_capital = float(live_cfg.get("initial_capital", 1_000_000))` → broker 构造（L2348/L2354/L2362）→ `LivePortfolio(initial_capital=...)`（L2564）→ **策略资金基准**：L2521-2523 注释"策略资金基准与账户一致（读 live 配置 initial_capital，避免默认 100 万口径错位）"+ `strategy_params.setdefault("capital_base", initial_capital)`。全链路同源 ✅
- **回测侧**：`batch_backtest.py` L67 `DEFAULT_INITIAL_CAPITAL = 1_000_000`，与实盘默认一致 ✅
- 策略内部：`base.py` L386-406 `_shares_from_capital(capital_base, price, pct)` 以 capital_base 为基准计算股数（L2523 已注入）。

### 4.2 P3-D8-004 API 回测请求默认资金 10 万 ≠ 回测/实盘 100 万（占位未接线，风险前置）

- `myquant/api/models/schemas.py` L245：`BacktestRequest.initial_capital: float = 100000.0`（**10 万**）。
- 回测 CLI 默认 100 万、实盘配置默认 100 万 → API 默认口径分裂。
- 现状缓解：`api/routes.py::run_backtest` L462 为 **v1 占位**（返回假指标 0.0523/0.125…，注释"v1占位：后续迭代调用回测引擎"），**不消费** `request.initial_capital` → 当前无实际资金错位。
- 风险：一旦占位接线到回测引擎，未显式传资金的 API 调用将以 10 万口径运行，与 CLI/实盘 100 万结果不可比。

**修复动作**：`BacktestRequest.initial_capital` 默认值改为引用统一常量（如 `myquant/core/constants.py::DEFAULT_INITIAL_CAPITAL = 1_000_000`），或接线时强制显式传参并加非零校验（batch_backtest L375-376 已有 `initial_capital <= 0` 拒绝）。
**复验方式**：API 文档默认值显示 1,000,000；无资金参数的回测请求与 CLI 同参数结果一致。
