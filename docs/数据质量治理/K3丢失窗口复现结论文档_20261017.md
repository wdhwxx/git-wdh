# K3 丢失窗口复现结论文档（2026-10-17）

**对应施工项**：A-03（P0，只读/临时库复现）· 数据层结构优化施工（v1.1 报告 §5.2 A-03 行，§5.3 依赖链 A-03→A-05）

## 结论（一句话）

**K3 丢失窗口成立（复现成功=机制确认）**：`full_clean_service.write_back_symbol` 的
"删旧+插新"在 SQLite 单连接上形成三层嵌套事务且无 SAVEPOINT，内层 `delete_market_data`
的 commit 提前提交外层事务，一旦后续 `bulk_insert` 失败，**DELETE 已生效（标的被删空）、
INSERT 未生效、外层事务无法回滚恢复**——"标的被删空且不可回滚"的数据丢失窗口为真。

## 一、根因（代码级取证）

| 位置 | 代码 | 角色 |
|---|---|---|
| `myquant/database/queries.py:218` | `bulk_insert_market_data` 内 `with self.conn.transaction():` | 内层事务②（insert） |
| `myquant/database/queries.py:237` | `delete_market_data` 内 `with self.conn.transaction():` | 内层事务①（delete） |
| `myquant/data_access/full_clean_service.py:735` | `write_back_symbol` 内 `with dq.conn.transaction():` | 外层事务 |

三层嵌套、SQLite 单连接、**无 SAVEPOINT**。Python sqlite3 在单连接上的行为：
事务内再次 commit 提交的是**当前整个活跃事务**，而不是内层"自己的事务"。

## 二、丢失窗口机制推演（与复现逐层对应）

1. 外层 `write_back_symbol` 事务开启（首次写语句触发隐式 BEGIN）；
2. `delete_market_data` 的内层 `transaction()` 退出时 `conn.commit()` → **DELETE 已生效且已提交**；
3. `bulk_insert_market_data` 开新事务写入，若中途异常 → 该事务 rollback → **INSERT 未生效**；
4. `write_back_symbol` 捕获异常返回 `"error"`，但 DELETE 早已提交、无法回滚
   ⇒ 标的旧行被删空、新行未写入 → 数据丢失窗口。

## 三、复现实验（临时库，不碰生产库）

复现脚本：`tests/unit/test_k3_loss_window.py`（3 项，临时 sqlite 库，模拟
`write_back_symbol` 嵌套语义；不调真实服务，聚焦事务机制本身）。

| 用例 | 结果 | 说明 |
|---|---|---|
| `test_k3_nested_delete_committed_insert_failed` | **PASS** | 预置 10 行 → 嵌套 delete（提交生效）+ insert 注入异常 → 写回 `error`、**行数=0**（旧数据丢失且不可回滚）——**K3 确认** |
| `test_k3_nested_normal_path_ok` | PASS | 嵌套模式正常路径 delete+insert 均各自提交，行数正确（旧 5 行→新 3 行） |
| `test_atomic_control_insert_failed_keeps_old` | PASS | **对照（A-05 验收基准）**：DELETE+INSERT 同一原子事务失败 → 整体回滚、旧 10 行保留 |

验证命令：`python -m pytest tests/unit/test_k3_loss_window.py` → `3 passed`。

## 四、结论与施工指向

- **A-03 验收达成**：复现成功 = K3 机制确认（非证伪）。
- **A-05 验收基准已固化**：`test_atomic_control_insert_failed_keeps_old` 断言
  "失败时数据不丢失" —— A-05（SAVEPOINT 嵌套事务或 DataQueries 不自行开事务）
  完成后该语义需在真实调用链上成立。
- 影响面：全量清洗的**整标的写回**路径（write_back_symbol）与任何
  `delete_market_data` + `bulk_insert` 组合调用点；A-13 的 duplicate_cleaner 使用
  **事务内单条 DELETE + rowid 精确删除**（单事务原子）不受此窗口影响。
