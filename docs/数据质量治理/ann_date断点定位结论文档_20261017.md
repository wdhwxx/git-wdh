## 2. 断点定位（源码证据链，已固化到文件行号）

### 2.1 供给侧断点 A：akshare 取数链路（三处记录构造均不产生 ann_date）

文件：`myquant/data_access/sources/akshare_source.py`

| 构造点 | 行号 | 现状 | 原始接口可提供性 |
|---|---|---|---|
| 东财数据中心估值 `_fetch_eastmoney_datacenter` | **867-879**（result dict） | 只取 `report_date`（TRADE_DATE），无 ann_date | 东财 datacenter 返回含公告日字段（可映射） |
| 新浪财务摘要 `_try_sina_finance` | **921-939**（result dict） | 只取 `report_date`（latest_period），无 ann_date | akshare `stock_financial_abstract` 可提供公告日期 |
| 东财历史财务 `_fetch_eastmoney_financial_history` | **1054-1069**（record dict） | 只取 `report_date`（REPORT_DATE），无 ann_date | 接口含公告日期列，未选取 |

共同特征：**三处都只构造 `report_date` 而忽略公告日字段**——这是 K1"取数映射不取公告日字段"的精确断点，与 CSV 链路无关。

### 2.2 供给侧断点 B：CSV 链路（列清单缺 ann_date）

- `myquant/data_access/financial_sync_service.py` **57-61**：`FINANCIAL_CSV_COLUMNS` 共 17 列（symbol…data_source），**无 ann_date** → 写出与合并的 CSV 恒无公告日列。
- 该常量同时被 GUI 保存财务 CSV（`gui/data_download_dialog.py:_save_financial_csv`）与同步合并（`financial_sync_service.py:272/275`）共用，是 CSV 链路的唯一列权威。

### 2.3 入库映射（有能力但无输入）

文件：`myquant/data_access/financial_service.py`

- **286-289**（F-15）：`raw.get("ann_date")` 若 CSV 提供则解析，否则置 None——**入库侧已具备解析能力**；
- **110**：入库列清单含 `ann_date`；**305**：写入 `ann_date` 字段。
- 断点因果：供给侧两链路（akshare 三处构造 + CSV 列清单）均不产出 ann_date → `raw` 恒无该键 → 入库恒 NULL。**只修 CSV 链路（A-04）无法让存量与增量获得 ann_date**，必须同时修 akshare 取数映射（B-09）。

### 2.4 消费侧支持（完整，非缺失方）

| 位置 | 行号 | 作用 |
|---|---|---|
| `myquant/database/schema.py` | 108 | `ann_date TEXT -- 公告日 YYYY-MM-DD（实际披露日，防未来函数时点）` |
| `myquant/database/schema.py` | 132 | `idx_fin_ann_date` 索引 |
| `myquant/data_access/time_semantics.py` | 89-95 | `eff_disclosure_date`：ann_date 优先 → report_deadline 推定 → report_date 兜底 |
| `myquant/data_access/manager.py` | 1276 / 1309 | 财务派生量 SQL 读取 ann_date + M1A-01 时点日落点收敛 |

结论：**schema、索引、时点语义、消费侧全部就绪，缺的只是供给侧两个断点**。

## 3. 因果链与施工指向

```
akshare 三处记录构造无 ann_date（akshare_source.py 867-879 / 921-939 / 1054-1069）
  └─→ financial_service.py:286-289 解析不到（raw 恒无键）→ 305 写 NULL
CSV 列清单无 ann_date（financial_sync_service.py:57-61）
  └─→ CSV 恒无公告日列 → 入库恒 NULL
        └─→ financial_data.ann_date 覆盖率 = 0（329,735 行全 NULL）
              └─→ eff_disclosure_date 退化为 report_deadline 推定口径（PIT 保障缺失）
```

施工指向（严格按报告 §5.3 依赖链）：
1. **★B-09**：akshare_source.py 三处记录构造补公告日期字段（字段名第 0 步实测），封堵取数映射断点——先做；
2. **A-04**：`FINANCIAL_CSV_COLUMNS` 补 `ann_date` + 存量 CSV 回填脚本 + 覆盖率指标——第二供给链，后做；
3. 两者完成后 V-00 验收：新导入行 ann_date 非空率 > 90%。
