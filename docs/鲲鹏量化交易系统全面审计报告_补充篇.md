## 补 6 · 第三轮收口补审（回应评价中 3 个缺口）

### 6.1 backtest/recorder.py 文件句柄（原补 1 漏扫）
- 证据：`myquant/backtest/recorder.py` 全文无 `open(` / `with` / `to_csv` / `to_parquet` / `save` / `flush` / `INSERT`。
- 结论：TradeRecorder **纯内存记录**（record_trade/record_equity 追加 list），不直接写盘；回测报告落盘在报告生成器（阶段 3 已验）。**recorder.py 无文件句柄问题** ✅。

### 6.2 event_bus 慢 handler I/O 审计（原补 2 结论偏乐观修正）
- 证据：订阅方分布——`risk_manager.py:833/840/847`（3）、`metrics_collector.py:1392-1412`（4）、`alerting.py:1355-1380`（5）均经 `lambda e: self.handle_xxx_event(e)` 同步执行。
- **修正表述**：同步串行本身就是阻塞，"发布预算"只是让单 handler 超时后跳过剩余 handler、把阻塞**限界**，而非消除。alerting handler 内含规则判断+聚合+通道发送（若 EmailAlertChannel 同步 SMTP，则占总线）。
- 结论：慢 handler 风险**有界**（预算兜底），但严格说未达"非 I/O 快操作"标准 → 降级表述：**P3 观察**（实盘量小不阻塞；若告警通道接 SMTP 应改异步/队列发送）。

### 6.3 风控 config 格式错误路径（原补 4 未验路径，有新发现）
- 证据：`myquant/risk/rules.py:604-619` `from_config` 逐条加载——未知规则名 warning 跳过；**单条规则构造失败 → `except Exception` 捕获、`logger.error` 记录、继续下一条，该规则不加入库，且不补默认值**。
- **新发现（P2 观察）**：`config=None` 路径安全（回落 create_default_library 全量默认）；但 `config` 存在且**某条规则参数写错**（如 daily_loss_limit_pct 写成字符串）→ 该条**静默失效**（仅 error 日志），**不回落到 1% 默认**。与 BUG-09 不同：这是"配置错误时单条风控静默缺失"，非空规则放行，但也非保守兜底。
- 结论：风控降级需补一句——from_config 单条错误应补默认规则（或启动时硬失败），当前为静默跳过。
